The anteros Framework backend is configured using the `define.Server()` function. This page covers all configuration options.

## Basic Configuration

```typescript
import { define, app } from '@anteros/core';

const config = define.Server({
  server: {
    name: 'My API',
    port: 4000,
  },
  tenants: [
    {
      id: 'v1',
      dir: 'v1',
      database: {
        uri: 'mongodb://localhost:27017/mydb'
      }
    }
  ]
});

await app.boot(config);
```

## Server Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `server.name` | `string` | `'SERVER'` | Server name displayed in console |
| `server.port` | `number` | `4000` | Port number |
| `server.cors` | `object` | - | CORS configuration |
| `server.jwt` | `object` | - | JWT configuration |
| `server.ipRestriction` | `object` | - | IP restriction rules |
| `server.body.maxSize` | `number` | `104857600` (100MB) | Maximum request body size in bytes |
| `server.reusePort` | `boolean` | `false` | Bun's `SO_REUSEPORT` — allow multiple processes to bind the same port |
| `server.trustProxy` | `boolean` | `false` | Trust proxy headers (`CF-Connecting-IP` / `X-Forwarded-For`) as the client IP |

```

  "connections": 0,

    "total": 1523,

  "cpu": { "percent": 12.5, "cores": 8, "user": 120000, "system": 80000 }

```

| Field | Meaning |
|-------|---------|
| `uptime` | Seconds since process start |
| `requests.total` | Total requests served |
| `requests.active` | Requests currently in flight (= `pendingRequests`) |
| `requests.errors` | Responses with status ≥ 500 |
| `requests.byMethod` / `byStatus` | Request counters split by HTTP method / status |
| `pendingRequests` | Requests currently in flight |
| `pendingWebSockets` | Active WebSocket connections |

| `cpu.percent` | % of a single core over the last sample window |

> `pendingRequests` high → possible DB saturation / slow queries.
> `pendingWebSockets` climbing → possible socket leak.

## IP Restriction

Block or allow requests based on client IP address. Uses [Hono IP Restriction Middleware](https://hono.dev/docs/middleware/builtin/ip-restriction) under the hood.

```typescript
const config = define.Server({
  server: {
    port: 4000,
    ipRestriction: {
      denyList: ['10.0.0.0/8', '192.168.0.50'],
      allowList: ['127.0.0.1', '::1', '203.0.113.0/24'],
    },
  },
  tenants: [...],
});
```

| Option | Type | Description |
|--------|------|-------------|
| `denyList` | `IPRestrictionRule[]` | IPs or ranges to block |
| `allowList` | `IPRestrictionRule[]` | IPs or ranges to allow |

<Callout type="warn">
`denyList` takes precedence over `allowList`. If an IP matches both lists, it is blocked.
</Callout>

### Rule Syntax

Rules accept static IPs, CIDR notation, or a wildcard:

| Format | IPv4 example | IPv6 example |
|--------|-------------|-------------|
| Static IP | `192.168.2.0` | `::1` |
| CIDR | `192.168.2.0/24` | `::1/10` |
| Wildcard | `*` | `*` |

### Block a Subnet

```typescript
ipRestriction: {
  denyList: ['10.0.0.0/8'],
}
```

### Allow Only Private Network

```typescript
ipRestriction: {
  denyList: ['*'],
  allowList: ['192.168.1.0/24', '127.0.0.1', '::1'],
}
```

### Allow Only Specific IPs

```typescript
ipRestriction: {
  denyList: ['*'],
  allowList: ['203.0.113.10', '203.0.113.20'],
}
```

### Client IP Resolution & Trust Proxy

The client IP used for `ipRestriction`, rate limiting, audit logs and `/health` is resolved **once per request** from the real socket address (`server.requestIP()`). By default, proxy headers are **ignored** — a client cannot spoof its IP by sending `X-Forwarded-For`.

If your server sits behind a reverse proxy / CDN (nginx, Cloudflare, …), enable `trustProxy` to use the proxy headers instead:

```typescript
const config = define.Server({
  server: {
    port: 4000,
    trustProxy: true,   // trust CF-Connecting-IP / X-Forwarded-For
  },
  tenants: [...],
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `server.trustProxy` | `boolean` | `false` | When `true`, uses `CF-Connecting-IP` then `X-Forwarded-For` as the client IP, falling back to the socket address |

<Callout type="warn">
Keep `trustProxy` **disabled** unless your server is really behind a trusted proxy — otherwise clients can spoof their IP and bypass IP restriction / rate limiting.
</Callout>

## Rate Limiting

Protect your API against brute-force attacks and excessive usage with configurable rate limiting. Uses the built-in middleware from `@anteros/core`.

```typescript
const config = define.Server({
  server: {
    port: 4000,
    rateLimit: {
      enabled: true,
      windowMs: 60_000,      // 1 minute window
      max: 100,               // 100 requests per window
      redis: {                // optional — Redis is detected automatically when present
        host: 'cache.internal',   // env fallbacks: REDIS_URL / REDIS_HOST / REDIS_PORT / REDIS_PASSWORD
        port: 6379,
      },
      login: {
        windowMs: 60_000,
        max: 10,              // 10 login attempts per minute
      },
    },
  },
  tenants: [...]
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `rateLimit.enabled` | `boolean` | `true` | Enable or disable rate limiting globally |
| `rateLimit.windowMs` | `number` | `60000` (1 min) | Time window in milliseconds |
| `rateLimit.max` | `number` | `100` | Maximum requests per window across all routes |
| `rateLimit.useRedis` | `boolean` | auto | Override: `false` = force in-memory, `true` = force Redis. Unset = **auto** (Redis if `redis` block or `REDIS_*` env vars present) |
| `rateLimit.redis.url` | `string` | - | `redis://` connection string (takes precedence over host/port) |
| `rateLimit.redis.host` | `string` | `localhost` | Redis host |
| `rateLimit.redis.port` | `number` | `6379` | Redis port |
| `rateLimit.redis.password` | `string` | - | Redis password |
| `rateLimit.login.windowMs` | `number` | `60000` (1 min) | Time window for login endpoints |
| `rateLimit.login.max` | `number` | `10` | Maximum login attempts per window |

<Callout type="info">
Rate limiting uses an **in-memory store** by default. As soon as Redis connection info is provided (`rateLimit.redis` or `REDIS_URL` / `REDIS_HOST` env vars), the limiter **automatically switches to Redis** to share counters across processes — no `useRedis` flag needed. If Redis becomes unavailable, it falls back to the in-memory store until it recovers.
</Callout>

### Login Endpoint Protection

The login endpoint (`/api/:tenant_id/:collection/login`) has a **stricter limit** by default (10 requests/minute). This helps prevent credential brute-force attacks.

### Disable Rate Limiting

```typescript
rateLimit: {
  enabled: false,
}
```

When disabled, no rate limit headers are applied and all requests pass through unrestricted.

## Logging

Anteros ships a built-in logging system (MongoDB-`mongodb.log`-style): every request, boot event and error is written to a **log file** with levels, timestamps, and rotation.

By default the file is **`.logs/anteros.log`** (created automatically at boot, relative to the working directory — a hidden folder like `.cache/`). The file is **JSONL** — one JSON object per line, with a Caddy-style envelope (`ts` epoch-seconds, `date` ISO 8601, `level`, `msg`), ready for `jq`/grep/parsing:

```json
{"ts":1786752192.458,"date":"2026-08-15T20:51:43.685Z","level":"info","msg":"Starting Anteros server","port":4000,"tenants":["v1"]}
{"ts":1786752193.658,"level":"info","msg":"POST /api/v1/users/find → 200","logger":"http.log.access","status":200,"duration":12.4,"method":"POST","uri":"/api/v1/users/find","remote_ip":"127.0.0.1","bytes_read":42,"size":1024,"user_id":"","ip":"127.0.0.1","traceId":"c4645d8e-...","tenant":"v1","request":{"headers":{"accept":["*/*"],"user-agent":["Mozilla/5.0..."]},"client_ip":"127.0.0.1","host":"api.example.com","method":"POST","remote_ip":"127.0.0.1","remote_port":51324,"uri":"/api/v1/users/find"},"resp_headers":{"content-type":["application/json"]}}
{"ts":1786752195.5,"level":"warn","msg":"Slow find (350ms)","collection":"orders","tenant":"v1","duration":350}
{"ts":1786752197.0,"level":"error","msg":"Uncaught exception","message":"...","stack":"..."}
```

The console output stays human-readable (`[HH:mm:ss] LEVEL message {meta}`, colorized); only the file is JSONL.

> ⚠️ **Console = your logs only.** Everything the framework logs *per request* — the **access log**, **MCP operations** and **slow queries** — is written to the **file only** (`logger.file(...)`), so a busy API doesn't flood the terminal. The console shows the boot banner, fatal errors (`uncaughtException` / `unhandledRejection`), and the `logger.*` calls **you** make from your code. Set `logging.console: false` to silence even those.

### Access log format

Every request is logged with a **Caddy-compatible JSONL** payload — flat fields + nested `request` / `resp_headers` blocks (a `ts`/`date`/`level`/`msg` envelope is injected automatically):

```json
{"ts":1786752193.658,"date":"2026-08-15T20:51:43.685Z","level":"info","msg":"POST /api/v1/users/find → 200","logger":"http.log.access","status":200,"duration":12.4,"method":"POST","uri":"/api/v1/users/find","remote_ip":"127.0.0.1","bytes_read":42,"size":1024,"user_id":"","ip":"127.0.0.1","traceId":"c4645d8e-...","tenant":"v1","request":{"headers":{"accept":["*/*"],"user-agent":["Mozilla/5.0..."]},"client_ip":"127.0.0.1","host":"api.example.com","method":"POST","remote_ip":"127.0.0.1","remote_port":51324,"uri":"/api/v1/users/find"},"resp_headers":{"content-type":["application/json"]}}
```

| Field | Type | Description |
|-------|------|-------------|
| `ts` | `number` | Epoch seconds (float) — auto-injected |
| `date` | `string` | ISO 8601 timestamp (`YYYY-MM-DDTHH:mm:ss.sssZ`) — auto-injected |
| `level` | `string` | Log level — auto-injected |
| `msg` | `string` | Log message — auto-injected |
| `logger` | `string` | Log source (`http.log.access`) |
| `status` | `number` | HTTP response status |
| `duration` | `number` | Processing time in ms (float) |
| `method` / `uri` | `string` | HTTP method / path + query |
| `remote_ip` | `string \| null` | Real socket address of the peer |
| `bytes_read` / `size` | `number` | Request body / response body size (from `Content-Length`) |
| `user_id` | `string` | `sub` claim of the verified JWT (empty when anonymous) |
| `ip` | `string` | Client IP (socket, or trusted proxy header when `trustProxy`) |
| `traceId` | `string` | Correlation id — links the HTTP request to logs/audit |
| `tenant` | `string \| null` | Tenant id from the URL (`/api/:tenant_id/...`) |
| `request` | `object` | `{ headers, client_ip, host, method, remote_ip, remote_port, uri }` |
| `resp_headers` | `object` | Response headers (`[values]`) — `set-cookie` stripped |

> ⚠️ TLS details (`tls.cipher_suite`, `tls.version`…) and the HTTP protocol version (`proto`) are **not exposed** by Bun's HTTP layer — they are omitted from the payload.

What gets logged:

- **Access log** — every request: `METHOD path → status`, duration, client IP, trace id, tenant, headers, bytes
- **MCP operations** — `tools/list`, `tools/call` (tool, args, isError), `resources/read` (uri, params)
- **Slow queries** — database operations slower than `slowQueryMs` (default 200ms) via the `@LogSlowQuery` decorator
- **Boot events** — start / ready / failure, cluster worker lifecycle
- **Errors** — `uncaughtException` / `unhandledRejection` / failed boots

Query the file with `jq`:

```bash
jq -c 'select(.level == "warn" and (.msg | startswith("Slow")))' .logs/anteros.log
jq -c 'select(.tenant == "v1") | {ts, level, msg}' .logs/anteros.log
```

### Configuration

```typescript
const config = define.Server({
  server: {
    port: 4000,
    logging: {
      level: 'info',              // 'debug' | 'info' | 'warn' | 'error' (default: 'info')
      console: true,              // also log to the console (default: true)
      file: true,                 // true → .logs/anteros.log, or a custom path string (default: true)
      dir: '.logs',               // directory when `file` is true (default: '.logs')
      maxSize: 10 * 1024 * 1024,  // rotate when the file exceeds this size (default: 10MB)
      maxFiles: 5,                // keep this many rotated files (default: 5)
      slowQueryMs: 200,           // log DB operations slower than this (default: 200)
    },
  },
  tenants: [...],
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `logging.level` | `string` | `'info'` | Minimum level emitted (`debug` < `info` < `warn` < `error`) |
| `logging.console` | `boolean` | `true` | Also write to the console (colorized) |
| `logging.file` | `boolean \| string` | `true` | `true` → `<dir>/anteros.log`, `string` → custom path, `false` → disabled |
| `logging.dir` | `string` | `'.logs'` | Directory used when `file` is `true` |
| `logging.maxSize` | `number` | `10485760` (10MB) | Rotate when the file exceeds this size in bytes |
| `logging.maxFiles` | `number` | `5` | Number of rotated files kept (dated names: `anteros-2026-07-08-1.log`, `-2`, …) |
| `logging.slowQueryMs` | `number` | `200` | Log database operations slower than this many ms |

<Callout type="info">
Disable file logging entirely with `logging.file: false` (console only). On `SIGINT`/`SIGTERM` the logger flushes pending writes before the process exits. Rotated files use **dated names** (`anteros-2026-07-08-1.log`, `-2`, … — the index resets each day) and the `maxFiles` most recent are kept.
</Callout>

### Logging from your code

The `logger` is exported from `@anteros/core` — usable anywhere (actions, services, routes, scripts, custom middlewares):

```typescript
import { logger } from '@anteros/core';

logger.info('Order processed', { orderId, total });
logger.warn('Low stock', { sku, remaining });
logger.error('Payment failed', { code: 'PAYMENT_ERROR' });
logger.debug('detail', { raw }); // only emitted when level ≤ 'debug'

// File only (never on console) — the framework uses this internally for the
// access log, MCP operations and slow queries.
logger.file('Server started', { pid: process.pid });
logger.file('warn', 'Long job finished', { took: 3000 }); // keep the level
```

## DB Query Cache

Cache-aside caching for `find` queries: with `{ useCache: true }` the result is served from the cache (keyed by a hash of the query params), populated on miss, and **invalidated automatically on any write** (insert/update/delete/findOneAndUpdate/bulk…) — plus cross-collection invalidation when a query uses `$include` (modifying `clients` invalidates `orders` queries that embed client data). `findOne` is never cached (point queries).

> ⚠️ **Opt-in**: the DB query cache is **disabled by default** — you must set `cache.enabled: true` in `server.cache` for `useCache` to have any effect. The default driver is **`memory`** (fastest, but lost on restart) — use `driver: 'filesystem'` for persistence or `'redis'` for multi-process sharing.

> ℹ️ **Large results**: every cached entry is tagged with its result `_id`s (up to `cache.maxTags`, default 50000) — a 7000-doc result is fully covered. Each tag costs ~0.18µs per cache hit, negligible vs the cost of the real query.

```typescript
const config = define.Server({
  server: {
    port: 4000,
    cache: {
      enabled: true,         // REQUIRED — the DB query cache is OFF by default (opt-in)
      driver: 'memory',       // 'memory' (default) | 'filesystem' | 'redis'
      directory: '.cache',      // filesystem driver directory (default: ./.cache)
      pruneInterval: '1h',      // filesystem prune interval
      ttl: '5m',                // default TTL for cached queries
      // redis: { host: 'localhost', port: 6379, password: '' }, // driver: 'redis'
    },
  },
  tenants: [...],
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `cache.enabled` | `boolean` | `false` | **Opt-in** — the DB query cache is disabled unless set to `true` |
| `cache.driver` | `string` | `'memory'` | Driver: `memory` (default, L1 only), `filesystem` (`.cache/` folder, L1 memory + L2 disk), `redis` |
| `cache.directory` | `string` | `'./.cache'` | Filesystem driver directory (project root) |
| `cache.redis` | `object` | - | Redis connection (`host`, `port`, `password`) when `driver: 'redis'` |
| `cache.pruneInterval` | `string` | `'1h'` | Filesystem prune interval |
| `cache.ttl` | `string \| number` | `'5m'` | Default TTL for cached queries |
| `cache.maxTags` | `number` | `50000` | Max `_id` tags per cached entry — large results are tagged up to this count (~0.18µs per tag check on each hit) |

### Per-collection TTL

Set a default TTL on the collection definition (`cache: { ttl }`) — it wins over the server default:

```typescript
export default define.Collection({
  slug: 'orders',
  fields: [...],
  cache: { ttl: '30s' },
});
```

### Usage

```typescript
// internal API / actions / services
const docs = await rest.find('orders', { $match: { status: 'paid' } }, {
  useCache: true,
});

// REST API — pass `options` alongside `params`
POST /api/v1/orders/find
{ "params": { "$match": { "status": "paid" } }, "options": { "useCache": true } }
```

TTL precedence: `collection.cache.ttl` > `server.cache.ttl` > `'5m'`. (The internal `rest.find` API still accepts an `options.ttl` override for server-side code — actions, services, scripts — but HTTP/SDK clients only control `useCache`; TTL is a backend concern.) Relations (`$include`) are tracked so a write on the included collection invalidates the parent's cached queries too.

### Invalidation

Every cached query is **indexed by the `_id`s of its results** (including the `_id`s of `$include`d documents). Invalidation is then **targeted**:

| Write | Invalidation |
|-------|-------------|
| `updateOne` / `updateMany` / `deleteOne` / `deleteMany` (known ids) | 🔥 **Targeted** — only the cached queries whose result contains one of those `_id`s are removed. A change on a document that is **not** part of a cached result (e.g. a January doc while the cached query returned February docs) **keeps that cache** |
| `insertOne` / `insertMany` / `bulkWrite` / `bulkUpdate` / `findOneAndUpdate` / `dropCollection` | 🧨 **Full** — the whole collection namespace is cleared (a new document could match any cached query) |
| Write on an `$include`d collection (`clients`) | 🔥 Targeted on the parent (`orders`) — only the queries embedding the modified client `_id` are removed |

> ⚠️ Writes done **directly through the MongoDB driver** (`rest.db.collection(...)`) bypass the framework and do **not** invalidate — the cache stays until its TTL.

## Tenants Configuration

See **[Tenant](/docs/reference/tenants)** for a focused reference on `dir`, URLs, and layout.

Each tenant represents an isolated database and a **code root** on disk. The field **`dir`** is **required**: it is the path (relative to the process working directory, usually the project root) where anteros looks for **`{dir}/collections`**, **`{dir}/routes`**, and **`{dir}/scripts`**.

```typescript
const config = define.Server({
  server: { port: 4000 },
  tenants: [
    {
      id: 'v1',
      dir: 'v1',
      name: 'v1',
      database: {
        uri: 'mongodb://localhost:27017/v1_db',
        options: { maxPoolSize: 10 }
      }
    },
    {
      id: 'tenant2',
      dir: 'tenants/tenant2',
      name: 'Second Tenant',
      database: {
        uri: 'mongodb://localhost:27017/tenant2_db',
      }
    }
  ]
});
```

| Option | Type | Required | Description |
|--------|------|----------|-------------|
| `id` | `string` | Yes | Unique tenant identifier (used in `/api/:tenant_id/...`) |
| `dir` | `string` | **Yes** | Relative path to the tenant folder (`collections`, `routes`, `scripts`) |
| `name` | `string` | No | Tenant display name |
| `routes.prefix` | `string` | No | URL prefix for custom routes; required to load `routes/**/*.route.ts` |
| `database.uri` | `string` | Yes | MongoDB connection URI |
| `database.options` | `object` | No | MongoDB client options |

<Callout type="info">
MongoDB connection is automatically injected by `syncTenants` at startup. See [Tenant](/docs/reference/tenants) for details.
</Callout>


## Reuse Port (cluster / multiple processes)

Set `server.reusePort: true` to enable Bun's `SO_REUSEPORT`. The framework then acts as a **master** that spawns workers and aggregates their metrics:

```typescript
const config = define.Server({
  server: {
    port: 4000,
    reusePort: true,   // cluster mode
    workers: 4,        // optional — default: CPU count
    metricsPort: 4001, // optional — default: port + 1
  },
  tenants: [...]
});
```

### Behavior

| Role | What it does |
|------|-------------|
| **Master** | Spawns N workers, aggregates metrics via **IPC**, restarts crashed workers, serves aggregated `/health` on `metricsPort` |
| **Worker** | Serves the main port (`reusePort`), reports metrics to the master every 5s, exposes its own `/health` |

```bash
curl http://localhost:4001/health   # aggregated view of ALL workers
```

> ⚠️ Each worker is a separate process with its own memory — use **Redis** for shared cache / Socket.io state in cluster mode.

## Port Conflict & Graceful Shutdown

### Zombie detection (dev only)

When the server is **not** in cluster mode and `NODE_ENV` is not `production`, the boot checks whether the port is already listening before binding it. The check uses a **real TCP connection probe** ([`tcp-port-used`](https://www.npmjs.com/package/tcp-port-used)) — only an actual listening server counts, so a connected client (browser, front-end dev server) never triggers a false positive.

A **grace period of ~2.5s** is applied before declaring a zombie: after a restart, the previous process may still be releasing the port (Mongo / Socket.IO shutdown). If the port stays occupied after the grace period, the boot fails with:

```
⚠ Port 4000 is already in use. Possible zombie server.
  → Kill it: lsof -ti :4000 | xargs kill -9
```

### Graceful shutdown (SIGINT / SIGTERM)

On `SIGINT` (Ctrl+C) or `SIGTERM`, the server shuts down cleanly: `server.stop()` releases the port immediately, MongoDB clients are closed, and the process exits with code `0`. This guarantees that restarts — e.g. `bun --watch index.ts` — never leave an orphan process holding the port.

In cluster mode, the master stops its workers and the metrics server the same way.
