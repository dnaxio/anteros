`ros` is the operations-facing CLI. It handles everything related to deploying and operating pods on remote servers: initialization, deployment, status, setup, logs, rollback, and configuration validation.

## Quick reference

```bash
# Install
bun i @anteros/cli@latest -g

# Initialize a new project
ros init

# Validate configuration
ros config validate

# Deploy to a target environment
ros deploy --env production

# Check what's running
ros status

# Install server dependencies (docker, caddy, git, …)
ros setup --env production

# Tail logs from a pod
ros logs api

# Roll back to a previous version
ros rollback api
```

## Concepts

<Callout title="Environments, pods, and artifacts">
- An **environment** is a group of SSH targets (e.g. `test`, `staging`, `production`).
- A **pod** is a deployable unit (web, api, database, …) with a `driver`
  (`docker` or `flox`) and one or more `containers`.
- An **artifact** is the payload transferred to each remote server before
  deployment: a local folder (rsync), a single file (scp), or a git repository
  (cloned on the remote).
</Callout>
