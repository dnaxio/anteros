```bash
ros deploy [env] [--pod <name>] [--tag <tag>] [--strategy <s>]
           [--env <name>] [--server <target>] [--config <path>]
           [--dry-run] [--force]
           [--no-healthcheck] [--healthcheck-timeout <seconds>]
```

Deploys one or more pods to the target environment. Runs the build
pipeline (local + remote), transfers artifacts, and rolls the new containers
in place.

## Examples

```bash
# Deploy everything in `production`
ros deploy --env production

# Deploy a single pod, overriding the tag
ros deploy --env production --pod api --tag v1.0.3

# Dry run: show the plan without applying
ros deploy --env production --dry-run

# Deploy to a single canary server
ros deploy --env production --server canary-1

# Bypass safety prompts
ros deploy --env production --force
```

## What happens

For each pod selected, in order:

1. **Local build steps** — run on the machine where `ros` is invoked
2. **Per-server**, in parallel:
   1. **Remote build steps** — run on the server via SSH
   2. **Artifact transfer** — `rsync` (folder), `scp` (file), or `git clone`
   3. **Secret resolution** — `env_from` secrets are resolved client-side (never sent to disk on the remote)
   4. **`docker pull` + stop + rm + run** of the new container
   5. **Health check** — polls `healthcheck` URL until `2xx` or timeout; auto-rollbacks on failure

## Options

| Flag                    | Description                                                   |
|-------------------------|---------------------------------------------------------------|
| `--env <name>`          | Target environment (e.g. `test`, `staging`, `production`)     |
| `--server <target>`     | Restrict to a specific server (repeatable)                    |
| `--pod <name>`      | Deploy only one pod                                       |
| `--tag <tag>`           | Override the image tag for this deploy                        |
| `--strategy <s>`        | Override the deploy strategy                                  |
| `--dry-run`             | Show the plan; do not execute anything                        |
| `--force`               | Bypass safety checks (drift, confirmation, downgrade)         |
| `--config <path>`       | Path to `deploy.yaml` (default: `./deploy.yaml`)              |
| `--no-healthcheck`      | Skip post-deploy health check polling                         |
| `--healthcheck-timeout <s>` | Health check timeout in seconds (default: `60`)           |

## Health checks

After `docker run`, `ros` polls the container's `healthcheck` URL (configured
per container in `deploy.yaml`) every 3 seconds until it returns a `2xx`
status code or the timeout is reached.

If the health check **fails**:
1. `ros` looks up the previous version from the deployment history
2. It automatically **rolls back** by running the previous image tag
3. An error is reported with the rollback result

```bash
# Skip health check entirely
ros deploy --env production --no-healthcheck

# Increase timeout to 2 minutes
ros deploy --env production --healthcheck-timeout 120
```

<Callout>
Health checks require the `healthcheck` field to be set on the container
config. If no `healthcheck` is configured, the check is skipped for that
container.
</Callout>

## Secrets

Secrets defined in `env_from` are resolved **client-side** before deploy.
They are passed as `-e` flags to `docker run` and are never written to
disk on the remote server. Explicit `env:` vars take precedence over
resolved secrets.

See [Configuration → Secrets](/docs/cli/ros/configuration#secrets) for the
full syntax and supported backends.

## Deploy plan output

`ros deploy --dry-run` prints a table of the plan:

```
POD        CONTAINER  BUILD    IMAGE                         INST  RES         SERVER              ARTIFACT
dnx-doc    docs       local:1  (no image)                    1     500m/512Mi  root@192.168.30.11  ./docs -> /opt/anteros/docs/ [force, +1, -1]
dnx-api    api        —        ghcr.io/myorg/dnx-api:v1.0.2  3     2/2Gi       root@192.168.30.11  ./apps/api -> /opt/anteros/api/ [+1]
```

Columns:
- `POD` — outer key from the `pods:` map
- `CONTAINER` — `containers[0].name` (first container of the pod)
- `BUILD` — number of local / remote build steps
- `RES` — merged `resources` (pod + container override), `cpu/memory`
- `ARTIFACT` — source, destination, and any active filters
