`ros` reads its configuration from a `deploy.yaml` file. Organized in
four top-level blocks: `environments`, `pods`, `proxy`, and settings.

## Minimal example

```yaml title="deploy.yaml"
version: "1"
name: "my-app"

environments:
  production:
    servers:
      - root@192.168.30.11

pods:
  api:
    type: api
    driver: docker
    instances: 1
    containers:
      - name: api
        image: ghcr.io/myorg/api
        tag: v1.0.0
        ports: ["3001:3001"]
```

## `environments`

```yaml
environments:
  production:
    servers:
      - root@192.168.30.11
      - root@192.168.30.12
      - name: canary-1
        host: root@192.168.30.99
        tags: [canary]
```

Server format: `user@host[:port]`, or `${VAR}` / `${VAR:-default}`.

## `pods`

```yaml
pods:
  api:
    type: api
    driver: docker
    instances: 3
    resources:
      cpu: "1"
      memory: 1Gi
    build:
      local:
        steps:
          - name: Install deps
            run: bun install
          - run: bun run build
      remote:
        steps:
          - run: mkdir -p /opt/anteros/api
    artifact:
      source: ./apps/api
      destination: /opt/anteros/api/
      include: [".output"]
      exclude: ["node_modules"]
      force: true
    containers:
      - name: api
        image: ghcr.io/myorg/api
        tag: v1.0.0
        ports: ["3001:3001"]
        env:
          NODE_ENV: production
        env_from:
          - secret: api-secrets
        healthcheck: /healthz
        restart: unless-stopped
```

### Resources

Maps **1:1 to Docker flags**:

| YAML | Docker flags |
|------|-------------|
| `cpu: "1"` | `--cpus=1` |
| `cpu: "500m"` | `--cpus=0.5` |
| `memory: 512Mi` | `--memory=512M --memory-swap=-1` |

Pod-level defaults can be overridden per-container. Merged: container
overrides pod, partial overrides allowed.

### Artifacts

| Source | Transport |
|--------|-----------|
| `source:` (directory) | `rsync` |
| `source:` (file) | `scp` |
| `repo:` | `git clone` on remote |

For directory sources, `.gitignore` is read automatically. `include:`
overrides it, `exclude:` adds to it.

### Build steps

`local` steps run on the machine invoking `ros`. `remote` steps run on
each target server via SSH. PATH is auto-extended with common toolchain
locations (`~/.bun/bin`, `~/.local/bin`, etc.).

## `proxy`

Caddy reverse-proxy, managed via Admin API on `localhost:2019`.

```yaml
proxy:
  routes:
    - domain: api.example.com
      target: 127.0.0.1
      upstream_port: 3001
      tls: auto
```

Subcommands: `ros proxy apply`, `show`, `remove`.

## Metrics

Cron-based scraper installed by `ros metrics install`. Collects host
(CPU, memory, disk), per-container, and system info metrics.

```yaml
settings:
  metrics:
    schedule: "* * * * *"
    endpoint: https://metrics.example.com/v1/import
    # endpoint:
    #   url: https://metrics.example.com/v1/import
    #   headers:
    #     Authorization: "Bearer ${PUSH_TOKEN}"
    #   secret: ${METRICS_SECRET}

    labels:
      env: production
      cluster: dnx

    system:
      - os
      - cpu
      - mem
      - hostname
      - uptime
      - docker

    # include_host: true
    # include_disk: true
    # include_containers: true
    # include_system: true
```

| Field | Default | Description |
|-------|---------|-------------|
| `schedule` | `* * * * *` | Cron expression |
| `endpoint` | (required) | URL or `{url, headers, secret}` |
| `labels` | `{}` | Merged into system line |
| `system` | all | Sub-sections: `os`, `cpu`, `mem`, `hostname`, `uptime`, `docker` |
| `include_host` | `true` | Emit host CPU + memory |
| `include_disk` | `true` | Emit disk per mount |
| `include_containers` | `true` | Emit per-container CPU + memory |
| `include_system` | `true` | Emit system info line |

See [`ros metrics`](/docs/cli/ros/commands/metrics) for output schema.

## Alerts

Cron-based monitoring installed by `ros alerts install`. Watches Docker
containers AND host resources (CPU, memory, disk).

```yaml
settings:
  alerts:
    schedule: "*/5 * * * *"
    email: ops@example.com
    webhook:
      url: https://hooks.slack.com/...
      headers:
        Authorization: "Bearer ${ALERT_TOKEN}"
      secret: ${ALERT_SECRET}
    filters:
      # Container filters
      - name: "API unhealthy"
        type: health
        container: api
        duration: 1m
      - name: "API high CPU"
        type: cpu
        threshold: 85
        duration: 5m

      # Host filters
      - name: "Host high CPU"
        type: host_cpu
        threshold: 90
        duration: 5m
      - name: "Root disk full"
        type: host_disk
        mount: "/"
        threshold: 85
        duration: 10m
```

### Container filter types

| Type | Description |
|------|-------------|
| `health` | Container is `unhealthy` |
| `stopped` | Container is `exited` or `dead` for `duration` |
| `cpu` | CPU% > `threshold` for `duration` |
| `memory` | Memory% > `threshold` for `duration` |
| `oom` | Container was OOM-killed |

### Host filter types

| Type | Description |
|------|-------------|
| `host_cpu` | Host CPU% > `threshold` for `duration` |
| `host_mem` | Host memory% > `threshold` for `duration` |
| `host_disk` | Disk% > `threshold` for `duration`. `mount` optional (all if omitted). |

See [`ros alerts`](/docs/cli/ros/commands/alerts) for payload format.

## Audit webhook

```yaml
settings:
  audit:
    url: https://hooks.slack.com/services/...
    # events: [deploy.completed, deploy.failed, rollback.*]
    # secret: ${AUDIT_SECRET}
```

Payload: `{ event, pod, env, tag, deployer, timestamp, servers, duration_sec, result, error? }`.

## Global blocks

```yaml
ssh:
  port: 22
  timeout: 60
  key_path: ~/.ssh/id_rsa

deploy:
  tag: v1.0.0
  strategy: rolling
  max_unavailable: 1

settings:
  install_dir: /opt/anteros
  auto_tls: true
```
