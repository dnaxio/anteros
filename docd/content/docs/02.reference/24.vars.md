Each tenant has a **key/value variable store** — `rest.vars` — like Redis but backed by MongoDB (durable). Use it for configuration-like values (licences, feature flags, limits…) that must persist across restarts.

Entries are grouped by **namespace** then key, and may carry a **scope** (who the value belongs to), **meta** (validated attributes) and a **TTL**.

## Declaring defaults (`define.Vars`)

Defaults live in `{tenant.dir}/vars/**/*.var.ts`. They are **seeded once at boot** at the global scope — a key that already exists is never overwritten.

```typescript
// v1/vars/config.var.ts
import { define } from "@anteros/core";

export default define.Vars({
  namespace: "config",

  // ONE identity field, optional — its value is part of the entry key
  scope: {
    name: "company",
    type: "relationship",
    relation: { to: "companies" },
  },

  // attributes — validated, never part of the key
  meta: [
    { name: "note", type: "string" },
    { name: "expiresAt", type: "datetime-local" },
  ],

  // values: a raw default, or a spec (Field + `ttl`)
  vars: {
    maxUsers: 100,
    licence: { type: "string", defaultValue: "RDX00" },
    session: { type: "string", ttl: "1h" },
  },
});
```

| Option      | Type                  | Description                                                                                |
| ----------- | --------------------- | ------------------------------------------------------------------------------------------ |
| `namespace` | `string`              | Namespace grouping these variables (required)                                              |
| `scope`     | `Field`               | **One** optional identity field — its value is part of the entry key                       |
| `meta`      | `Field[]`             | Annotation fields — validated, never part of the key                                       |
| `vars`      | `Record<string, any>` | Values: a raw default, or a spec (any `Field` option + `defaultValue` + `ttl`)             |
| `api`       | `VarsApi`             | HTTP access rules — required to expose this namespace over `POST /vars/:tenant_id/:action` |

## Scope — one value per entity

A scoped namespace stores a distinct value per scope value (company, branch, environment…). The scope is declared with the same `Field` DSL — typically a `relationship`.

```typescript
const acme = rest.vars.scope(companyId); // bound store, like `rest`

await acme.set("config", "licence", "ACME-001");
await acme.get("config", "licence"); // 'ACME-001'
await acme.all("config"); // the whole config of this company

await rest.vars.get("config", "licence"); // global value — untouched
```

`scope` can also be passed **per call** — the same `{ scope }` option is accepted by every method:

```typescript
await rest.vars.set("config", "licence", "ACME-001", { scope: companyId });
await rest.vars.get("config", "licence", { scope: companyId });
await rest.vars.all("config", { scope: companyId });
await rest.vars.del("config", "licence", { scope: companyId });
```

## Meta — validated attributes

`meta` fields are declared at the namespace level and validated on write (Joi, same rules as collections). `relationship` meta values are stored as `ObjectId`.

```typescript
await acme.set("config", "licence", "ACME-002", {
  meta: { note: "Contrat 2026", expiresAt: new Date("2026-12-31") },
});

const entry = await acme.entry("config", "licence");
// { value: 'ACME-002', meta: { note: 'Contrat 2026', … }, scope, expiresAt, updatedAt }

await acme.entries("flags", { where: { note: "grp" } }); // filter on meta
```

An unknown `meta` key is rejected — and a namespace with declared `meta` fields requires them to match. A namespace **without** a `define.Vars` stays free-form.

## TTL

Entries can expire. The TTL is enforced two ways: a MongoDB **TTL index** (`expiresAt`) deletes them in the background, and reads **filter out expired entries** (TTL deletion is lazy — up to ~60 s).

```typescript
await rest.vars.set("session", "abc", "token", { ttl: "30m" }); // per call
await rest.vars.set("config", "session", "x"); // '1h' — the var's default TTL
await rest.vars.expire("session", "abc", "15m"); // set / renew
```

| TTL source                              | Priority                |
| --------------------------------------- | ----------------------- |
| `set(..., { ttl })`                     | highest                 |
| the variable's `ttl` (in `define.Vars`) | fallback                |
| none                                    | the entry never expires |

`set` is **authoritative**: calling it without `ttl` clears an existing expiry (like Redis `SET`). `incr` does **not** clear it. TTL accepts a human string (`'30s'`, `'30m'`, `'2h'`, `'1d'`) or milliseconds.

## API (`rest.vars`)

Tenant-scoped (like every `rest.*` accessor).

| Method                                          | Description                                            |
| ----------------------------------------------- | ------------------------------------------------------ |
| `set(ns, key, value, { meta?, ttl?, scope? })`  | Set a value (replaces value, meta and TTL)             |
| `setMany(ns, entries, { meta?, ttl?, scope? })` | Set several keys at once                               |
| `get(ns, key, { scope? })`                      | Read a value — `undefined` when missing or expired     |
| `entry(ns, key, { scope? })`                    | Full entry (value + meta + expiry)                     |
| `entries(ns, { scope?, where? })`               | All entries (filter on meta)                           |
| `all(ns, { scope?, where? })`                   | All key/value pairs                                    |
| `del(ns, key, { scope? })`                      | Delete a key — `true` when removed                     |
| `has(ns, key, { scope? })`                      | Key existence check                                    |
| `incr(ns, key, by?, { scope?, ttl? })`          | Atomic increment (default `1`) — keeps the TTL         |
| `expire(ns, key, ttl, { scope? })`              | Set / renew the TTL                                    |
| `clear(ns, { scope? })`                         | Delete every key of the namespace in the current scope |
| `scope(value)`                                  | Bound store with the scope pre-filled                  |

## Storage

Variables live in the **`_vars_`** collection of the tenant's main database — one document per `(scope, namespace, key)`:

```json
{
  "_id": "65f1…:config:licence",
  "scope": "65f1…",
  "ns": "config",
  "key": "licence",
  "value": "ACME-001",
  "meta": { "note": "Contrat 2026" },
  "expiresAt": "2026-12-31T00:00:00.000Z",
  "createdAt": "2026-09-19T10:00:00.000Z",
  "updatedAt": "2026-09-19T10:00:00.000Z"
}
```

Indexes — **always created** (per tenant, in the background, even without a `define.Vars`): `{ scope: 1, ns: 1 }` for the scoped lookups and `{ expiresAt: 1 }` (TTL). `{ 'meta.<field>': 1 }` is added when a meta field is marked `index: true`.

## Variables vs Cache

|                     | `rest.vars`                                  | `rest.cache`                |
| ------------------- | -------------------------------------------- | --------------------------- |
| Backend             | MongoDB (`_vars_`)                           | memory / filesystem / Redis |
| Persistence         | **durable** (optional TTL)                   | ephemeral (TTL by design)   |
| Declarable in files | yes (`define.Vars`)                          | no                          |
| Use case            | **configuration, flags, licences, counters** | hot query results, sessions |

Rule of thumb: **configuration → `vars`, performance → `cache`.**

## HTTP API

A namespace can be exposed over `POST /vars/:tenant_id/:action` — gated by `api.access`, **denied by default** (same pattern as collections).

```typescript
export default define.Vars({
  namespace: "config",
  vars: { licence: "RDX00" },
  api: {
    access: {
      "*": false, // deny by default
      get: true, // public read
      set: ({ token }) => token?.decoded?.role === "admin",
    },
  },
});
```

```http
POST /vars/v1/get
Content-Type: application/json

{ "ns": "config", "key": "licence" }   →   { "value": "RDX00" }
```

Actions: `set`, `setMany`, `get`, `entry`, `entries`, `all`, `del`, `has`, `incr`, `expire`, `clear`. Only namespaces declared with `define.Vars` are reachable (`NAMESPACE_NOT_FOUND` otherwise). See [REST API → Vars API](/docs/manage-data/rest-api#vars-api) and the [SDK](/docs/manage-data/sdk) (`api.vars`).

## Replication

`_vars_` is replicated **by default**, like the other framework collections. A namespace opts **out** of its own file:

```typescript
// v1/vars/config.var.ts
export default define.Vars({
  namespace: "config",
  vars: { licence: "RDX00" },
  // Optional: this namespace is replicated unless it opts out
  replication: { enabled: true },
});
```

```typescript
// v1/vars/private.var.ts
export default define.Vars({
  namespace: "private",
  vars: { apiSecret: "…" },
  replication: { enabled: false }, // never leaves the source
});
```

The engine copies `_vars_` with a **per-document filter**: every namespace goes to the destination except the ones declaring `replication: { enabled: false }`. To stop `_vars_` entirely, exclude it at the tenant level:

```typescript
replication: {
  destinations: [{ id: "backup", uri: "…" }],
  exclude: ["vars"], // covers every namespace, opted-in or not
}
```

::prose-callout{variant="warning"}

A namespace with **no** `replication` entry **is replicated**. If a namespace holds secrets, licences or tokens, either declare `replication: { enabled: false }` on it or put `'vars'` in the tenant's `exclude` list — the tenant-level `exclude` wins over everything.

::

Insert / update flow through the incremental date cursor (`updatedAt`), and `del` / `clear` propagate through tombstones — a variable deleted on the source disappears on the destination too.

::prose-callout{variant="info"}

Not replicated: the **TTL index** (entries keep their `expiresAt`, but the destination has no TTL index unless you create one) and the `_vars_` scope index.

::
