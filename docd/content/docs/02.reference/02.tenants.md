A **tenant** is an isolated slice of your app: its own MongoDB connection and its own on-disk folder for collections, routes, services, scripts, and its lifecycle.

## Required fields

| Field          | Description                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`           | Unique identifier used in URLs: `POST /api/:tenant_id/collections/:collection/:action`.                                                                                                                                                                                                                                                                                                                                                  |
| `dir`          | Path **relative to the project root** (working directory when the server starts). anteros resolves `collections/`, `routes/`, `scripts/`, and `lifecycle.ts` under this path. **Omitting `dir` is not supported.**                                                                                                                                                                                                                       |
| `database.uri` | MongoDB connection string for this tenant. **This is where High Availability lives**: for a replica set, list the members and the set name (`mongodb://host1,host2,host3/app?replicaSet=rs0`) so the driver handles failover and elections. The replication engine does **not** provide failover — see [Replication → Not a replacement for MongoDB replication](/docs/reference/replication#not-a-replacement-for-mongodb-replication). |

## Optional fields

| Field              | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`             | Human-readable label (logging, UI).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `description`      | Free-text description.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `routes.prefix`    | Base path for custom routes (`**/*.route.ts`). Without a prefix, the `routes/` folder is not loaded.                                                                                                                                                                                                                                                                                                                                                                                                                |
| `database.options` | Extra options passed to the MongoDB client.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `audit`            | Audit trail of this tenant's database — `audit.retention: "90d"` to expire `_audit_` entries, `false` to opt out; `audit.file` to also append them to a local JSONL file (`true`, `"<dir>"` or `{ dir, maxSize, retention }`, `false` to opt out). Both fall back to `server.audit.*` (**the tenant wins**); if neither is set, entries are kept forever and no file is written. See [Audit → Retention](/docs/reference/audit#retention) and [Audit → Local file backup](/docs/reference/audit#local-file-backup). |
| `replication`      | One-way replication of this tenant's data to one or more destinations. See [Replication](/docs/reference/replication).                                                                                                                                                                                                                                                                                                                                                                                              |

## Example

```typescript
import { define, app } from "@anteros/core";

await app.boot(
  define.Server({
    server: { port: 4000 },
    tenants: [
      {
        id: "v1",
        dir: "v1",
        routes: { prefix: "/api/v1" },
        database: {
          uri: "mongodb://localhost:27017/myapp",
          options: { maxPoolSize: 10 },
        },
      },
    ],
  }),
);
```

## Layout under `dir`

Relative to `tenant.dir` (e.g. `v1/`):

| Path                        | Role                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------- |
| `collections/**/*.model.ts` | Collection models                                                                     |
| `routes/**/*.route.ts`      | Custom HTTP routes (needs `routes.prefix`)                                            |
| `scripts/**/*.run.ts`       | Scripts run shortly after boot                                                        |
| `services/**/*.service.ts`  | Tenant-scoped services exposed under `/api/:tenant_id/services/...`                   |
| `lifecycle.ts`              | Tenant lifecycle hooks (`beforeBoot`, `afterBoot`, `onDestroy`) — one file per tenant |
| `vars/**/*.var.ts`          | Tenant variables (`define.Vars`), seeded into `_vars_` at boot                        |

Several tenants can share the same `dir` or use different folders (e.g. `v1`, `tenants/client-a`).

For a full repo layout (cache, `config/`, `uploads/`, optional `services/`, `tasks/`, etc.), see **[Project structure](/docs/getting-started/project-structure)**.
