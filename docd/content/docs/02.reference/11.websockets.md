WebSocket handlers let you build real-time features like chat, notifications, and live collaboration. They run on the same Socket.IO server as the framework and have access to the database via `rest`.

## How It Works

anteros discovers all files matching `**/*.ws.ts` inside the `sockets/` directory of each tenant. Each file exports a handler created with `define.WebSocket()`. Handlers are loaded at boot time — after services.

`exec` is called **once per connected client** and receives the `socket` instance, a shared `io` instance, and a tenant-scoped `rest` instance.

## Directory Structure

Place your socket files inside `{tenant.dir}/sockets/`:

```
v1/
├── collections/
├── services/
└── sockets/
    ├── chat.ws.ts
    ├── push.ws.ts
    └── realtime/
        └── notifications.ws.ts
```

::prose-callout{variant="info"}

Files are discovered recursively — you can organize sockets in subdirectories. Only files ending with `.ws.ts` are loaded.

::

## Define a WebSocket Handler

Use `define.WebSocket()` to create a handler:

```typescript
import { define } from "@anteros/core";

export default define.WebSocket({
  enabled: true,
  exec: ({ io, rest, socket }) => {
    console.log("New user connected", socket.id);

    socket.on("join", async (room: string) => {
      socket.join(room);
      socket.emit("joined", { room });
    });

    socket.on("disconnect", () => {
      console.log("User disconnected", socket.id);
    });
  },
});
```

The file **must** use `export default` and end with `.ws.ts`.

## Handler Options

| Property    | Type       | Required | Description                                                    |
| ----------- | ---------- | -------- | -------------------------------------------------------------- |
| `enabled`   | `boolean`  | No       | Whether the handler is active (default: `true`)                |
| `namespace` | `string`   | No       | The Socket.IO namespace to serve (default `'/'`) — `'/chat'`   |
| `authorize` | `function` | No       | Gate per connection, **before** `exec` — return `false` to close the socket |
| `exec`      | `function` | **Yes**  | Handler called per connection receiving `{ io, socket, rest, agents, api, tenant }` |

### `namespace`

A handler can serve a dedicated namespace instead of the default one. Its rooms and its
connections are separate, and an event emitted on `/chat` never reaches `/`.

```typescript
export default define.WebSocket({
  namespace: "/chat",
  exec: ({ socket }) => {
    socket.emit("chat:hello", { id: socket.id });
  },
});
```

### `authorize`

A per-file gate, called for each connection **before** `exec` and after the global
`server.sockets.authorize` (the transport hook). It receives the same context as `exec`;
returning `false` (or throwing) closes the socket immediately.

```typescript
export default define.WebSocket({
  namespace: "/admin",
  authorize: ({ socket, tenant }) => socket.handshake.auth?.tenant === tenant.id && socket.handshake.auth?.role === "admin",
  exec: ({ socket }) => { /* … */ },
});
```

::prose-callout{variant="info"}

The connection is already established when a per-file `authorize` runs: a refusal is a
**disconnect**, not a `connect_error` (the client may briefly see `connect`, then
`disconnect`). For a refused **handshake**, use the global `server.sockets.authorize`.

::

## Handler Context

`exec` is called for each client connection with five properties:

### `socket` — The Connected Client

The [Socket.IO Socket](https://socket.io/docs/v4/server-api/#socket) instance for the current client. Use it to listen for events, join rooms, and emit back:

```typescript
exec: ({ socket }) => {
  socket.on("chat:join", (roomId) => {
    socket.join(roomId);
  });

  socket.emit("welcome", { message: "Hello!" });
};
```

| Method                      | Description                             |
| --------------------------- | --------------------------------------- |
| `socket.on(event, fn)`      | Listen for events from this client      |
| `socket.emit(event, data)`  | Send an event to this client            |
| `socket.join(room)`         | Join a room                             |
| `socket.leave(room)`        | Leave a room                            |
| `socket.to(room).emit(...)` | Broadcast to a room (excluding self)    |
| `socket.id`                 | Unique connection ID                    |
| `socket.handshake`          | Request metadata (headers, query, auth) |
| `socket.rooms`              | Set of rooms this socket belongs to     |
| `socket.disconnect()`       | Force-disconnect the client             |

### `io` — Socket.IO Server

The shared [Socket.IO](https://socket.io/) server instance. Use it for broadcasting to all clients or across rooms:

```typescript
exec: ({ io, socket }) => {
  socket.on("message", (data) => {
    io.to(data.roomId).emit("message", {
      text: data.text,
      socketId: socket.id,
    });
  });
};
```

| Method                     | Description                        |
| -------------------------- | ---------------------------------- |
| `io.emit('event', data)`   | Broadcast to all connected clients |
| `io.to(room).emit(...)`    | Send to a room                     |
| `io.sockets.adapter.rooms` | List active rooms                  |
| `io.engine.clientsCount`   | Count connected clients            |

### `rest` — Database Access

A `useRest` instance automatically scoped to the handler's tenant:

```typescript
exec: ({ rest, socket }) => {
  socket.on("room:join", async (roomId: string) => {
    const room = await rest.findOne("rooms", roomId);
    if (!room) {
      socket.emit("error", { message: "Room not found" });
      return;
    }
    socket.join(roomId);
    socket.emit("joined", { roomId, name: room.name });
  });
};
```

### `agents` — LLM Registry

Tenant-scoped LLM registry, bound to this handler's `rest` — `agents.get('support')`. See [Agents](/docs/ai/agents).

### `api` — In-process Facade

The same `rest` client, grouped the way the SDK groups it: bind a resource once (`api.collection('orders')`, `api.service('analytics')`) or reach a family (`api.vars`, `api.files`), plus `api.agent(id)`. Every call delegates to this handler's `rest` — see [Internal API → The `api` facade](/docs/manage-data/internal-api#the-api-facade).

### `tenant`

The tenant the handler belongs to — `{ id, name, dir, database, … }`. Handy for a log line
or to bind a claimed tenant (`socket.handshake.auth.tenant`) to the real one.

## Examples

### Chat Room

```typescript
import { define } from "@anteros/core";

export default define.WebSocket({
  enabled: true,
  exec: ({ io, rest, socket }) => {
    socket.on("chat:join", async (roomId: string) => {
      const room = await rest.findOne("rooms", roomId, {
        $include: ["messages"],
      });
      if (!room) return socket.emit("error", { message: "Room not found" });

      socket.join(roomId);
      socket.emit("chat:history", room.messages);
    });

    socket.on(
      "chat:message",
      async (data: { roomId: string; text: string }) => {
        const msg = await rest.insertOne("messages", {
          roomId: data.roomId,
          text: data.text,
          socketId: socket.id,
        });
        io.to(data.roomId).emit("chat:message", msg);
      },
    );
  },
});
```

### Live Dashboard — Broadcast DB changes

```typescript
import { define } from "@anteros/core";

export default define.WebSocket({
  enabled: true,
  exec: ({ io, rest, socket }) => {
    socket.emit("dashboard:stats", {
      users: await rest.countDocuments("users"),
      orders: await rest.countDocuments("orders"),
      revenue: await rest.aggregate("orders", [
        { $match: { status: "paid" } },
        { $group: { _id: null, total: { $sum: "$amount" } } },
      ]),
    });
  },
});
```

### Typing Indicator

```typescript
import { define } from "@anteros/core";

export default define.WebSocket({
  enabled: true,
  exec: ({ socket }) => {
    const typing = new Map<string, Set<string>>();

    socket.on("typing:start", (roomId: string) => {
      if (!typing.has(roomId)) typing.set(roomId, new Set());
      typing.get(roomId)!.add(socket.id);
      socket
        .to(roomId)
        .emit("typing:update", { userId: socket.id, typing: true });
    });

    socket.on("typing:stop", (roomId: string) => {
      typing.get(roomId)?.delete(socket.id);
      socket
        .to(roomId)
        .emit("typing:update", { userId: socket.id, typing: false });
    });

    socket.on("disconnect", () => {
      for (const [roomId, users] of typing) {
        if (users.delete(socket.id)) {
          socket
            .to(roomId)
            .emit("typing:update", { userId: socket.id, typing: false });
        }
      }
    });
  },
});
```

## Multi-Tenant

WebSocket handlers are scoped per tenant. Each tenant's `sockets/` directory is scanned independently, and the `rest` instance passed to `exec` is automatically connected to that tenant's database:

```
v1/
└── sockets/
    └── chat.ws.ts    → rest connects to app_v1

v2/
└── sockets/
    └── chat.ws.ts    → rest connects to app_v2
```

The `io` instance is shared across all tenants — use rooms prefixed with the tenant
(`v1:room-42`), a `namespace` per handler, or a check on `socket.handshake.auth.tenant`.

## Rooms

A room is a **server-side** concept: the client cannot join one by itself. It emits an
event, and the handler calls `socket.join()` — usually after checking that the caller may
enter:

```typescript
socket.on("room:join", async (roomId: string, ack?: Function) => {
  const room = await rest.findOne("rooms", roomId);
  if (!room) return ack?.({ ok: false, error: "ROOM_NOT_FOUND" });
  await socket.join(roomId);
  socket.to(roomId).emit("room:presence", { socketId: socket.id });
  ack?.({ ok: true });
});
```

| Call | Who receives |
| --- | --- |
| `socket.emit(event, data)` | the caller only |
| `socket.to(room).emit(...)` | the room, **except** the caller |
| `io.to(room).emit(...)` | everyone in the room, the caller included |
| `io.to(socketId).emit(...)` | one socket — every socket is in a room named after its own id |

`await socket.join()` is idempotent and accepts an array. **Rooms do not survive a
reconnection**: the socket is new, so the client must join again. The SDK does it for you
with `client.socket("/", { rooms: ["room-42"] })` (re-emitted on every `connect`).

## Reload and metrics

| Call | What it does |
| --- | --- |
| `sockets.list()` | the loaded handlers (`{ tenant, namespace, enabled }`) |
| `sockets.reload()` | re-scan `sockets/**/*.ws.ts` — listeners are removed first, so nothing stacks |
| `sockets.stop()` | remove every registered listener (shutdown does this) |
| `sockets.stats()` | `{ total, tenants }` — live connections, by the tenant they claim |

`GET /health` carries the same `sockets: { total, tenants }` block. A connection is
counted once, whatever the number of handlers attached to it.

## Security

`/socket.io/` is served by the Bun engine **before Hono**, so the HTTP middlewares do not run on that path: no `api.access`, no per-request token verification, no rate limit. The framework guards what it can at the transport level and leaves **authentication to the app** — a socket connection has no tenant path, so there is no rule to apply.

What the framework does:

- **CORS** — the same `server.cors` policy as the API, preflight included (`Access-Control-Allow-Origin` only for an allowed origin);
- **IP restriction** — the same `server.ipRestriction` allow/deny lists, resolved through the trusted proxy chain (`server.trustProxy`);
- **Security headers** — on the polling transport (an upgrade response carries none);
- **an optional handshake hook** — `server.sockets.authorize`, run once per connection.

```typescript
// config.ts — refuse a socket without a valid token
server: {
  sockets: {
    authorize: async ({ decoded, token }) => {
      if (!token || !decoded) return false;      // no token, or an invalid/expired one
      return typeof decoded.sub === "string";     // your own rule
    },
  },
},
```

The client presents the token where it can:

```typescript
import { io } from "socket.io-client";

const socket = io("http://localhost:4000", {
  auth: { token },                    // 1. the auth payload (browser-friendly)
  // extraHeaders: { Authorization: `Bearer ${token}` },  // 2. a Node client's header
  // query: { token },                                       // 3. a fallback
});
```

The hook receives `{ id, token, decoded, expired, auth, headers, query, address }`; `decoded` is the verified JWT payload when the token is valid, `null` otherwise. Return `false` (or throw) and the client gets a `connect_error`.

Inside a handler, `socket.handshake` is still available for anything the app needs (a tenant in the query, a session table lookup). **A handler that accepts every connection is a public endpoint** — say so explicitly in the app if that is the intent.

For a rule that needs the tenant database (`rest`, `api`, `agents`), use the per-file
[`authorize`](#authorize) — it runs after this transport hook, before `exec`.

::prose-callout{variant="info"}

The hook runs **after** the transport policies: a refused origin or a denied IP never reaches it. Registration is global (`io.use`), not per tenant — the tenant is known from the connection payload, not the path.

::

## Client-Side Usage

With **`@anteros/sdk`**, use the built-in client: it carries the tenant and token, re-joins rooms, and exposes every Socket.IO method with types — see [SDK → WebSocket (Socket.IO)](/docs/manage-data/sdk#websocket-socketio).

```typescript
const socket = api.socket();              // the default namespace
const chat = api.socket<ChatEvents>("/chat", { rooms: ["room-42"] });

chat.on("chat:message", (message) => console.log(message));
await chat.emitWithAck("room:join", "room-42");
```

Without the SDK, connect from the frontend using the [Socket.IO client](https://socket.io/docs/v4/client-api/):

```typescript
import { io } from "socket.io-client";

const socket = io("http://localhost:4000");

socket.on("connect", () => {
  console.log("Connected", socket.id);
  socket.emit("chat:join", "room-123");
});

socket.on("chat:message", (msg) => {
  console.log("New message:", msg);
});

socket.on("disconnect", () => {
  console.log("Disconnected");
});
```

## Enable / Disable

Toggle `enabled` to control whether a handler is loaded:

```typescript
export default define.WebSocket({
  enabled: false, // Handler is ignored at boot
  exec: ({ socket }) => { ... }
})
```

When `enabled` is `false`, the handler is simply not executed — no error, no side effect.

## Structure Summary

| Property     | Description                                                 |
| ------------ | ----------------------------------------------------------- |
| `enabled`    | `boolean` — whether the handler is active (default: `true`) |
| `exec`       | `({ io, rest, socket }) => void` — called per connection    |
| `ctx.socket` | Socket.IO `Socket` — the connected client                   |
| `ctx.io`     | Socket.IO `Server` — shared across all handlers             |
| `ctx.rest`   | `useRest` — database client auto-scoped to the tenant       |
| File pattern | `**/*.ws.ts` inside `{tenant.dir}/sockets/`                 |
| Timing       | Loaded at boot, after services                              |
