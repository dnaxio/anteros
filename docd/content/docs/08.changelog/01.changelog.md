## [Unreleased]

### Added

- **Audit — a DuckDB mirror (`audit.quack`).** `_audit_` stays the primary — what `rest.audit.getActivities()` reads and what the replication engine copies. `tenant.audit.quack` (with `server.audit.quack` as the fallback, `false` to opt out) adds a **second copy** in a `@anteros/duckdb` table, fed from the same choke point and **after** the insert, so the payload is the already-redacted entry and `data._id` joins back to the collection. `url` is a quack server (`quack:host:port`) **or a local `.duckdb` file path** (no server, no token); `table` defaults to `_audit_`, `ttl` mirrors `audit.retention` (a `retention()` job purges it every `purgeEvery`, default `1h`), `maxQueuedBatches` bounds the in-memory queue and `onError` reports a failed background write. `@anteros/duckdb` is imported **lazily** — the native module never loads for a tenant without the mirror — and the write is fire-and-forget: a quack server that is down never costs an audit entry nor slows a request. Every shutdown path drains the queue and closes the instance (`stopAuditQuack()`). Covered by `tests/audit-quack.test.ts` (mirror, redaction parity with `_audit_`, opt-out).
- **Audit — `audit.driver: 'default' | 'file' | 'quack'`.** The trail can be written somewhere other than `_audit_`: `'default'` (the collection, with the configured file / quack as **copies**), `'file'` (JSONL only) or `'quack'` (DuckDB only). The tenant wins over `server.audit.driver`. A selected driver that is not configured (`driver: 'file'` with `file: false`) falls back to `'default'` with **one** warning — an audit entry is never lost to a typo. The write is **awaited only when the driver is the only copy**, so a successful mutation keeps its trace, while the copies of `'default'` stay fire-and-forget; redaction applies wherever the entry lands. ⚠️ With `'file'` / `'quack'`, `_audit_` is not written at all: `rest.audit.getActivities()` returns nothing, the audit HTTP surface is empty and replication has nothing to copy — warned once per tenant at boot. Covered by `tests/audit-driver.test.ts` (the three drivers, and the fallback).
- **`@anteros/gateway` — a passive reverse proxy for Anteros microservices.** Routes `/api/<microservice>/…` to the deployment declared for that name, **without rewriting the path** — so the first segment is both the microservice name and the Anteros tenant id the backend expects. It forwards method, path, query, body, `authorization`, cookies and application headers; strips hop-by-hop headers and `host`; adds `x-forwarded-for`, `x-forwarded-proto`, `x-forwarded-host` and `x-request-id`; streams request and response bodies and passes **SSE** through untouched. `fetch` runs with `decompress: false` so a compressed upstream body keeps its `content-encoding`, multiple `Set-Cookie` headers survive via `getSetCookie()`, and `204`/`304` are forwarded with a null body. `timeoutMs` covers connection and **upstream response headers only** (never the body), with `502 UPSTREAM_UNAVAILABLE` and `504 UPSTREAM_TIMEOUT`. **No control**: no JWT verification, authentication, authorization, rate limiting, retries, cache, aggregation or WebSocket proxying — the gateway is not a trust boundary. Ships `defineGateway`, `createGateway`, `loadGatewayConfig`, the `anteros-gateway` binary, 61 tests and a docd page. Request logs are stored by `logging.engine`: `stdout` (default), `file` (JSONL in `.logs/gateway.log`) or `duckdb` (table `logs` in `.logs/gateway.duckdb`); the file engine supports `rotate` (`size`/`hourly`/`daily`/`weekly`/`monthly`/`yearly`), `maxSize`, `maxFiles` and `compress` (gzip), and DuckDB supports `ttl` + `purgeEvery` + `purgeOnStart` (a periodic `DELETE` of older rows, appender flushed first). `logging.captureBody` (off by default) adds `requestBody` from `request.clone()`, bounded by `maxBytes`, limited to textual methods/content types, with recursive redaction of sensitive keys. The DuckDB sink opens asynchronously (`gateway.ready`), flushes every 100 rows and on the now-async `stop()`. They are scoped — `logging.enabled` and `logging.microservices` (`"*"`, one name or a list) — and always JSON with an ISO 8601 `timestamp`, a `level` (`error` on 5xx, `info` otherwise), a `logger` name and static `logging.fields` (env, instance, version), never the token, cookie or body. CORS is **opt-in and per microservice** (`cors` global, `microservice.cors` override or `false` to opt out; `cors.origins/methods/headers/exposeHeaders/credentials/maxAge`): the preflight is answered locally, upstream `access-control-*` headers are stripped so only one authority applies, and `credentials` is refused with `origins: "*"`. The platform-token contract (HS256 shared secret, no `tenant` claim, `roles` per tenant enforced in `api.access`, `access: { "*": true }` forbidden on protected collections) is documented, not implemented here. Docs: `/docs/packages/gateway`.

- **`@anteros/reco` — face recognition, locally.** A separate, opt-in package: `createEngine()` loads InsightFace's `det_10g` (RetinaFace) and `w600k_r50` (ArcFace) through ONNX Runtime, and the engine returns faces carrying a **512-dimension unit embedding** — `detect()`, `embed()`, `recognize()`, **`getDescriptors()` / `getDescriptor()`** (the vectors alone, best face or all), `embedAligned()`, `compare()`, plus `cosineSimilarity()` / `findBestMatch()` for a 1:N search over an index you own. Inputs are a path, bytes, a `Blob` (`Bun.file()` included), **a base64 string, a `data:` URL or an explicit `{ base64 }`**, through every method, with `maxPixels` capping what an untrusted image may decode to (a string is a filesystem path — the docs say so). Detection outputs are grouped **by tensor shape** (1/4/10 channels) instead of name or order, boxes are NMS-filtered and clipped to the image, and alignment maps the five landmarks onto the ArcFace reference with bilinear sampling. Images are decoded by **`sharp`**, which returns raw pixels directly: EXIF applied, colour converted to sRGB, alpha dropped and 16-bit downscaled, with `maxPixels` mapped to `limitInputPixels`. **`createEngine()` downloads the pack itself** when `det_10g.onnx` / `w600k_r50.onnx` are missing — `fetch` streamed to disk, `unzip` (or `tar`) extraction, one download per directory shared by concurrent calls, controlled by `autoDownload`, `modelUrl` and `downloadTimeoutMs`, with `RECO_MODEL_DOWNLOAD_FAILED` / `RECO_MODEL_EXTRACT_FAILED` on failure; the standalone script remains. Other failures are `RecoError`s with stable codes (`RECO_MODEL_NOT_FOUND`, `RECO_MODEL_INVALID`, `RECO_NO_FACE`, `RECO_ALIGNMENT_INVALID`, `RECO_EMBEDDING_INVALID`, `RECO_ENGINE_CLOSED`…). The **`buffalo_l` weights are non-commercial research only**, stated on the page and in the README. Verified under Bun 1.4.4: 58 tests, and a real 1280x886 photo — six faces, six 512-d descriptors in ~420 ms, cross-face cosine between -0.08 and 0.21, self-comparison 1.000. Docs: `/docs/packages/reco`.

- **`api` — the in-process facade, in every context.** The contexts that already carried `rest`, `io` and `agents` now also carry **`api`**: the same grouping as the SDK and the HTTP API, in process. **`rest` is untouched and not deprecated — nothing has to be migrated**: `api` is _additive_ (a shape, not a replacement), and a contract test (`tests/api.test.ts`) pins every `rest` method so one cannot disappear by accident. `api.collection(slug)` is a client **bound to one collection** (`find`, `findOne`, `aggregate`, `countDocuments`, `watch`, `insertOne`, `insertMany`, `updateOne`, `findOneAndUpdate`, `updateMany`, `deleteOne`, `deleteMany`, `bulkWrite`, `bulkUpdate`, `dropCollection`, `dropIndex`, `dropIndexes`, `runAction`), and the families are grouped the same way: `api.vars` (the same object as `rest.vars`), `api.service(name).run(action, data)`, `api.files.url(collection, filename, { width, height, format, quality })`, `api.files.delete(collection, fileId)` (the exact `handleDelete` the route uses — binary **and** document, audited), `api.agent(id)` (bound to the same `rest`, `undefined` if unknown). **Nothing is re-implemented**: every call lands on the corresponding `rest` method, so audit, collection hooks, access rules, the Mongo session and the transaction stay those of the caller — `rest` is unchanged and still available. Naming rule, shared with the SDK: **singular = a client bound to one resource** (`api.collection(slug)`, `api.service(name)`, `api.agent(id)`), **plural = the family's operations** (`api.vars`, `api.files`). Injected in hooks and custom actions, services, routes, scripts (heavy ones included), sockets, workflow steps and compensations, lifecycle hooks and MCP tools/resources; typed in `HookContext`, the service/action/route/script/socket/workflow/lifecycle/MCP contexts. Note: there is **no `upload` in process** (an upload is a multipart request) — use the route or a `define.FileCollection`. Covered by `agents-api.test.ts` (route, service and hook probes now assert the facade, including "same result as `rest`" and a write that fires the collection hook) and `upload.test.ts` (`api.files`).

- **Agents** — a per-tenant LLM runtime (`define.Agent`, `{tenant.dir}/agents/**/*.agent.ts`, `agents.get(id)`).
  - **`id` and `description` are required** — the id identifies the agent (`agents.get('weather')`, `info`, the HTTP route), the description says what it is for and is served to whoever discovers it. No more id derived from the file name; a definition missing either is refused at load (logged, the other agents still load).
  - **Provider declared inline** — `{ model, apiKey, compatible: 'openai' | 'anthropic', baseUrl, headers, options }`: the model, the credentials, the endpoint **and how it is called** (`provider.options` — `{ temperature, maxTokens, topP, timeout, retries }`, merged into `provider` when a call overrides them, readable with `getOptions()` / `setOptions()`). Called with `fetch`: **no SDK, no dependency**. `'openai'` (the default) covers every OpenAI-compatible gateway; a bare `baseUrl` host gets `/v1` appended. The key falls back to `ANTEROS_AI_API_KEY`, then `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` — the definition stays valid without one (`AGENT_PROVIDER_NO_API_KEY` at call time, never at boot).
  - **Tools** — `define.Tool({ id, description, inputSchema, execute })`: the **`id` is required** (it is the name the model calls — the record key must match it, `AGENT_TOOL_ID_MISMATCH` otherwise; an MCP tool keeps the protocol's `name`). The schema accepts Joi (`v`), zod or a plain JSON Schema, is converted to JSON Schema for the model and **enforced** before the handler runs. `define.McpTool` is accepted as-is (its `exec` is adapted, its `{ content: [...] }` result flattened to text). A failing tool is reported to the model (`Error: …`) instead of failing the run.
  - **`skills` — markdown documents injected into the system prompt** — `define.Agent({ skills: ['./docs/*.md', './guide/ml.md', /^runbooks\/.*\.md$/] })`: a **string** is a path or a glob resolved from the **tenant directory** (absolute paths as-is), a **RegExp** is matched against the relative path of every file of the tenant (so a regex is just another way to walk the tenant), and `./guides/**/SKILL.md` covers the directory-skill layout. Files are read **once, at boot** (`resolveSkills()` in `lib/skills.ts` — a run never touches the filesystem) and their body is injected as-is under a `## Skills` heading, after the instructions and **before** the working memory, so the prefix of the prompt stays static and cacheable. The frontmatter format is the shared one: `name` (required, kebab-case, 1-64 characters, and the **parent directory** when the file is a `SKILL.md`), `description` (required, ≤ 1024 characters), `license`, `compatibility` (≤ 500 characters), `metadata` (arbitrary key-value pairs, kept out of the prompt) and `allowed-tools` (space-separated; parsed and served by `getSkills()`, **not enforced** — a skill is always in the prompt, so there is no activation to scope, and `tools: ['read_pdf']` / `tools: false` / `maxSteps` remain the run's own controls). The body is **required** too: frontmatter alone injects nothing. A malformed skill **refuses the agent** at load (`AGENT_SKILL_INVALID` / `AGENT_SKILL_DUPLICATE` / `AGENT_SKILL_TOO_LARGE` — a typo never changes a prompt silently) while the other agents keep loading; a file that is not markdown is skipped with a warning, a pattern that matches nothing is reported, and the same file matched twice stays **one** skill. `agent.getSkills()` returns the resolved documents (`name`, `description`, `license`, `compatibility`, `metadata`, `allowedTools`, `content`, `source`), and `info` serves `name` + `description` only. The frontmatter reader is dependency-free (`parseFrontmatter()` — mappings, sequences, inline `[a, b]` / `{ k: v }`, no multi-line scalars, no anchors).
  - **`generate()`** — the tool loop runs until the model answers without a tool or `maxSteps` (default 5) is reached; returns `text`, `toolCalls`, `toolResults`, `steps`, `usage` and the whole `messages` conversation. **`stream()`** — `textStream` / `fullStream` plus promises (`text`, `object`, `toolCalls`, `usage`…) that resolve at the end of the run, and `abort()`.
  - **`version`, `toolTimeoutMs`, `parallelTools`, `savePartial`** — the run-level options. `version` names the prompt (`'2026-09-24'`, `'v3'`): served by `info`, written on every audit entry, so an answer is traceable to the prompt that produced it. `toolTimeoutMs` (per agent, per tool via `tool.timeoutMs`, per call) **abandons** a tool that hangs — the deadline also travels on `ctx.signal` so a cooperative tool stops itself, and the model is told `Error: Tool 'x' timed out after 2000ms` while the run goes on. `parallelTools` runs a step's tools together (`Promise.all`), results attached in the model's order; off by default, because two writes must not interleave. `savePartial` stores what a **failed** run produced instead of losing the whole exchange (the `save` processors still run, so a guardrail keeps its veto).
  - **Approvals (human-in-the-loop)** — `define.Tool({ approval: true })` pauses the run **before anything executes**: `finishReason: 'approval_required'`, `result.pendingApprovals`, nothing written to the thread, and the caller resumes with `{ resume: { messages, decisions } }`. The paused step is **not replayed through the model** (approving costs exactly one model call), a step is all-or-nothing (an assistant turn never carries half-answered calls, which the protocols refuse), and a refusal reaches the model as `Error: Refused by the caller`. Same payload over HTTP — `resume` in the body, `pendingApprovals` + `resume` in the response.
  - **`agents` — another agent as a tool** — `agents: [researcher]` exposes an agent under its `id`, described by its own `description`, taking `{ input, thread?, resource? }` and answering with its text. Built per call and bound to the calling `rest` (so the sub-agent's own tools run with the right tenant, session and transaction), its `skills` resolved at load like any agent's, dropped by `tools: false` / an allow-list like any tool, and a declared tool wins on a name clash.
  - **`mcp` — a remote MCP server's tools** — `mcp: ['https://host/mcp']` (or `{ name: url }`, the name for the logs) lists a remote server's tools and adapts them into ordinary `AgentTool`s: **the other direction of the protocol the framework already serves** (SDK client + Streamable HTTP). Connected **lazily**, on the first run that needs them — a remote that is down must not slow a boot down — and memoized **per server**, so a failure is retried on the next run while the servers that answered keep serving. A tool the agent declares itself wins; a tool that fails is reported like any other. `closeMcpClients()` (also called by `agents.reload()`) closes the live clients.
  - **`agents.memory.summarize()` — history compaction** — a `load` processor that replaces the turns older than the last `keep` with one `[Summary of the conversation so far]` turn written by a model **you** name (`threshold` defaults to `keep * 3`, `prompt` builds the request — a support thread and a legal review condense very differently). The summary is **cached in the store's state**, per thread, and refreshed only once the window has moved on by `keep` turns: a long conversation costs one summary per `keep` turns rather than one per turn, and the prompt prefix stays put between refreshes. An empty answer compacts nothing rather than losing the conversation. It is a **processor**, not a store — the registry test that pins `agents.memory` was updated deliberately.
  - **Structured output really is a schema on the wire** — an OpenAI-compatible gateway now gets `response_format.json_schema` (named from `api.object.name`, defaulting to the agent id, sanitized to `[a-zA-Z0-9_-]{1,64}`) instead of the bare `json_object`, with a **one-shot downgrade** to `json_object` when a gateway answers 400 _about the schema_ (and no downgrade for an unrelated 400). Anthropic, which has no such field, gets a **forced tool** carrying the schema — and the adapter turns that call back into the answer, never surfacing it as a tool call the run would execute (streaming included: the `input_json_delta` tokens are emitted as text). A forced tool is incompatible with extended thinking, so that combination stays prompt-only + repair turn, as documented.
  - **Prompt cache** — `provider.options.cache: true` puts an Anthropic `cache_control` breakpoint on the stable prefix (the system prompt and the last tool), so the instructions, skills and tool definitions are billed once instead of on every run. A no-op on OpenAI-compatible gateways, which cache by themselves.
  - **Structured output** — `schema` (or `generateObject()`) parses and validates the answer, tolerating a markdown fence, makes **one repair turn** and fails with `AGENT_OUTPUT_INVALID` if it stays invalid.
  - **Attachments** — `{ files: ['./invoices/2026-01.pdf'] }` server-side (a path, read at call time) or `{ files: [input.files[0]] }` from the SDK (a `File`/`Blob`, base64 on the wire; `{ name, data, encoding: 'utf8' }` for text). Each file becomes what a model understands: **text** (md, csv, json, code…), an **image** part (png/jpg/webp/gif), a **document** part (pdf), or extracted text for **`.docx`** (`word/document.xml`) and **`.xlsx`** (one CSV block per sheet) — both read through a **dependency-free ZIP reader** (`lib/zip.ts`, `node:zlib`). Anything else is refused (`AGENT_FILE_UNSUPPORTED`, with a hint for `.doc`/`.xls`/`.ppt`), a path that does not exist is `AGENT_FILE_NOT_FOUND`, and 10 MB per file / 200 000 characters per inlined text are the hard limits. Attachments land on the **current user turn**; the memory keeps the **text** (it replays) and a `[image]` / `[file invoice.pdf]` note for the binaries.
  - **Per-call control** — `tools` takes a **boolean, an allow-list or extra definitions**: `true` (default) = every tool the agent declares, `false` = **none at all** (the definitions are not even sent), `['forecast']` = **only these** (an unknown name is ignored), `{ … }` = extra tools merged in. Plus `toolChoice` (`'auto' | 'none' | 'required' | { name }`, mapped to `tool_choice` on OpenAI and `{ type: 'auto' | 'none' | 'any' | 'tool' }` on Anthropic), `thinking` (`true` / `'low' | 'medium' | 'high'` / `{ budgetTokens }`), and `instructions`, `provider`, `maxSteps`, `schema`, `files`, `signal`, `onStepFinish`.
  - **Thinking output** — `thinking` maps to a real **budget** (Anthropic) or a **reasoning effort** (OpenAI-compatible), and the reasoning is never mixed with the answer: `result.reasoning`, `step.reasoning`, and a dedicated `reasoning` event on `fullStream`. OpenAI-compatible endpoints exposing `reasoning_content` (DeepSeek, Groq…) are surfaced the same way. On Anthropic, `max_tokens` is **raised** above the budget and `temperature` omitted (both required by the API), and a tool round **echoes the signed reasoning blocks** back — kept raw on the assistant message, streaming included (`signature_delta` accumulated by the adapter). `AGENT_THINKING_INVALID` refuses a budget below 1024.
  - **`thinking` is a declaration default** — `define.Agent({ thinking: 'medium' })` applies to every run, like `toolChoice`; a call overrides it, and `thinking: false` turns the declaration off for one run (a value, not an absence). Exposed by `info` / `toJSON()` next to `toolChoice`.
  - **Memory** — `AgentMemory` (`get` / `save` / `clear`, optional `list`) receiving a `{ agentId, tenant, rest, resourceId }` context; `thread` replays the conversation, `memory: { readOnly: true }` reads without writing, and a failed write is logged instead of failing the run.
    - **`agents.memory.Mongo`** — durable, one document per thread in a collection **the tenant names** (`collection` is required: `_memories_`, `support_threads`…, created with its indexes on first use, never at boot). A **hard `maxMessages` cap** (default 100, the opening `system` message keeps a slot), opt-in **`ttl` retention** on `updatedAt`, threads **namespaced per `resourceId`** (`user-42:chat-1`), `title` derived from the first user message, and `list()`.
    - **`agents.memory.InMemory`** — the same options on a per-process `Map` (demos, scripts, tests).
    - **`agents.memory.Redis`** — one key per thread (`anteros:agent-memory:<tenant>:thread:<resourceId>:<threadId>`) plus a sorted set per caller for `list()`, with an optional **`ttl` refreshed on every save**. The **tenant is part of every key** (a store built once can serve several tenants) and the store **refuses to run without one** (`AGENT_MEMORY_NO_TENANT`); the `ioredis` client is connected lazily and can be provided (`client`). Outside MongoDB, it is outside the replication engine — documented.
    - **Replicated** — the agent loader publishes the memory collection of every agent (`collections()` on the store → `cfg.agentMemories`), and the replication engine copies it like a declared collection: whatever name you chose, `replication.exclude: ['memory']` is the opt-out. A **cleared thread writes a tombstone** (`replicatesCollection()` in `database/deleteLog.ts` resolves a slug to the name the config knows) so the deletion follows the data instead of leaving an orphan on the destination. The Redis store is out of scope by nature (it is not a MongoDB collection).
    - `agent.listThreads()`; HTTP `threads` action (`AGENT_MEMORY_NO_LIST` / `AGENT_MEMORY_NO_REST` when it cannot serve) and SDK `threads()`; `history` / `clear` / `generate` all take the same `resource`.
    - **`memory: { resource, thread }`** — the Mastra-style shorthand on `generate()` / `stream()` / `object()` (server and SDK): `thread` / `threadId` are interchangeable, as are `resource` / `resourceId`, the `memory` block wins over the flat options, and `readOnly: true` runs a preview without writing the exchange back. `getMessages()`, `clearMessages()`, `listThreads()` and every HTTP action accept the same names — the run and the reads always resolve to the same thread.
    - **`messages` — injecting turns into a run** — the option carries what the run must **know**: an `AgentInput` (one turn, or a conversation) placed **after** the thread history and **before** the input, sent to the model _and_ saved with the rest of the conversation, so a seed, a history imported from another system or a priming turn pair (an injected block may end on an `assistant` turn) becomes part of the thread. Normalized exactly like the input, needs no `thread` to be sent, and `result.messages` shows where it landed.
    - **`agent.remember(thread, messages)` — writing a thread with no model call** — a store replaces a whole thread on `save()`, so this reads it, appends, and writes it back: the caller namespace (`resource`), the `maxMessages` cap and the same normalization as the input apply (an attachment is stored as a note, a `tool-result` part as the `tool` turn it means). Returns the stored thread. It is the write-only door for seeding a conversation or importing a transcript; an agent without a `memory` refuses with `AGENT_NO_MEMORY`, and unlike a run (where a failed write is only logged) it **throws**, because the caller asked for that write.
    - **`workingMemory` — a durable scratchpad** — `define.Agent({ workingMemory: { template: '# Customer\n- Name:\n- Plan:' } })` (or a `schema`, then the update is a validated **deep merge** with `null` removing a key and an array replacing an array). It is injected into the system prompt of every run, and the model keeps it up to date through an auto-generated `updateWorkingMemory` tool; the framework **never picks a tool** elsewhere, and this one obeys the run: `tools: false` or an allow-list removes it, a parameter declaring the same id wins, and `memory: { readOnly: true }` injects the block without the tool. Scope is `'resource'` (one profile per caller, shared by their threads — the default) or `'thread'`; without the id it needs, the run simply has no scratchpad. Read and written from code with `getWorkingMemory()` / `setWorkingMemory()` / `clearWorkingMemory()` — no model call — and persisted by the store: Mongo derives a second collection (`support_threads` → `support_threads__state`, published to the replication engine like the threads), Redis a `<prefix>:<tenant>:state:<key>` key with no expiry, InMemory a `Map` beside the threads. A store that omits `getState`/`setState` makes it inert (`AGENT_WORKING_MEMORY_UNSUPPORTED` on an explicit write); a definition with neither `template` nor `schema` — or both — is refused at load.
    - **`lastMessages` — the history window** — `lastMessages: 6` on the definition or per call replays only the last N messages of the thread, **after** the store read and **before** the prompt: a prompt decision, never a write (the thread keeps everything, `remember()` and `getMessages()` still see it all), and a stable prompt prefix for the provider cache. Deliberately no token-budget variant: a tool result can weigh a few tokens or thousands, so a `save` processor is the honest place for that.
    - **`processors` — your code around the memory** (Mastra-style) — one ordered list, two hooks: `load` rewrites what the **model** will see (thread windowed, injected turns, input, attachments), `save` rewrites what will be **stored** (`save` runs before the cap and before the attachments become notes). A processor that returns nothing leaves the messages alone; a throwing `save` keeps the whole conversation out of the store — the guardrail — while the caller still gets the answer (the skip is logged). This is also the documented seam for **semantic recall**: the framework ships no embedder and no vector database on purpose, so recall is a `load` processor over an index you control, and indexing a `save` one.
  - Tools receive the **caller's** `rest` (the `agents` member of a context binds it), plus `agent`, `tenant`, `toolCallId`, `step`, `signal` and `error`.
  - The loader isolates a broken file (like the other loaders), reports a duplicate `id` and defaults the id to the file name; the boot banner gained an `Agents:` line.
  - **Reachable from every context** — `agents` is injected next to `rest` and `io` in every tenant-scoped context (route, service action, collection hook and action, socket, script — heavy scripts included — lifecycle, workflow step, MCP tool/resource), so `agents.get(id)` needs no tenant. Outside a context (module scope, a global middleware, a `Bun.cron`), the importable registry takes the tenant: `agents.get(tenantId, id)` / `ids` / `list` / `has` / `stats()` / `reload()` (a `rest` can be passed as the third argument).
  - **`agents.get()` returns a copy bound to the context's `rest`** — the registry instance is shared by every caller, so binding it in place would leak one request's client (and its Mongo session) into another. The copy shares the declaration: instructions, tools, memory.
- **Agents HTTP API** — `POST /api/:tenant_id/agents/:agent/:action`, the same shape and the same access model as the services API (`api.access`, **no rules = denied**).
  - **Actions** — `info` (metadata, no model call), `generate`, `stream` (**SSE**), `object` (structured output, schema declared under `api.object`), `history` and `clear` (memory threads).
  - **A client only chooses what it may** — the input, a memory thread, a `resourceId` and a **lower** `maxSteps` (clamped to the declared ceiling). The provider (model, endpoint, key), the options and the structured-output schema stay server-side, so a caller can never spend on another model, point the agent elsewhere or dictate the output shape.
  - **Streaming** is one SSE event per runtime chunk (`text`, `tool_call`, `tool_result`, `step`, `finish`) then `{ type: 'done', result }`; a mid-run failure travels as `{ type: 'error', code }`, and a client disconnect **aborts the run** instead of burning tokens (the request signal is handed to the agent).
  - **Audited** as `agent.generate` / `agent.stream` / …, `collection: '_agents_:<id>'` (the `_vars_:<namespace>` convention): the prompt is kept (capped at 2000 chars, redacted), the **answer and the tool arguments never are** — `result` holds the finish reason, the usage, the tool **names** and the step count. A refused call is recorded as `status: 'error'` too.
  - Access rules now receive the agent, the action, the input and the thread (`{ rest, agent, action, body, input, thread, token, jwt, error }`, plus the deprecated `threadId` alias), and the shared helpers (`evaluateAccess` / `errorResponse` / `getAccessToken`) moved to `server/access.ts` so the collection/vars/service API and the agents API cannot drift apart.
- **SDK — `api.agent(id)`** — a client bound to one agent, mirroring the API: `info()`, `generate()`, `object()`, `stream()`, `history()`, `threads()`, `clear()` (plus `getId()`), with `thread` / `resource` / `maxSteps` options. `stream()` resolves the headers first (a `401` or an unknown agent throws _there_, not mid-stream) and exposes `textStream`, `fullStream`, `text`, `object`, `toolCalls`, `toolResults`, `steps`, `usage`, `finishReason` and `abort()` — which ends the streams and rejects the promises with an `AGENT_STREAM_ABORTED` `AbortError`.
- **JSON Schema helper** (`lib/jsonSchema.ts`) — the Joi → JSON Schema converter used by the MCP server was extracted and shared with the agent runtime (a tool now looks identical over MCP and to a model), and gained zod / plain JSON Schema support. The bogus `description: "required"` it used to add to required fields is gone.
- **Variables** — a per-tenant Redis-like key/value store: `rest.vars.set(ns, key, value)` / `get` / `del` / `has` / `all` / `incr` / `clear`.
  - Declarable with `define.Vars({ namespace, scope, meta, vars })` — `{tenant.dir}/vars/**/*.var.ts` — defaults seeded at boot without overwriting.
  - **`scope`** — one optional identity field (e.g. a `relationship`), part of the entry key: one value per company/branch/environment (`rest.vars.scope(id)`).
  - **`meta`** — annotation fields validated with the collection field DSL (Joi) — never part of the key.
  - **TTL** — per call (`{ ttl }`) or per variable (`vars: { session: { type: 'string', ttl: '1h' } }`), enforced by a MongoDB TTL index **and** re-checked at read time; `expire()` to renew.
  - MongoDB-backed (`_vars_` collection, one document per `scope:namespace:key`). Durable, unlike `rest.cache`.
  - **HTTP API** — `POST /api/:tenant_id/vars/:action` (`set` / `get` / `del` / `all` / `incr` / `expire`…), gated per namespace by `define.Vars({ api: { access } })` — **denied by default**.
  - **Replicable** — `define.Vars({ replication: { enabled: true } })` opts a namespace in, like a collection; only the opted-in namespaces of `_vars_` are replicated (per-document filter), and `del` / `clear` propagate via tombstones.
  - **SDK** — `api.vars.*` mirrors the server API (same scopes, meta and TTL).
  - **File collections** can also opt into the data replication engine — `define.FileCollection({ replication: { enabled: true } })` replicates their documents (metadata); combine with `replicate` for the binaries. Upload records now carry `createdAt` / `updatedAt` (BSON `Date`s, exposed in the response too), and custom fields are converted like a collection insert (`toBson`, e.g. `date` fields → `Date`).
  - **Fixed** — single-file uploads (`POST /api/:tenant_id/upload/:slug` with one file) no longer fail with a 500.
- **Lifecycle** — per-tenant lifecycle hooks: `{tenant.dir}/lifecycle.ts` with `define.Lifecycle({ beforeBoot, afterBoot, onDestroy })`.
  - `beforeBoot` — blocking, runs after DB + collections, before replication and before the server listens (migrations, seeding). Fail-fast on error.
  - `afterBoot` — once the server is listening (notifications, warmup). Never fatal.
  - `onDestroy` — on SIGINT/SIGTERM, before replication stops and DB clients close, bounded by `destroyTimeout` (default 10s).
  - Context exposes `rest` and a **tenant-bound** `replication` API (like `rest`, no tenant id) — so `beforeBoot` can `reset()` or `seed()` a replication before it starts.
  - Runs once in cluster mode (master/standalone only, never in workers).
- **Replication** — one-way, incremental replication of collection data from a tenant's main database to one or more destination databases.
  - **Per tenant** configuration: `replication.destinations`, `schedule` (`{ cron }` or `{ interval }`), `key`, `batchSize`, `lookback`, `initialSync`, `runOnBoot`.
  - **Opt-in per collection**: `replication.enabled`.
  - Incremental **date cursor** with an `_id` tie-breaker (default key `updatedAt`) — inserts and updates always replicated.
  - **Initial sync control** (`initialSync: 'full' | 'skip' | 'latest' | Date`) to skip the full backfill on a pre-loaded destination.
  - **Delete propagation always on** — hooks + tombstones persisted in the `_replication_` collection, with no configuration needed.
  - **Runtime control** — `replication.reset()` forgets a tenant's progress, `replication.seed()` sets the starting point (`'now'`, `'latest'` or a `Date`). Both are reachable from a lifecycle `beforeBoot` hook.
  - Distributed lock, `bulkWrite` chunking + retry/backoff, and a cluster guard (master-only).
  - Public API: `replication.start()`, `replication.stop()`, `replication.now()`, `replication.state()`, `replication.reset()`, `replication.seed()`.
- **Replication-only process** — `bun index.ts --replication-only` (or `server.mode: 'replication-only'`; the flag wins) boots a process **dedicated to the replication engine**: no HTTP API, no websocket handlers, no scripts, no services, no MCP tools, no middlewares, no cluster, no metrics. Tenant databases, collections, file collections, variables and lifecycle hooks are still loaded (`beforeBoot` runs before replication starts — the documented place to seed/reset it — and `onDestroy` runs on shutdown; `afterBoot` is skipped, there is no listening server). The process keeps itself alive (replication timers are `unref`'d) and stops cleanly on `SIGINT`/`SIGTERM`. Covered by an end-to-end test that boots the real fixture with the flag: data is replicated, `/health` refuses connections, the lifecycle marker is written, the script marker is not, and `SIGTERM` exits 0 after `onDestroy`.
- **No-replication process** — `bun index.ts --no-replication` (or `server.mode: 'no-replication'`) is the mirror image: a **full** server (API, sockets, services, routes, scripts, MCP, middlewares) that **never starts the replication engine** — no scheduling, no `_replication_` collection, no tombstones, nothing written to the destinations. Handy to deploy the same codebase where replicating is not wanted, without stripping the tenant configuration. Passing both flags is allowed: `--replication-only` wins and a warning is printed. Covered end-to-end: the API answers `/health`, the destination stays empty, no `_replication_` state is created, and scripts/lifecycle still run.
- **Granular boot flags** — `--no-scripts` (never runs the tenant scripts) and `--no-sockets` (no Socket.IO handlers, `/socket.io/` is not served at all) sit next to `--replication-only` / `--no-replication` / `--api-only`, and `server.mode` accepts `'api-only'` as a fourth preset. They all resolve to four **capabilities** (`api`, `replication`, `scripts`, `sockets`): the flags win over `server.mode`, `api: false` disables what the API carries _and_ the scripts, and the banner only prints a `Mode:` line when something is off (`Mode: api-only (replication, scripts, sockets off)`). Contradictory flags (`--replication-only` with `--no-replication`/`--api-only`) resolve to replication-only with a warning.
- **Audit — file operations** — uploads (`POST /api/:tenant_id/upload/…`) and file deletions (`DELETE /api/:tenant_id/files/…`) are now audited: `action: "upload"` / `"deleteFile"`, `collectionType: "file"`, with the file metadata (`name`, `mimetype`, `size`, plus the **names** of the custom fields) and the generated `_id` — never the stored document. `09.files.md` already claimed uploads were audited; they now are. Served files (`GET /api/:tenant_id/files/…`) are deliberately not audited.
- **Replication — agent memory collections** — the Mongo store's collection is now **named by the tenant** (`agents.memory.Mongo({ collection })`, required) and **replicated by default**, like `_audit_` or `_vars_`: the agent loader publishes what its stores write to (`cfg.agentMemories`), the engine copies those slugs (`key: updatedAt`), and `replication.exclude: ['memory']` leaves every conversation on the source. A **cleared thread propagates its deletion** (the store writes a tombstone — `writeDeleteMarkers` / `replicatesCollection`, which resolves a slug to the name the config knows and skips a collection nobody replicates, instead of piling up an unflushable marker). Two limits documented: a `ttl` set on the store prunes the source only, and a store created outside the loader is not published.
- **Workflows — loader (`lib/workflow.ts`)** — the boot loader now indexes what `_workflows_` is actually queried with: `{ workflowId: 1, createdAt: -1 }` (`listRuns()`) and `{ status: 1 }` (`resumeAll()`) — those queries were scanning the whole collection. The index pass creates only the missing indexes, in `background`, and **never blocks boot** (it used to be awaited, one blind `createIndex` per declared context field). It also creates the collection when missing (`listIndexes()` fails on a non-existent namespace, so a tenant that had never run a workflow got **no** index at all).
  - **`enabled`** on `define.Workflow` (default `true`) — keep a definition without registering it.
  - A definition **without `id`** is ignored with a warning, and a **duplicate `id`** for a tenant is reported (the last file wins, a single entry is kept).
  - A file that **throws on import** no longer aborts the load of the other workflows and other tenants.
  - `workflows: loaded` is written to the log file, and the boot banner gained a `Workflows:` line.
  - **`context` is validated at `run()`** — the declaration's `type` is now enforced: a `string` field receiving a number, or an invalid date, is rejected with `WORKFLOW_CONTEXT_INVALID` (400) instead of being stored silently; a `date` sent as an ISO string is coerced to a real `Date` so the `context.*` indexes stay typed. Undeclared keys are still kept.
  - **`indexes[]`** on a workflow definition — compound, `unique`, `sparse`, explicitly `name`d indexes on `_workflows_` (`{ key: { 'context.companyId': 1, status: 1 } }`), created like the rest: only the missing ones, in the background.
  - **Loaders are isolated per file** — `importDefinition()` (`lib/load.ts`) is now used by the collections, file-collections and MCP loaders too: a file that throws on import is logged and skipped instead of aborting the whole loader (for every tenant).
- **Workflows — engine robustness** — the run engine (`database/workflow.ts`) is now safe to operate in a cluster and to resume after a crash.
  - **Distributed lock per run** (`_locks_`, `workflow:<runId>`, refreshed before every step, TTL 15 min) — two nodes can no longer advance the same run; the loser gets `RUN_LOCKED` (409).
  - **`pause()` / `cancel()` are effective on an in-flight run** — they stop it at the next step boundary. Progress writes are now a compare-and-set that refuses to overwrite a `paused`/`cancelled` run, and a step's **completion is persisted immediately** (it used to be written only by the next iteration, so a pause lost the result and the step was replayed). `pause()`/`cancel()` return a boolean, and `cancel()` ignores runs that are already terminal.
  - **Compensations are never replayed**: a successful compensation is not run again, an interrupted rollback is **finished** by `resume()` instead of restarted, and a fully rolled back run becomes `compensated` — a new status, refused by `resume()` (409 `RUN_COMPENSATED`) and excluded from `resumeAll()`. A partially rolled back run stays `failed`.
  - **Resume guards**: `completed` / `cancelled` / `compensated` runs are refused (`RUN_TERMINAL`), and a run started by another `version` of the definition is refused (`WORKFLOW_VERSION_MISMATCH`, 409) unless `{ force: true }`.
  - **Per-step `retries` / `backoffMs`** — a transient failure is retried (exponential backoff, capped at 5s) instead of rolling the saga back, and **`timeout`** aborts a step that hangs (`WORKFLOW_STEP_TIMEOUT`), aborting the `signal` handed to the handler.
  - **Run retention** — `server.workflows.retention` / `tenant.workflows.retention` (tenant wins) maintains a TTL index on `completedAt`: only **finished** runs are pruned, in-flight ones never are.
  - **`resumeAll()` is batched** by `_id` (a large backlog is no longer loaded in memory), and **step handlers receive a real `rest` client** — they used to get the engine instance, so `rest.findOne(...)`/`rest.workflow.run(...)` inside a step could not work (the documented `rest.mongo.*` never existed).
  - ⚠️ **A step is at-least-once** — a process dying _inside_ a step means that step is re-executed on resume; the documentation now says so and asks for idempotent steps. There is still **no transaction** spanning the run state and the step writes.
- **Distributed locks carry their owner (`pid` + `hostname`)** — `rest.lock()` records which process holds a lock, and a lock whose owner is **gone on the same host** is taken over **immediately** (the pid is probed with `kill(pid, 0)`) instead of waiting for the TTL. A foreign-host owner can only be taken over when it expires, and `unlock()` never removes a lock another node took over. Motivated by Bun `reusePort` / forked deployments, where several processes run the same code.
  - The lock holder is also recorded where the work happens: `_replication_.pid`/`hostname` on every state document, `_workflows_.pid`/`hostname` on every run. A workflow that **loses** its run lock (another node took it over) stops at the next step boundary without writing anything.
- **Replication — framework collections are replicated by default** — `_audit_`, `_workflows_`, `_locks_`, `_replication_` and `_vars_` are now copied to the destinations, each read with the key the framework itself uses (`_audit_` on `ts`, the rest on `updatedAt`). Opting out goes through a **typed list** — `replication.exclude: ['locks', 'replication']` (`'audit' | 'workflows' | 'locks' | 'replication' | 'vars'`) — applied per tenant and by destination (`collections: ['_audit_']` still narrows a single destination). A tenant's own collections stay **opt-in**.
  - ⚠️ **`_vars_` now carries every namespace**: a namespace is replicated unless it declares `replication: { enabled: false }`, and `exclude: ['vars']` wins over everything. Namespaces holding secrets must be opted out explicitly (they used to be excluded by default).
  - **The destination mirrors the source retention** — internal collections have no hooks, so their deletions never propagate: with `audit.retention` / `workflows.retention` set, the destination gets the same TTL index and prunes itself (`database/ttl.ts` shared helper).
  - **Numeric replication keys fixed** — the delete guard compared the key to a date, so a collection using a numeric key silently skipped every deletion on the destination (`filter` now matches the date **or** its epoch — `database/replication.ts`, `flushDeletes()`).
- **Audit — indexes** — the `_audit_` collection now gets four query indexes created automatically at boot, in the background, for every tenant: `ts`, `operation.collection + ts`, `operation.status + ts`, and `trace.id`. No more collection scans on `rest.audit.getActivities()`.
- **Audit — retention (opt-in)** — a MongoDB TTL index on `ts` expires `_audit_` entries on their own. Set globally (`server.audit.retention`) and/or per tenant (`tenant.audit.retention`) — **the tenant always wins**, `false` opts a tenant out of the server default, omitted keeps entries forever (default). A duration change is applied in place with `collMod`, an invalid value is logged and ignored.
- **Audit — local file backup (opt-in)** — `server.audit.file` and/or `tenant.audit.file` append every activity to a JSONL file on the application server, independent from MongoDB: one dated file per day (`audit-<tenant>-YYYY-MM-DD.jsonl`), rotated on size (`-1`, `-2`…), pruned by age, values defaulting to `<logging.dir>/audit`, 50MB and the database retention. Same precedence rule as retention (**the tenant wins**, `file: false` opts out). Lines carry the `_id` MongoDB assigned, so the file can be joined with `_audit_`. Writes are append-only, serialized per tenant and never blocking.
- **Audit — read operations** — `find`, `findOne` and `aggregate` are now logged too, with their **parameters only** (`operation.input`: `{ params, options }` / `{ id, params }` / `{ pipeline }`). `operation.result` is always `null` for reads — the result set is never stored (huge, redundant, privacy risk). A failed read is recorded with `status: "error"` and its error, still without any result.
- **SDK — listening for errors (`api.on`)** — a client is now an emitter: `on(event, listener)`, `once`, `off` (one listener, or all of them) and `listenerCount`. Two events: **`error`** — _every_ failure, whether the server refused it (with its `code` / `status` / `meta`), it never reached the server (`SDK_NETWORK_ERROR`, the original failure on `cause`), or an agent stream failed **after** its headers (an SSE `error` event, which no call site could have caught) — and **`unauthorized`**, the same error when the status is 401, emitted _in addition to_ `error`, so a dead token is handled once (`api.on('unauthorized', () => api.logout())`) instead of matching on a message. The listener receives the **same object** the call throws (a listener is not a replacement for `try`/`catch`), a listener that throws is ignored rather than masking the error it was handed, an unknown event name is refused (`Unknown SDK event 'errr'`) instead of registering a listener that would never fire, and a request **you** aborted reports nothing — cancelling is not a failure. Every request now goes through **one** funnel (`Client#send`), so no surface can escape the events: the namespaced families (`api.collection(…)`, `api.service(…)`, `api.vars`, `api.agent(…)`) report to the client that owns them, `Anteros` and `Rest` alike. **Behaviour change**: a transport failure used to throw the raw `fetch` error — it now throws an `Error` with `code: 'SDK_NETWORK_ERROR'`, the original message and the original error on `cause`.
- **Audit — custom actions** — `rest.runAction()` and the custom-action branch of `POST /api/:tenant_id/collections/:collection/:action` are now audited (they were not at all). The entry carries the custom action name and its `data` (`operation.action: "runAction"`), never the returned payload; a failing action is recorded with its error and still rethrown unchanged. The route now delegates to `rest.runAction()`, so both paths behave identically.
- **Audit — services, internal calls** — `rest.runService()` is now audited too, and **internal vs HTTP** is explicit: every entry carries the top-level `internal` flag (`true` from server-side code, `false` through the HTTP API). The HTTP route delegates to `rest.runService()` so a call is logged exactly once.
- **Audit — streams & watch** — `findStream`, `aggregateStream` and `watch` are now audited with their **parameters only** (`{ params, options }` / `{ pipeline, options }`), `operation.result` always `null`. Stream entries are written when the stream ends (completion, error, or an early `break` in the consumer) — `operation.duration` is therefore the full iteration time.
- **Audit — redaction (sensitive values)** — payloads are redacted **by default** before being stored, in `_audit_` and in the local file: the values of sensitive keys are replaced by `"[redacted]"` in `operation.input`, `operation.result` and `meta`, at any depth and case-insensitively (`password`, `passwd`, `pwd`, `token`, `authorization`, `apikey`, `api_key`, `key`, `secret`, `cookie`, `otp`, `pin`). Customise with `server.audit.redact: […]`, disable with `false`. Applied at the single write choke point (`rest.audit.addActivities`), so entries written by hand are covered too; non-plain values (`Date`, `ObjectId`…) are never altered and a payload with nothing to redact is returned as-is (no allocation). **This closes the login-password leak** — the auth payload was previously stored verbatim.
- **`@anteros/duckdb` — backups on a schedule, a restore you can run, and a server that prepares itself before it serves.** `db.backup()` / `server.backup()` snapshot a database **while it is open**, in one of two formats: **`'file'`** (the default) attaches a fresh target and runs `COPY FROM DATABASE … TO <alias>` — a consistent hot clone, an ordinary `.duckdb` file that opens while the original still answers — or **`'export'`**, which runs `EXPORT DATABASE … (FORMAT PARQUET)` into a directory holding `schema.sql`, `load.sql` and one Parquet file per table, and is the only choice for an in-memory instance. Every snapshot is named `<stem>-YYYYMMDDTHHmmssZ` (`.duckdb` for a clone, `.export` for a directory) so it sorts chronologically, and rotation runs after each successful one: `keep` (default `7`, `0` = keep everything) bounds the snapshots carrying that stem and suffix. `backup()` calls on one instance are **serialized**, so two snapshots never interleave on the connection, and a failed clone detaches its target and deletes the partial file before `DUCKDB_BACKUP_FAILED` is thrown (an export failure is the same code). A backup is the **server's own file**, so an attached instance refuses (`DUCKDB_BACKUP_REMOTE`) and `format: 'file'` needs a `dbPath` (`DUCKDB_BACKUP_REQUIRES_DBPATH`).
  - **`server.backup: { directory, every, keep, onStart, format }` — the snapshot on a timer.** `every` defaults to `'1h'` (a duration string or milliseconds), `onStart` takes one as soon as the server serves, and the schedule is armed **after `onReady`** on an **unref'd** timer: a tick that lands while a snapshot is still in flight is **skipped**, not queued; a failure goes to `onError` (or `console.error`) and the schedule keeps going; `stop()` clears the timer and **awaits** the in-flight snapshot, best-effort and never throwing, and the next `start()` re-arms it. The options are validated at construction (`DUCKDB_BACKUP_INVALID`, before a file or a socket is opened), and `server.backup(overrides?)` merges a partial schedule over the configured one for a manual run.
  - **`antd restore --backup <file|dir> --dbPath <target> [--force]`** — the way back. A `.duckdb` clone is copied next to the target as `<dir>/.<name>.restore` and `rename()`d over it, so a reader never sees half a database; a directory is an `EXPORT DATABASE` folder and is restored with `IMPORT DATABASE '<dir>'`. An existing target without `--force` is refused; with it, it is **moved aside** to `<target>.bak-<YYYYMMDDTHHmmss>` (`-1`, `-2`… when taken) and a stale `<target>.wal` is deleted, so it can never replay onto the restored file. It reopens what it wrote, counts the tables and prints one line — `restored <target> from <backup> — N table(s)`; an engine failure becomes an `error:` line and a non-zero exit.
  - **Startup hooks and index recovery** — `start()` now has fixed points to plug into: `rebuildIndexesOnStart` replays stored indexes, `beforeStart(db)` (+ `beforeStartTimeoutMs`, default `30_000`) runs before any listener opens (migrations, a purge, a checkpoint), `onReady(server)` is **awaited inside** `start()`, and `afterStart(server)` runs **after `start()` resolves**. A throwing `beforeStart` is `DUCKDB_QUACK_BEFORE_START_FAILED`, a deadline is `DUCKDB_QUACK_BEFORE_START_TIMEOUT` (the wait is bounded, the hook is not), a throw in `onReady` fails the start with `DUCKDB_QUACK_READY_FAILED` and releases what was opened, while an `afterStart` failure only reaches `onError` — the server keeps serving. `rebuildIndexesOnStart: RebuildIndexKind[]` (`['hnsw']`, the only kind today) reads `duckdb_indexes()`, keeps the SQL matching `/USING\s+HNSW/i` and replays each as `DROP INDEX IF EXISTS <name>` + its own `CREATE INDEX …`, `LOAD vss` first, best-effort; a failing statement is `DUCKDB_QUACK_REBUILD_FAILED`, and a kind the package does not know — or the former `"hnsw"` / `true` scalar forms — is `DUCKDB_QUACK_REBUILD_INVALID` at construction.
  - **The pool is remote-only, and the constructor validates.** `DuckdbQuackPool` now requires a `url` (`DUCKDB_POOL_REMOTE_REQUIRED`): N local clients would be N independent in-memory databases answering as one. `connections()` (the rows of `quack_active_connections()`), `stop({ drain, timeoutMs })` (polls every 50 ms, bounded, then stops anyway) and `handleSignals(signals?)` (idempotent, returns a disposer) cover the operational side; `port`, `healthPort` (which must differ from `port`) and `beforeStartTimeoutMs` are checked in the constructor (`DUCKDB_QUACK_PORT_INVALID`, `DUCKDB_QUACK_HEALTH_PORT_INVALID`, `DUCKDB_QUACK_OPTION_INVALID`), and `antd` gained `--rebuildIndexes`, `--healthPort` and `--debug`.
- **`@anteros/core` — a tool runtime that says why it failed, and an agent runtime that survives a bad provider, a budget and a guardrail.** Every tool failure now carries a stable **`errorCode`** on its result entry and reaches the model as `Error [CODE]: …`, so a run can branch instead of parsing English: `AGENT_TOOL_UNKNOWN` (a tool outside the run's toolbox), `AGENT_TOOL_ARGS_INVALID` (the schema refused the arguments — the handler never ran), `AGENT_TOOL_TIMEOUT` (`timeoutMs` reached), `AGENT_TOOL_FAILED` (the handler threw without a code) and `AGENT_BUDGET_EXHAUSTED` (a call the run will not pay for), plus whatever code the handler threw. **`description` is required on `define.Tool`** — at the type level and in the loader — because it is the whole prompt the model selects a tool by. The schema conversion is **faithful**: an object is published **closed** (`additionalProperties: false`, unless the Joi schema is `.unknown()`) and a `.default(…)` travels with its field, so the model can omit it instead of inventing a value. `readOnly: true` marks a tool that only reads, and a step whose calls are all read-only runs them concurrently, at most **`maxParallelToolCalls`** (default `8`) in flight, results attached **in the model's order** either way. A tool may return **media** — `{ type: 'image', data, mimeType }` / a document — which Anthropic receives as a real `tool_result` block, which an OpenAI-compatible endpoint receives as a marker (`[image: image/png]`), and which the **stored thread** keeps as a marker, never the base64. **`result.toolStats`** aggregates the run in one object — `{ calls, errors, byCode, timeouts, durationMs }` — also behind `await stream.toolStats`, so a dashboard never walks `toolResults`. A zod schema **types the handler** (`z.output`, no cast), while Joi has no inference and is typed explicitly with `define.Tool<TInput>`.
  - **Sub-agents are bounded by the run that asked for them** — a delegated agent inherits the parent's `signal` and `maxSteps`, so an aborted run aborts its calls and a child cannot outlive the loop, and its **tokens and cost** are folded into the parent's `usage` (a budget sees the whole tree). A sub-agent that **pauses for an approval** is refused with `AGENT_APPROVAL_IN_DELEGATION`: a tool result cannot carry a decision, and dropping the call silently would lose it.
  - **`provider.fallbacks`** — endpoints tried in order when the **provider** is the problem: `429`, `5xx`, a network error or a timeout. A `4xx` never falls back (the request is wrong, the next endpoint would reject it too), `options` are merged over the primary's, `result.model` names the one that answered — and a **streamed** run only falls back while nothing has been emitted, since a restarted stream would duplicate text.
  - **`provider.pricing` → `usage.cost`** — `{ input, output }`, USD per million tokens; the model that answered is the one billed, a fallback may price differently, and a delegated run's cost lands in the parent's usage.
  - **Run budgets** — `maxTokens`, `maxDurationMs` and `maxCost` bound what the calls of a run may cost, not just how many there are (`maxSteps`). The run stops **cleanly**: `finishReason: 'budget'`, `result.budget = { limit, value }`, the answer produced so far is returned, and a tool call the model had already asked for is answered with `Error [AGENT_BUDGET_EXHAUSTED]: …` so the conversation stays valid for the next turn.
  - **Guardrails** — `guardrails.input` runs before the first model call (a blocked prompt costs nothing) and `guardrails.output` before the answer is stored or returned (a blocked answer is never persisted); either side throws `AGENT_GUARDRAIL_BLOCKED` naming the guardrail, and a call's list is **additive** to the declaration's.
  - **`contextTokens`** — the prompt bounded by **tokens** (estimated as 4 characters per token, no tokenizer) where `lastMessages` bounds it by message count: the oldest turns are dropped first and the current question always survives, after the `load` processors.
  - **The HTTP surface carries the new fields** — `generate` and `object` now answer `toolStats`, `model` (the fallback that answered) and `budget` next to the text, the usage and the finish reason, so a client sees the same accounting the in-process call does.

- **`@anteros/core` — an agent runtime that streams its sub-agents, guards what a tool returns, traces and evaluates a run, and resumes a dead one from its last step.** Every addition is opt-in — an agent that declares none of them runs exactly as before — and whatever they account for (`usage`, `toolStats`, `finishReason`) lands in the same `result` the runtime already answered with.
  - **A streaming parent streams its sub-agents** — every chunk of a delegated run is re-emitted on the parent's `fullStream` as `{ type: 'subagent', name, chunk }`, `name` being the child's id; a child that delegates in turn nests another `subagent` chunk at the same level. `textStream` stays the **parent's** text — the child's tokens are never mixed into it — and the child's answer is still what the tool returns to the parent's model, so a consumer that ignores the new chunk sees the same run as before. The child's `usage` **and** `toolStats` are folded into the parent's (`mergeToolStats`), so a delegation reports the same calls, errors, timeouts and cost as a blocking one: a budget and a dashboard see the whole tree. The SSE writer forwards `fullStream` as-is, so the chunk needs no new code on the HTTP surface.
  - **`guardrails.tool` — a tool result is checked before the model reads it** — the check runs **after the tool succeeded**, on the **serialized** string the model is about to read, and a guardrail that throws blocks **that result, not the run**: the entry keeps its `id`, `name` and `args`, loses `result`, and carries `error: "Guardrail '<name>' blocked the tool result: …"` with `errorCode: 'AGENT_GUARDRAIL_BLOCKED'` — the model reads `Error [AGENT_GUARDRAIL_BLOCKED]: …` and goes on, and the blocked entry lands in `toolStats.byCode` like any other failure. A **failed** result is never checked (there is nothing to inspect), the lists are additive like `input` / `output` (declaration first, then the call's), and the same check runs on the resume path of an [approval](/docs/ai/agents#approvals), so an approved result is guarded exactly like a direct one.
  - **`streamObject()` — the object as it is written** — `generateObject()` waits for the whole answer; `streamObject(input, options)` returns everything `stream()` does **plus** `partialObjectStream`, which yields a **best-effort** parse of the answer so far (`undefined` until the partial JSON parses). The parse is tolerant (`lib/partialJson.ts`, `parsePartialJson`): a markdown fence, an open string, object or array, escapes and a dangling `,` or `:` are repaired on the fly, and anything still unparsable returns `undefined` instead of throwing — a partial answer is best-effort by definition, never an error. The final `object` is still parsed and **validated** against the schema: the partial stream is for rendering, `await run.object` is the one to trust. It **drains** the run's text, so a caller picks `partialObjectStream` **or** `textStream`, never both; without a `schema` (or `structuredOutput`) it refuses with `AGENT_SCHEMA_REQUIRED` (500), exactly like `generateObject()`.
  - **`onTrace` — what a run did, as plain events** — declared on the agent or passed per call (the call's hook **replaces** the declared one). Six milestones, each carrying `at: Date.now()`: `run.start` (once, **after** the input guardrails and before the first model call — a blocked prompt traces nothing and costs nothing), `step.start`, `model.end` (duration, the model that answered, its usage, the finish reason), `tool.start`, `tool.end` (duration, and the `errorCode` when the call failed) and `run.end` (finish reason, duration, the folded usage and `toolStats`, the error when there is one). They are **events, not spans** — turning them into durations, parents and attributes is the caller's job, so no tracing dependency enters the framework — and the hook runs **synchronously on the run's own path**: one that throws is swallowed (observability is never a failure mode of the run), one that does I/O slows the run down. `runId` names the run on `run.start`, and is the key of its [checkpoint](/docs/ai/agents#checkpoint-and-resume).
  - **`evaluateAgent()` — the regression test of a prompt** — `evaluateAgent({ agent, cases, graders, passScore?, options? })` runs the cases **sequentially** (a run may write to a thread), each with `options` overlaid by its own, and grades every answer. A grader returns a score or `{ score, reason? }`; scores are clamped to `0..1`, a **case** score is the mean of its graders, the **report** score the mean of the cases, and `passed` counts the cases at or above `passScore` (default `0.5`). A case report keeps its `finishReason`, `usage` and `toolStats`, and a grader that **throws** is a zero with its message in `reasons` — one broken check never ends the evaluation. Exported from `@anteros/core` next to `agents`.
  - **Durable checkpoint — `checkpoint` + `runId`, continued by `resumeRun()`** — `checkpoint` (declared on the agent, or passed per call — the call's store wins) saves an `AgentRunState` (`runId`, `step`, the conversation, `usage`, `toolStats`, `model`, the finish reason) through a three-method `AgentRunStore` (`load` / `save` / `clear`, synchronous allowed). A run saves only when it has **both** a store and a `runId`: the state is written **after each completed step** — the assistant turn and the tool results it asked for, so the stored conversation is always valid to replay — never mid-step and never on an [approval](/docs/ai/agents#approvals) pause, whose conversation ends on an unanswered call. `save` is **best-effort** (a store that throws is logged, the run goes on) and a normal end `clear()`s the state, while a run that throws or is aborted leaves its last state in place. `agent.resumeRun(runId, options?)` continues from `state.step` with the stored conversation: the completed steps are **never replayed through the model** (the first call of the resumed run is the **next** step), `usage`, `toolStats` and `model` start from the state so a budget sees what the whole run already spent, and the same `runId` and store carry on until the run ends. `AGENT_CHECKPOINT_REQUIRED` (400) when `resumeRun()` finds no store, `AGENT_CHECKPOINT_NOT_FOUND` (404) when the store holds nothing for that id. `savePartial` still keeps the **thread**; a checkpoint keeps the **run**.

### Changed

- **⚠️ Breaking — replication now runs on change streams only; `mode`, `schedule`, `lookback` and the date scan are gone.** A date-key scan cannot see a deletion, so the two engines never had the same semantics: a tenant left on `scan` silently kept deleted documents on the destination. There is now one engine and one set of rules.
  - **`ReplicationConfig` loses `mode`, `schedule` and `lookback`** (`ReplicationSchedule` and `ReplicationMode` are removed). `key` (default `updatedAt`) and `batchSize` only drive the **initial backfill**, and `seed()` resolves `'latest'` from `key`; a collection is otherwise tailed, not polled.
  - **No fallback.** On a source that cannot serve change streams (a standalone `mongod`), the tenant is logged (`replication: change streams unavailable — a replica set is required, tenant skipped`) and **not replicated at all** — `replication.now()` refuses the same way rather than leaving a one-shot copy that would never follow another write. A one-node replica set is enough (`mongod --replSet rs0` + `rs.initiate()`); the [Replication](/docs/reference/replication) page states it up front.
  - **The hook + tombstone path is deleted.** `database/deleteLog.ts` (`writeDeleteMarkers`, `replicatesCollection`, `replicatesMetaCollection`) is removed, with its three callers — `vars.del` / `vars.clear`, `agentMemory.clear()` and the file-collection delete in `files.ts`. Their deletes go through the driver, so the oplog carries them; `ReplicationDeleteMarker`, `reset({ tombstones })` and `ReplicationResetResult.tombstones` go with it.
  - **`_replication_` keeps two distinct positions**: `resumeToken` (the stream — the real cursor) and `cursor` (where a cold-start backfill resumes, written by `seed()`). The `mode` field is gone from `ReplicationState`.
  - **`exclude` and the watched collection list are fixed when a watcher starts** — a change at runtime takes effect on the next `stop()` / `start()`.
  - **`replication.start()` opens the streams and `stop()` closes them**, and nothing is scheduled: dropping `Bun.cron` / `setInterval` means the process is held open by the cursors, not by a timer.
  - `reset()` now returns `{ tenant, state }`; `now()` still backfills what was never seeded, and still skips a collection a stream owns.
  - Tests: the six replication suites were converted to stream semantics (deletes awaited on the destination instead of tombstones; the `initialSync` / `seed` documents are inserted **before** the watcher starts), and the `replicatesCollection` suite of `agent-memory.test.ts` was removed with `deleteLog.ts`.

- **The SDK gained `Anteros` — a namespaced client — and `Rest` keeps the flat surface it always had.** Nothing is deprecated and no call site has to move: `new Rest({ server, tenant })` still answers `api.find('users', …)`, `api.upload(…)`, `api.runService(…)`, `api.login(…)`… with the same signatures, while `new Anteros({ server, tenant })` groups the very same calls per family. Both extend one shared, unexported `Client` (the transport: URL, headers, token, error shape) and **both talk to the new family URLs** — the SDK builds the paths, so a client written before this change keeps working against the current server, line for line.

  | Family      | `Rest` (original, unchanged)                                                                       | `Anteros` (namespaced, recommended)                                |
  | ----------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
  | Collections | `api.find('users', params)` / `api.findOne('users', id, params)` / `api.insertOne('users', data)`… | the same on `api.collection('users')`, without the slug            |
  |             | `api.login('users', payload)` / `api.logout('users')`                                              | `api.collection('users').login(payload)` / `.logout()`             |
  |             | `api.runAction('orders', 'refund', data)`                                                          | `api.collection('orders').runAction('refund', data)`               |
  | Services    | `api.runService(service, action, data)`                                                            | `api.service(name).run(action, data)`                              |
  | Files       | `api.upload(slug, file, data)` / `api.getFileUrl(slug, name, t)` / `api.deleteFile(slug, id)`      | `api.files.upload(…)` / `api.files.url(…)` / `api.files.delete(…)` |
  | Shared      | `api.vars.*`, `api.agent(id)`, `api.getConfig()`, `setHeader`/`getToken`…                          | the same members                                                   |

  The naming rule is the same one the URL families follow: **singular = a client bound to one resource** (`api.collection(slug)`, `api.service(name)`, `api.agent(id)`), **plural = the family's operations** (`api.files`, `api.vars`). Why the namespaced client is worth adopting for new code: the row type is given once (`api.collection<User>('users')`), the slug is never repeated across eight calls, and the argument order that used to differ between methods (`find(collection, params)` vs `findOne(collection, id, params)`) can no longer be got wrong. `defaultParams`, `useCache`, `cleanDeep` and the error shape are identical on both. Covered by `packages/sdk/tests/rest.test.ts` (38 tests) — the client surfaces had **no** dedicated tests before, only the agents one.

- **⚠️ Breaking — every HTTP surface now lives under `/api/:tenant_id/<family>/…`.** One namespace, a family segment per surface, instead of one flat route per surface:

  | Before                                            | Now                                                    |
  | ------------------------------------------------- | ------------------------------------------------------ |
  | `POST /api/:tenant_id/:collection/:action`        | `POST /api/:tenant_id/collections/:collection/:action` |
  | `POST /services/:tenant_id/:service/:action`      | `POST /api/:tenant_id/services/:service/:action`       |
  | `POST /vars/:tenant_id/:action`                   | `POST /api/:tenant_id/vars/:action`                    |
  | `POST /upload/:tenant_id/:collection`             | `POST /api/:tenant_id/upload/:collection`              |
  | `GET\|DELETE /files/:tenant_id/:collection/:file` | `GET\|DELETE /api/:tenant_id/files/:collection/:file`  |
  | `POST /agents/:tenant_id/:agent/:action`          | `POST /api/:tenant_id/agents/:agent/:action`           |
  | `GET\|POST /mcp/:tenant_id`                       | `GET\|POST /api/:tenant_id/mcp`                        |

  The generated `_file.url` follows (`/api/:tenant_id/files/:collection/:name`), and so do the SDK (`packages/sdk`), the CLI scaffold (`ant create`) and the docs. **No aliases**: the old paths are not served (a request to one now falls through to a 404). The framework writes every path **once**: `lib/endpoints.ts` holds both the Hono patterns the server registers and the builders a client uses — exported as `endpoints` (`endpoints.collection('v1', 'orders', 'find')`), so a client never hardcodes a route again.
  - Why the shape is safer: a collection may now be called `services`, `vars` or `login` without ever colliding with the family segment (it always sits under `/collections/`), and a tenant's own routes (`routes: { prefix: '/api/v1' }`) are still mounted **first**, so they win as before.
  - Two things surfaced while refactoring: the login rate limiter used Hono's `/api/*/login` (a `*` matches **one** segment, so it had silently stopped matching) — it now uses the exact login pattern; and a tenant route mounted on a reserved family (`/v1/vars/x`) would shadow the framework API, so the route loader **warns at boot** instead of letting it happen silently.

- **Agents — `stream()` takes the options of `generate()`, everywhere.** In-process the two already shared `AgentCallOptions`; the gap was the **wire**: the HTTP body (and therefore the SDK) exposed fewer run options, so a streamed run could not do what a generated one did. The body now also carries `messages` (turns injected into the run — sent _and_ stored) and `lastMessages` (the replayed-history window, clamped to the declaration the way `maxSteps` is), and the SDK forwards them through the **same body builder** for `generate()`, `object()` and `stream()` (`AgentRunOptions`). One more asymmetry closed: the **reasoning** now travels on the result for a streamed run too — `stream.reasoning` in the SDK, and `reasoning?` in the HTTP envelope (`generate`, `object` and the SSE `done` payload), where it used to be reachable only by collecting the `reasoning` chunks.

- **Agents — one message model for every provider.** The input of a run is normalized by a single shared pass (`lib/messages.ts`), so a caller can hand over what they actually have: a `string`, **one message**, a whole conversation, or the **unified content parts** other LLM libraries use. The canonical message keeps the roles `system` / **`developer`** / `user` / `assistant` / `tool`, an optional `name`, and content parts carrying an **image or a document by URL or base64** (`{ type: 'image', url }`, `{ type: 'file', url }`). A `tool-call` part is hoisted onto the assistant turn's `toolCalls`, a `tool-result` part becomes the `tool` turn it means (a turn that is _only_ a tool result leaves no empty `user` message behind). **Nothing is dropped silently**: an unknown role, a part the role cannot carry, a part with no payload, an empty turn or a `file://` address is refused with `INVALID_INPUT` (400) instead of vanishing. Provider mapping: `developer` is sent as such on OpenAI-compatible and folded into the system prompt on Anthropic; `name` is forwarded to OpenAI and dropped on Anthropic; a remote **image** URL is handed to the endpoint (it fetches it), a remote **file** URL is downloaded and inlined (10 MB cap, `AGENT_FILE_TOO_LARGE` / `AGENT_FILE_NOT_FOUND`) so `file: { url }` works where only base64 is accepted. Only the canonical fields survive normalization — a stray key on the way in never reaches the wire. Covered by `tests/messages.test.ts` (22 tests) plus the in-process, HTTP and SDK round-trips.
- **Agents — the HTTP body accepts a single message.** `input` may now be `{ role, content }`, not only a string or an array: the route and the in-process runtime share the same normalizer, so the two cannot drift (`INPUT_REQUIRED` when missing/empty, `INVALID_INPUT` for the content itself). The SDK type follows (`AgentInput` accepts one message).
- **Agents — `thinking` is a declaration default.** `define.Agent({ thinking: 'medium' })` applies to every run, like `toolChoice`; a call overrides it, and `thinking: false` turns the declaration off for one run (a value, not an absence). Exposed by `info` / `toJSON()` next to `toolChoice`.

- **Agents — the run options are named `thread` and `resource`** (the `Id` suffix was redundant). The renamed spellings are the documented ones everywhere: `generate(input, { thread, resource })`, the `memory` shorthand (unchanged — it already used them), the HTTP body (`{ input, thread, resource, maxSteps }`), the access-rule context (`ctx.thread`), the SDK (`api.agent(id).generate(input, { thread, resource })`) and the audit entry (`operation.input.thread`). The previous `threadId` / `resourceId` (flat, inside `memory`, and in the HTTP body) are **still read as deprecated aliases**, so a mix of the two works and nothing breaks. The **memory store contract is untouched** — the three methods keep their positional `threadId` and the context its `resourceId`, because those name identifiers of a stored record, not call options (`AgentThread.threadId` likewise).

- **Agents — `provider.compatible` is now `provider.protocol`.** The field selects the **wire protocol** of the endpoint — `'openai'` (Chat Completions, the default, which every OpenAI-compatible gateway speaks too) or `'anthropic'` (Messages). That is a choice, not a claim about the remote: `compatible` read like a property of the endpoint, and `compatible: 'anthropic'` never made sense as a phrase. `protocol` is canonical everywhere — `AgentProvider` (`AgentProtocol` replaces `AgentCompatible`), `Agent.toJSON()` / `info`, the SDK type and the `AGENT_PROVIDER_INVALID` error. The old **`compatible` is still read as a deprecated alias**: `protocol` wins when both are set, so a call-level override never silently loses to the stale field, and the serializable view never exposes the alias. `resolveProtocol()` is exported next to the deprecated `resolveCompatible()`. Covered by `tests/agent-provider.test.ts` (protocol, alias, precedence, normalization, unknown value).

- **Audit — `request` is redacted too** — the redactor now covers `operation.request` (headers, query string), not just `input`/`result`/`meta`. Keys are matched after normalising `-`/`.` to `_` and stripping the `x-` header prefix, so `X-API-Key` is masked like `api_key` (exact match only — `key` does not redact `monkey`). New default keys: `auth_token`, `access_token`, `refresh_token`, `id_token`, `session_id`. `authorization` and `cookie` remain dropped outright by the request middleware.
- **Audit — mutations are awaited** — the audit entry of a mutation (`insert*`, `update*`, `delete*`, `upload`, `deleteFile`…) is now written **before** the operation returns, so a successful write can no longer lose its trace to a crash/exit. Reads (`find`, `findOne`, `aggregate`, streams, `watch`) stay fire-and-forget and pay no extra round-trip. New `rest.audit.log({ action, collection, input, result?, error?, duration? })` writes a custom entry with the framework envelope.
- **Breaking — audit entries no longer store results.** `operation.result` keeps at most the **generated identifiers** (`{ _id }` on `insertOne`/`updateOne`/`findOneAndUpdate`, `{ count, insertedIds }` on `insertMany`, capped at 100) and, by default, the **operational counters** (`matchedCount`, `modifiedCount`, `deletedCount`, `nIndexesWas`, `{ deleted: true }`…). The data lives in the collection: the audit trail records **who did what, with which parameters, and how it ended** (`status` / `error` / `duration`) — never a document. Opt out of the counters with `server.audit.results: 'none'`, or restore the previous behaviour with `'full'`. Reads, custom actions and services never stored a result and still never do. ⚠️ Two consequences, documented on the [Audit](/docs/reference/audit) page: no **pre-image** (the previous values are not kept — `input.update.$set` holds the new ones), and no content for a `deleteOne` (only the `_id` remains — use a soft delete if you must prove what was deleted).
- **Audit — service entry shape** — a service call is now logged as `operation.action: "runService"` with `operation.collection` = the service name and `operation.input: { action, data }` (it used to log the service action name as `action` and the **response** as `result`). Same shape as `runAction`, and the payload is no longer stored.
- **Breaking — the audit collection is renamed `_audit_`** (was `_activities_`), so the stored data now uses the same vocabulary as the public surface: `rest.audit.*` and the [Audit](/docs/reference/audit) page.
  - **Migration at boot** — right after each tenant's main database is connected, a pre-existing `_activities_` is renamed with `renameCollection` (no copy, no data loss, no downtime). Idempotent and never fatal: a failure is logged and the server still starts.
  - If `_audit_` already exists, the legacy collection is left untouched — never merged nor dropped, audit entries are never silently discarded.
  - `_audit_` remains a valid `$lookup` target from a declared collection, like `_locks_` and `_workflows_`.

### Removed

- **`ruvector` is no longer a dependency of `@anteros/core`.** It was declared (`^0.3.2`) but **never imported** — no code path used it, only the documentation pointed at it as one possible embedder. Installing the framework no longer pulls 17 `@ruvector/*` packages (≈25 MB, several of them native binaries) plus the MCP SDK, a CLI and its formatting stack.
- **Semantic tool selection is gone** — `toolChoice: 'semantic'`, `toolSelection: { topK, embed }` and the built-in scorer (`lib/toolSelector.ts`: BM25 and cosine over vectors) are removed, with the embeddings injection point they required. The framework **never picks a tool**: what a run allows is decided by `tools` and `toolChoice`, and narrowing belongs to the application, which can pass `tools: ['forecast', 'geocode']` (the ids it selected with whatever search it likes) and read back what was sent on `result.steps[0].tools`. The reasoning: a half-search that has to be documented, tuned and explained (`topK`, fail-open, query/passage, embedder choice, vector cache) for a decision the model already makes well with a well-named, well-described tool — and the price of the feature was a whole dependency tree. `toolChoice` keeps `'auto' | 'none' | 'required' | { name }`; `'auto'` remains a real value, so a call can release a tool forced by the declaration.

### Fixed

- **`rest` — a collection definition that disappears mid-call crashed with `col.hooks`.** The adapter re-resolved the collection **after** `@CheckIfCollectionExists()`, inside the method callback; when `cfg.collections` was replaced in between — a reload, or a cache-miss factory running after an `await` — `getCollection()` returned `null`, the `as Collection` cast hid it, and `col.hooks` threw `null is not an object (evaluating 'col.hooks')`, surfaced as an unhandled `INTERNAL_API_ERROR` rejection. Every method now resolves through `requireCollection()`, which throws `COLLECTION_NOT_FOUND` (the same code as the guard), and `find()` resolves the collection **once, before any await**, so a cached query keeps the definition it started with. Covered by `tests/api-external-guards.test.ts` (« fails with COLLECTION_NOT_FOUND instead of a TypeError on `col.hooks` »).

- **`api.privateFields` was bypassed by a join.** The masking ran on the queried collection's rules only, so a document pulled in by `$include` (`find` / `findOne`) or by a `$lookup` in an `aggregate` pipeline — which carries the _included_ collection's fields — was returned whole: `$include: ['author']` handed the client `author.password`. Every collection embedded by the request now has its own `api.privateFields` applied to the joined documents, at the path the join produced (`hasMany` includes, every element included, and nested `$lookup` stages too), and nowhere else — a field of the queried collection that merely shares a name with the included collection's private field is left alone. Masking stays a **response** concern: an internal read (`rest.find` / `rest.aggregate`) still returns every field, so a login handler keeps the hash it compares, and a cached document is never rewritten (masked copies are made along the response path). Covered by `tests/api-private-fields.test.ts` (7 cases: `find`, `findOne`, `hasMany`, `$lookup`, the collection's own fields, no over-masking, cache integrity).

- **Audit — `operation.collectionType` was wrong for document collections** — every declared collection without an explicit `type` was logged as `"file"`. A file collection is now `"file"`, a document collection `"document"` (its optional `type` still wins), and an undeclared/internal collection stays `undefined`.

## How to add an entry

When a new version is released, bump the version in `packages/core/package.json` and add a `## [x.y.z]` section above the previous one, grouping changes under `### Added`, `### Changed`, `### Fixed`, and `### Removed`.
