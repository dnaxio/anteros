The framework ships **eleven built-in tools**. They are **disabled by default**, because they are powerful: three
of them run code with the process's own permissions, and the rest read and write the workspace.

They exist for an agent that is *meant* to act on the machine — a coding agent, an ops agent — not for a bot
that answers questions. A support agent enables none of them.

## Enabling them

```typescript
export default define.Agent({
  id: "coder",
  description: "A coding agent that works in the repository.",
  instructions: "You are a careful coding agent.",
  provider: { /* … */ },

  // `true` enables all eleven; an array picks a subset.
  builtinTools: ["read_file", "write_file", "edit_file", "ls", "grep", "shell"],
  builtinToolsOptions: {
    root: process.cwd(), // the workspace — every path is confined to it
  },
});
```

An unknown name in the array is ignored, so a typo silently narrows the toolbox instead of failing the boot —
`BUILTIN_TOOL_NAMES` is the canonical list if you want to validate a configuration yourself.

### Options — `builtinToolsOptions`

| Option                | Default         | What it does                                                                                     |
| --------------------- | --------------- | ------------------------------------------------------------------------------------------------ |
| `root`                | `process.cwd()` | The **workspace**. Every path a file tool accepts is resolved inside it.                          |
| `maxReadBytes`        | `500_000`       | `read_file` refuses a larger file (`BUILTIN_TOOL_FILE_TOO_LARGE`).                                   |
| `timeoutMs`           | `30_000`        | Default deadline of `shell` / `bun` / `spawn`; the child is killed past it.                        |
| `maxOutputBytes`      | `200_000`       | Captured stdout/stderr, per stream.                                                               |
| `browser.backend`     | `'webkit'`      | `'webkit'` (macOS, no dependency) or `'chrome'` (cross-platform — Chrome must be installed).        |
| `browser.width`       | `1024`          | Viewport width of `browser_control`.                                                              |
| `browser.height`      | `768`           | Viewport height.                                                                                  |

### How they compose with the rest

- A tool the agent **declares itself** under the same id **wins** over a built-in — nothing is overridden
  behind your back.
- `tools: false` removes **every** tool, built-ins included; an allow-list (`tools: ['read_file']`) keeps only
  the listed ones. Both apply to a built-in exactly like to a declared tool.
- `read_file`, `ls`, `grep` and `image` are marked **read-only**: the runtime may run them **concurrently**
  within one step, while a writing tool stays sequential.
- A failing tool is reported to the model as `Error [CODE]: message` — the run continues, like any other tool.

### Typical sets

| Agent                | `builtinTools`                                                     |
| -------------------- | --------------------------------------------------------------- |
| Coding               | `read_file`, `write_file`, `edit_file`, `ls`, `grep`, `shell`    |
| Ops / maintenance    | `ls`, `read_file`, `shell`, `spawn`                              |
| Data / vision        | `read_file`, `image`, `archive_file`                             |
| End-to-end web check | `browser_control`                                                |

## The tools

| Tool              | Read-only | Summary                                                                  |
| ----------------- | --------- | ------------------------------------------------------------------------ |
| `read_file`       | ✅        | Read a UTF-8 file, optionally a range of lines                            |
| `write_file`      |           | Write a file, creating its parent directories                             |
| `edit_file`       |           | Replace an exact string — refuses an absent or ambiguous match            |
| `ls`              | ✅        | List a directory, recursively or with a glob                              |
| `grep`            | ✅        | Search for a regex (or a fixed string) across the workspace               |
| `shell`           |           | Run a shell command and return its exit code and output                   |
| `bun`             |           | Run a Bun/TypeScript snippet                                              |
| `spawn`           |           | Run a program with an argument array — no shell                           |
| `image`           | ✅        | Read an image's size/format, resize or convert it                         |
| `archive_file`    |           | Create, list or extract a tar / tar.gz                                    |
| `browser_control` |           | Drive a real browser: open, evaluate, click, type, screenshot             |

### `read_file`

| Argument | Type   | Default | Meaning                                   |
| -------- | ------ | ------- | ----------------------------------------- |
| `path`   | string | —       | File path, relative to the workspace root (required) |
| `offset` | number | `0`     | First line to return (0-based)             |
| `limit`  | number | `2000`  | Maximum lines (1–5000)                     |

Returns the file's text, or that slice with a trailing `… (N more lines — raise \`offset\`)`. A file larger than
`maxReadBytes` is refused rather than truncated; a file containing a NUL byte is refused as binary.

### `write_file`

| Argument  | Type   | Meaning                                                    |
| --------- | ------ | ---------------------------------------------------------- |
| `path`    | string | Target file, relative to the root (required)                |
| `content` | string | The complete new content — the file is **replaced**, not patched |

Parent directories are created. Returns `Wrote N bytes to <path>`.

### `edit_file`

| Argument      | Type    | Default | Meaning                                                         |
| ------------- | ------- | ------- | --------------------------------------------------------------- |
| `path`        | string  | —       | File to edit (required)                                          |
| `old_string`  | string  | —       | The exact text to replace (required)                             |
| `new_string`  | string  | —       | The replacement (required, may be empty to delete)               |
| `replace_all` | boolean | `false` | Replace every occurrence instead of refusing an ambiguous match  |

- **0 occurrence** → `BUILTIN_TOOL_EDIT_NOT_FOUND`.
- **More than one** and `replace_all` is off → `BUILTIN_TOOL_EDIT_AMBIGUOUS` (the message says how many). Pass a
  longer excerpt or `replace_all: true`.
- Returns `Replaced N occurrence(s) in <path>`.

### `ls`

| Argument    | Type    | Default | Meaning                                              |
| ----------- | ------- | ------- | ---------------------------------------------------- |
| `path`      | string  | `"."`   | Directory to list (a file is `BUILTIN_TOOL_NOT_A_DIRECTORY`) |
| `recursive` | boolean | `false` | Walk the whole subtree                               |
| `glob`      | string  | —       | Filter, e.g. `src/**/*.ts` (implies a recursive scan) |

Returns sorted entries, one per line, directories suffixed with `/`; `(empty)` when there is nothing. The walk
skips `node_modules`, `.git`, `dist`, `.output`, `.nuxt`, `.cache` and `coverage`, and stops at **500 entries**
with a trailing note.

### `grep`

| Argument      | Type    | Default | Meaning                                                     |
| ------------- | ------- | ------- | ----------------------------------------------------------- |
| `pattern`     | string  | —       | Regular expression, or a literal string when `fixed` (required) |
| `path`        | string  | `"."`   | Directory to search                                         |
| `glob`        | string  | `**/*`  | Files to scan                                               |
| `ignore_case` | boolean | `false` | Case-insensitive                                            |
| `fixed`       | boolean | `false` | Treat `pattern` as a literal string                          |
| `max_results` | number  | `200`   | Stop after this many matches (1–2000)                        |

Returns `file:line: text` per match, `No match` when there is none, and a trailing note when it stopped at the
cap. Files over **1 MB**, binary files, and the same ignored directories as `ls` are skipped. An invalid regex is
`BUILTIN_TOOL_INVALID_PATTERN`.

### `shell`

| Argument     | Type   | Default        | Meaning                                              |
| ------------ | ------ | -------------- | ---------------------------------------------------- |
| `command`    | string | —              | The command line (required)                          |
| `timeout_ms` | number | `options.timeoutMs` | Kill it after this many milliseconds (100–600 000) |

Runs `/bin/sh -c <command>` (on Windows `cmd.exe /d /s /c`), with `cwd` = the workspace root. The result is:

```
exit code: 0
--- stdout ---
…
--- stderr ---
…
```

`timed out (killed)` replaces the exit line when the deadline expired. Output is capped at `maxOutputBytes`
per stream.

### `bun`

| Argument     | Type   | Meaning                                              |
| ------------ | ------ | ---------------------------------------------------- |
| `code`       | string | The program source, run with `bun -e` (required)     |
| `timeout_ms` | number | Same deadline as `shell`                             |

Same result shape as `shell`.

### `spawn`

| Argument     | Type                    | Default | Meaning                                              |
| ------------ | ----------------------- | ------- | ---------------------------------------------------- |
| `command`    | string                  | —       | The program (required) — resolved through `PATH`     |
| `args`       | string[]                | `[]`    | Arguments, passed **verbatim** — no shell, nothing interpreted |
| `cwd`        | string                  | root    | Working directory, confined to the workspace          |
| `stdin`      | string                  | —       | Text written to the child's stdin                     |
| `env`        | Record<string, string>  | —       | Extra environment variables, merged over `process.env` |
| `timeout_ms` | number                  | `options.timeoutMs` | Same deadline as `shell`                   |

`spawn({ command: "/bin/echo", args: ["$(whoami)"] })` prints `$(whoami)` — it is an argument, not an
instruction. Use it when a shell would be a liability; use `shell` when you need pipes, redirections or globs.

### `image`

| Argument  | Type   | Default | Meaning                                                        |
| --------- | ------ | ------- | -------------------------------------------------------------- |
| `path`    | string | —       | Source image, relative to the root (required)                   |
| `width`   | number | —       | Target width (1–16384) — `height` omitted keeps the ratio       |
| `height`  | number | —       | Target height                                                  |
| `format`  | string | source  | `png`, `jpeg` or `webp`                                        |
| `quality` | number | `80`    | JPEG/WebP quality (1–100)                                       |
| `output`  | string | —       | Write the result here; omit to return it to the model           |

With no `width`, `height`, `format` or `output`, it only reports `png 1024x768` (format and size). Otherwise it
resizes with `fit: "inside"` and **never enlarges**, then either writes the file (`Wrote N bytes to <path>`) or
returns an **image content block** the model can look at. Powered by `Bun.Image` — no `sharp`, no native install.

### `archive_file`

| Argument      | Type     | Default | Meaning                                                          |
| ------------- | -------- | ------- | ----------------------------------------------------------------- |
| `action`      | string   | —       | `create`, `list` or `extract` (required)                          |
| `path`        | string   | —       | The archive, relative to the root (required)                      |
| `files`       | string[] | —       | `create`: files to add, relative to the root or to `base`          |
| `glob`        | string   | —       | `create`: add by pattern; `list` / `extract`: filter the entries   |
| `base`        | string   | `"."`   | `create`: directory the archive names are relative to              |
| `destination` | string   | `"."`   | `extract`: target directory                                       |
| `compress`    | string   | —       | `"gzip"` to produce a `.tar.gz`                                    |

- **`create`** needs `files` or `glob`, or fails with `BUILTIN_TOOL_ARCHIVE_EMPTY`. Names inside the archive are
  relative to `base`; at most 2000 entries.
- **`list`** returns `name (N bytes)` per entry.
- **`extract`** refuses any entry that is absolute or contains `..` (`BUILTIN_TOOL_ARCHIVE_UNSAFE` — zip-slip),
  then extracts; it returns `Extracted N entries to <path>`.

`Bun.Archive` reads and writes **tar** (optionally gzip) — **not zip**. An unreadable archive is
`BUILTIN_TOOL_ARCHIVE_INVALID`.

### `browser_control`

Drives a real browser through `Bun.WebView` (experimental in Bun 1.4.4). One view per process, reused by every
call; `close` releases it.

| `action`    | Extra arguments                          | What it does                                                        |
| ----------- | ---------------------------------------- | ------------------------------------------------------------------- |
| `open`      | `url`                                    | Navigate and wait for load; returns the final URL and the title      |
| `evaluate`  | `script`                                 | Run an **expression** in the page (awaited page-side), returns its JSON value (capped at `maxOutputBytes`) |
| `screenshot`| `format?` (`png`/`jpeg`/`webp`), `path?`  | Returns an image block, or writes it to `path`                       |
| `click`     | `selector`, or `x` and `y`                | Clicks an element (waits until actionable) or a viewport point        |
| `type`      | `text`                                    | Types into the focused element                                       |
| `press`     | `key` (`Enter`, `Tab`, `ArrowDown`, …)    | Presses a key                                                        |
| `scroll`    | `dx`, `dy`                                | Scrolls the viewport                                                 |
| `reload` / `back` / `forward` | —                        | Navigates; returns the resulting URL                                 |
| `close`     | —                                         | Closes the view                                                     |

- `backend: "webkit"` (default) uses the system WebKit on **macOS**; `backend: "chrome"` works anywhere Chrome
  is installed (headless).
- `evaluate` takes an **expression**; wrap a statement sequence in an IIFE:
  `(() => { const x = 1; return x + 1 })()`.
- A runtime without `Bun.WebView` fails with `BUILTIN_TOOL_BROWSER_UNAVAILABLE`; a missing argument with
  `BUILTIN_TOOL_BROWSER_URL_REQUIRED` (and the equivalents for `script`, `text`, `key`, a click target).

## Safety

::prose-callout{variant="warning" title="Code execution is not sandboxed"}

`shell`, `bun` and `spawn` run **with the process's own permissions** — the workspace root is only their `cwd`,
not a sandbox. A command can read anything the process can read and write anything it can write. Enable these
three only for an agent whose whole purpose is to act on the machine, and run that process with the least
privilege you can (a container, a dedicated user).

::

### Workspace confinement

The file tools — `read_file`, `write_file`, `edit_file`, `ls`, `grep`, `image`, `archive_file` — and `spawn`'s
`cwd` are **confined to `builtinToolsOptions.root`**. A refused path is `BUILTIN_TOOL_PATH_ESCAPE`, and the check
covers three ways out:

1. a relative `..` climb;
2. an absolute path outside the root;
3. a **symlink** inside the root that resolves outside it — the real path is checked for an existing target,
   and for the closest existing parent when the file is about to be created.

A missing `path` is `BUILTIN_TOOL_PATH_REQUIRED`. The root itself defaults to `process.cwd()`, so a server started
from its project directory is confined to that project.

### Limits at a glance

| Limit                        | Value                                       |
| ---------------------------- | ------------------------------------------- |
| `read_file` size             | `maxReadBytes` (500 000 bytes)              |
| `read_file` lines            | `limit` (2000, max 5000)                    |
| `grep` file size             | 1 MB — larger files are skipped             |
| `grep` matches               | `max_results` (200, max 2000)               |
| `ls` entries                 | 500                                         |
| Workspace walk               | 20 000 files, ignored dirs excluded         |
| `archive_file` entries       | 2000                                        |
| Process deadline             | `timeoutMs` (30 s), `timeout_ms` per call   |
| Captured output              | `maxOutputBytes` (200 000 per stream)       |

## Errors

A tool error reaches the model as `Error [CODE]: message`; it never fails the run.

| Code                                                                          | When                                                              |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `BUILTIN_TOOL_PATH_ESCAPE`                                                        | `..`, an absolute path outside the root, or a symlink leaving it   |
| `BUILTIN_TOOL_PATH_REQUIRED`                                                      | A required `path` (or `cwd`, `output`, `destination`) is missing   |
| `BUILTIN_TOOL_NOT_FOUND` · `NOT_A_FILE` · `NOT_A_DIRECTORY`                        | Missing path, or the wrong kind                                    |
| `BUILTIN_TOOL_FILE_TOO_LARGE` · `BINARY_FILE`                                      | `read_file` limits                                                 |
| `BUILTIN_TOOL_EDIT_NOT_FOUND` · `EDIT_AMBIGUOUS`                                   | `edit_file`: nothing matched, or more than one                      |
| `BUILTIN_TOOL_INVALID_PATTERN`                                                     | `grep`: the regex does not compile                                 |
| `BUILTIN_TOOL_SPAWN_FAILED`                                                        | `shell` / `bun` / `spawn`: the program cannot start                |
| `BUILTIN_TOOL_BROWSER_UNAVAILABLE` · `IMAGE_UNAVAILABLE` · `ARCHIVE_UNAVAILABLE`   | The Bun capability is missing in this runtime                      |
| `BUILTIN_TOOL_BROWSER_URL_REQUIRED` · `SCRIPT_REQUIRED` · `TARGET_REQUIRED` · `TEXT_REQUIRED` · `KEY_REQUIRED` | `browser_control`: an argument for that action is missing |
| `BUILTIN_TOOL_ARCHIVE_EMPTY` · `ARCHIVE_INVALID` · `ARCHIVE_UNSAFE`                | `archive_file`: nothing to add, unreadable archive, unsafe entry    |

## Examples

The model picks the tool and the arguments; these are the calls it makes.

```typescript
// builtinTools: ['grep', 'read_file', 'edit_file', 'shell']
await agent.generate("Find the TODOs in src/api.ts, fix the null return, and run its tests");
//  1. grep      { pattern: "TODO", glob: "src/api.ts" }
//  2. read_file { path: "src/api.ts", offset: 40, limit: 60 }
//  3. edit_file { path: "src/api.ts", old_string: "return null", new_string: "return []" }
//  4. shell     { command: "bun test src/api" }
```

```typescript
// builtinTools: ['image'] — the result goes back to the model as an image
await agent.generate("Resize ./avatars/alice.png to 128px wide and save it as alice-128.webp");
//  image { path: "avatars/alice.png", width: 128, format: "webp", output: "avatars/alice-128.webp" }
```

```typescript
// builtinTools: ['browser_control'] — the screenshot arrives as an image content block
await agent.generate("Open https://example.com, screenshot it, and summarise the title");
//  browser_control { action: "open", url: "https://example.com" }
//  browser_control { action: "screenshot" }
```

```typescript
// builtinTools: ['archive_file']
await agent.generate("Bundle dist/ into release.tar.gz");
//  archive_file { action: "create", path: "release.tar.gz", glob: "dist/**", compress: "gzip" }
```

A screenshot (`browser_control`) and an image without `output` come back as an **image content block**, so the
model can look at them — not as a path it would have to open.

## Using them outside an agent

The same tools are ordinary `AgentTool`s, usable in a service, a script or a workflow step:

```typescript
import { builtinToolsFor } from "@anteros/core";

const tools = builtinToolsFor(["read_file", "grep"], { root: process.cwd() });
const read_file = tools.find((tool) => tool.id === "read_file")!;

const text = await read_file.execute!({ path: "package.json" }, {} as any);

// …or hand one to a run, beside the agent's own tools
await agent.generate("Read package.json", { tools: { read_file } });

console.log(builtinToolsFor(true).map((tool) => tool.id)); // all eleven
```

`BUILTIN_TOOL_NAMES` lists the eleven ids, so a UI can offer a checklist without hardcoding the names.

## Requirements

- **Bun 1.4.4+** — `Bun.WebView`, `Bun.Image` and `Bun.Archive` are the primitives behind `browser_control`,
  `image` and `archive_file`; a runtime without one fails with `*_UNAVAILABLE` rather than a cryptic error.
- **A browser** for `browser_control`: the system WebKit (macOS, zero dependency) or Chrome
  (`backend: "chrome"`, cross-platform).
- **tar / tar.gz** for `archive_file` — zip is not supported by `Bun.Archive`; use `shell` for a `.zip`.
