`anteros` is the developer-facing CLI: creating a project, running it locally, and checking your environment.

## Commands

| Command          | What it does                                               |
| ---------------- | ---------------------------------------------------------- |
| `anteros create` | Scaffold a new Anteros project                             |
| `anteros dev`    | Run the local dev server with Bun's watcher                |
| `anteros doctor` | Diagnose Bun, the project files, MongoDB and the HTTP port |

Run `anteros <command> --help` for the options of a single command.

## create

```bash
bunx @anteros/cli create server my-api
anteros create server my-api
anteros create my-api            # default template
```

Templates:

| Template | Contents                                                                              |
| -------- | ------------------------------------------------------------------------------------- |
| `server` | Bun + MongoDB server: a tenant, an example collection, a custom route and an MCP tool |

Options:

| Option                      | Description                                         |
| --------------------------- | --------------------------------------------------- |
| `-d, --dir <path>`          | Target directory (default: `./<name>`)              |
| `-t, --tenant <id>`         | Tenant id and folder (default: `v1`)                |
| `-p, --port <port>`         | HTTP port (default: `4000`)                         |
| `--mongo <uri>`             | MongoDB connection string                           |
| `--pm <pm>`                 | `bun` \| `npm` \| `pnpm` \| `yarn` (default: `bun`) |
| `--install`, `--no-install` | Install dependencies (default: ask)                 |
| `--git`, `--no-git`         | Initialize a git repository (default: ask)          |
| `-f, --force`               | Write into a non-empty directory                    |
| `-y, --yes`                 | Accept the default answer to every prompt           |

The generated project follows the [recommended layout](/docs/getting-started/project-structure):

```
my-api/
├── config/app.ts     # define.Server({ server, tenants })
├── index.ts          # app.boot(config)
├── v1/               # tenant root (tenant.dir)
│   ├── collections/  # items.model.ts
│   ├── mcp/tools/    # items-summary.tool.ts
│   └── routes/       # health.route.ts
├── .env.example
└── package.json
```

Then:

```bash
cd my-api
bun install
cp .env.example .env
bun run dev
```

## dev

Runs the project entrypoint with Bun — restarting on every file change.

```bash
anteros dev                   # bun --watch index.ts
anteros dev src/main.ts       # custom entrypoint
anteros dev --no-watch        # run once, without the watcher
```

## doctor

Diagnoses the local environment before you start chasing an error:

- the Bun version (≥ 1.3.0) and whether the project files are present (`package.json`, `index.ts`, `config/app.ts`)
- whether `@anteros/core` is declared and installed
- whether the MongoDB connection string (from `.env`, the environment, or `config/app.ts`) is reachable
- whether the configured HTTP port is free
- whether the project directory is writable (the server writes `.logs/` and `storage/`)

It exits with code `1` when an error is reported, so it can gate a CI job.
