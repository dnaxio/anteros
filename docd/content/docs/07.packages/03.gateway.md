## What it is

A **passive L7 reverse proxy** for Anteros microservices. Each deployment keeps its own
`/api/:tenant_id/…` surface; the gateway picks the upstream from the first path segment and
forwards the request unchanged.

```text
Client → Caddy (TLS) → @anteros/gateway → pharmacie / facturation / stats / auth
```

::prose-callout{variant="warning" title="Not an API gateway"}
It does **no** authentication, authorization, rate limiting, transformation, aggregation or
path rewriting. TLS, WAF and WebSocket stay at Caddy/Traefik. The gateway is not a trust
boundary — backends stay on a private network and enforce access themselves.
::

```bash
bun add @anteros/gateway
```

## Configuration

```typescript
import { defineGateway } from "@anteros/gateway";

export default defineGateway({
  port: 8080,
  microservices: [
    { name: "auth", upstream: "http://auth:4000" },
    { name: "pharmacie", upstream: "http://pharmacie:4000" },
    { name: "facturation", upstream: "http://facturation:4000" },
    { name: "stats", upstream: "http://stats:4000" },
  ],
  timeoutMs: 30_000,
  cors: {
    origins: ["https://app.example.com"],
    methods: ["GET", "POST", "PUT", "PATCH", "DELETE"],
    headers: ["authorization", "content-type"],
    exposeHeaders: ["x-request-id"],
    credentials: false,
    maxAge: 600,
  },
  logging: {
    enabled: true,
    microservices: ["pharmacie", "facturation"], // "*" for every microservice
    name: "gateway",
    fields: { env: "prod", instance: "gw-1", version: "0.0.1" },
  },
});
```

`name` is both the first URL segment and the Anteros **tenant id** the backend expects,
because the path is not rewritten: `name: "pharmacie"` receives `/api/pharmacie/…`.

## Routing

| Request | Result |
| --- | --- |
| `POST /api/pharmacie/collections/ordonnances/insertOne` | same path on `http://pharmacie:4000` |
| `GET /api/stats/collections/ventes/find` | same path on `http://stats:4000` |
| `/health` | local `{ "status": "ok", "microservices": [...] }` |
| anything else | `404 { "code": "MICROSERVICE_NOT_FOUND" }`, no upstream call |

There is no wildcard, no regex and no client-supplied upstream.

## What the proxy does

- Forwards method, path, query, body, `authorization`, cookies and application headers.
- Removes hop-by-hop headers in both directions and `host`.
- Adds `x-forwarded-for`, `x-forwarded-proto`, `x-forwarded-host` and `x-request-id`.
- Streams request and response bodies; SSE is untouched.
- Keeps compressed upstream bodies compressed (`fetch` runs with `decompress: false`).
- `timeoutMs` covers connection and upstream **response headers**, never the body.
- `502` when the upstream is unreachable, `504` when its headers are late; no retries.
- Logs one JSON line per request (method, microservice, upstream, status, duration, request
  id) — never the token, the cookie or the body.

## Request logs

The scope is configurable — every microservice, one, or a list. Each line starts with the
**timestamp** (ISO 8601 UTC, when the request was received); add `durationMs` to get the end.

```typescript
logging: {
  enabled: true,                                  // default true; false logs nothing
  microservices: ["pharmacie", "facturation"],    // default "*" (every microservice)
}
```

- `"*"` logs every routed request.
- An array restricts the logs to those names; the other microservices keep working, they
  are simply not logged.
- A 404 has no microservice: it is logged only when the scope is `"*"`.
- `logger` replaces the default JSON-on-stdout sink; an unknown name in the scope is a
  startup error.

```json
{"timestamp":"2026-11-08T12:34:56.789Z","level":"info","logger":"gateway","requestId":"6f1c…","method":"POST","path":"/api/pharmacie/collections/x/find","microservice":"pharmacie","upstream":"http://pharmacie:4000","status":200,"durationMs":12,"env":"prod","instance":"gw-1"}
```

- `level` is `error` for a 5xx response and `info` otherwise.
- `logger` is `logging.name` (default `gateway`).
- `logging.fields` are copied onto every line; they cannot shadow a gateway field.

### Capturing request bodies

Off by default. `captureBody: true` uses the safe defaults; an object tunes them.

```typescript
logging: {
  captureBody: {
    maxBytes: 4096,                       // only bodies with Content-Length ≤ this
    methods: ["POST", "PUT", "PATCH", "DELETE"],
    contentTypes: ["application/json", "application/x-www-form-urlencoded", "text/"],
    redact: ["password", "token", "secret", "authorization"], // extended default list
  },
}
```

::prose-callout{variant="warning" title="Bodies are sensitive"}
A request body may contain passwords, tokens or personal data. Enable capture deliberately, keep
`redact`, bound `maxBytes`, and keep the retention short (`ttl` on DuckDB).
::

- The body is logged as `requestBody`: a parsed JSON object, a form object, or a string.
- Sensitive keys are redacted at any depth (`[redacted]`); `redact: []` disables redaction.
- Only bodies with a `Content-Length` at or below `maxBytes` and a textual content type are
  captured. Chunked, multipart and binary bodies are skipped.
- The copy is read from `request.clone()`: what the upstream receives is unchanged.
- In DuckDB the body lives in `raw`; query `raw::JSON->>'requestBody'`.

### Where the logs are stored

`logging.engine` chooses the sink. The short names are the defaults, under `.logs/` (git-ignored);
use a long name such as `gateway.jsonl` if you prefer the format in the extension.

| `engine` | Destination | Default path |
| --- | --- | --- |
| `stdout` (default) | one JSON object per line on stdout | — |
| `file` | JSONL, one object per line | `.logs/gateway.log` |
| `duckdb` | a DuckDB database, table `logs` | `.logs/gateway.duckdb` |

```typescript
logging: { engine: "file" }                     // .logs/gateway.log
logging: { engine: "file", file: "gateway.jsonl" }
logging: { engine: "duckdb" }                   // .logs/gateway.duckdb
logging: { engine: "duckdb", file: "/var/log/gateway.duckdb" }
```

`logging.file` is relative to the process working directory unless absolute.

- **stdout** — storage and retention belong to the runtime: Docker `json-file`,
  systemd/journald, Kubernetes, or a collector (Vector, Fluent Bit, Promtail → Loki/Elastic).
- **file** — JSONL, with configurable rotation:

  ```typescript
  logging: {
    engine: "file",
    rotate: "size",        // size | hourly | daily | weekly | monthly | yearly
    maxSize: "10m",        // size mode only; default 10 MB ("500k", "1g", bytes)
    maxFiles: 5,           // archives kept; default 5
    compress: true,        // gzip each archive; default false
  }
  ```

  Archives for a live `gateway.log`: `gateway-2026-11-09-1.log` (size),
  `gateway-2026-11-09-14.log` (hourly), `gateway-2026-11-09.log` (daily),
  `gateway-2026-W45.log` (weekly), `gateway-2026-11.log` (monthly), `gateway-2026.log` (yearly);
  `.gz` is appended when `compress` is on. Calendar archives are pruned by name, size archives by
  mtime; the live file is never deleted. `rotate` requires the `file` engine, and `maxSize` only
  applies to `rotate: "size"`.
- **duckdb** — table `logs` with `timestamp`, `level`, `logger`, `request_id`, `method`, `path`,
  `microservice`, `upstream`, `status`, `duration_ms`, `fields` (JSON text of the custom fields)
  and `raw` (the whole entry). Opens asynchronously: `await gateway.ready` before traffic (the
  CLI does). Rows are flushed every 100 entries and on `stop()`.

```sql
SELECT timestamp, level, microservice, status, duration_ms, path
FROM logs ORDER BY timestamp DESC LIMIT 50;

SELECT raw::JSON->>'requestId' AS request_id FROM logs WHERE level = 'error';
```

**Retention (TTL)** — delete rows older than a duration, with a periodic purge:

```typescript
logging: {
  engine: "duckdb",
  ttl: "7d",           // 500ms, 30m, 24h, 7d, 2w
  purgeEvery: "1h",    // default 1h
  purgeOnStart: true,  // default true
}
```

The purge runs `DELETE FROM logs WHERE CAST(timestamp AS TIMESTAMP) < cutoff`, flushes the
appender first, and its timer is `unref()`ed. Without `ttl`, nothing is purged and the database
grows. `ttl` is only valid with the `duckdb` engine; `purgeEvery` / `purgeOnStart` require `ttl`.
Deleted rows free space for reuse, but DuckDB does not necessarily shrink the file on disk.

`stop()` is async and flushes the sink:

```typescript
await gateway.stop();
```

A custom `logger` is still available on the `stdout` engine; it cannot be combined with `file` or
`duckdb`. A sink that throws is reported on stderr and never fails a request.

## CORS

CORS is **opt-in**: omit `cors` (or set it to `false`) and the upstream headers pass through
untouched. When you set it, the gateway owns the policy:

```typescript
cors: {
  origins: ["https://app.example.com"],   // or "*" (not with credentials)
  methods: ["GET", "POST", "PUT", "PATCH", "DELETE"],
  headers: ["authorization", "content-type"], // omitted → echo Access-Control-Request-Headers
  exposeHeaders: ["x-request-id"],
  credentials: false,
  maxAge: 600,
}
```

- A browser preflight (`OPTIONS` + `Origin` + `Access-Control-Request-Method`) is answered
  **locally**, with no upstream call.
- Actual responses get the policy, and the upstream `access-control-*` headers are **removed**
  — two `Access-Control-Allow-Origin` values make browsers reject the response.
- A disallowed origin gets no CORS headers (the browser blocks); the request is still proxied.
- `credentials: true` is refused with `origins: "*"`.
- Once the gateway owns CORS, disable CORS in the backends to keep one authority.

The policy is also **per microservice**: `microservice.cors` overrides the global `cors`, and
`cors: false` opts a service out (pass-through), even when the global policy is enabled.

```typescript
cors: { origins: ["https://app.example.com"] }, // default for services without an override

microservices: [
  { name: "pharmacie", upstream: "http://pharmacie:4000", cors: { origins: ["https://pharmacie.example.com"] } },
  { name: "facturation", upstream: "http://facturation:4000" }, // inherits the global policy
  { name: "stats", upstream: "http://stats:4000", cors: false }, // pass-through, upstream owns CORS
],
```

Precedence: `microservice.cors` (object or `false`) → global `cors` → pass-through. A 404 has no
microservice and uses the global policy.

## Token contract

With one login across several Anteros deployments, the auth backend signs a **platform
token** with the shared `JWT_SECRET`. It carries **no** `tenant` claim and lists roles per
tenant:

```json
{
  "sub": "usr_123",
  "roles": { "pharmacie": ["admin"], "facturation": ["reader"], "stats": ["reader"] },
  "iss": "auth",
  "aud": "anteros-platform",
  "exp": 1730000900
}
```

Each backend verifies the signature (Hono does it) and enforces the roles in `api.access`:

```typescript
api: {
  access: {
    "*": ({ token, rest }) => {
      const roles = (token.decoded?.roles as Record<string, string[]> | undefined)?.[rest.tenant_id] ?? [];
      return roles.includes("admin") || roles.includes("reader");
    },
  },
}
```

No rules means denied. `access: { "*": true }` allows requests **without a token** — never
use it on a protected collection. The auth backend, its users and the role provisioning are
your application, not this package.

## Limits

- No WebSocket proxying: `/socket.io/` carries no microservice. For realtime, expose a Caddy
  host that routes only `/socket.io/*` to the backend and 404s everything else.
- No retries, circuit breaker, service discovery, cache or aggregation (v1).
- No TLS termination.
