## What it is

A **separate, opt-in package**. `@anteros/reco` turns an image into faces and each face into a
**512-dimension embedding**, locally: two ONNX models, no API key, no image ever leaving the machine.

| Model            | Role                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| `det_10g.onnx`   | RetinaFace detector — boxes, confidence, five landmarks               |
| `w600k_r50.onnx` | ArcFace recognizer — a 512-d unit vector per aligned face             |

```bash
bun add @anteros/reco
```

::prose-callout{variant="warning" title="The weights are not free for commercial use"}
The InsightFace **code** is MIT, but every pretrained pack — `buffalo_l` included — is released for
**non-commercial research purposes only**. A commercial deployment needs a license from InsightFace.
Check the [model zoo notice](https://github.com/deepinsight/insightface/blob/master/model_zoo/README.md)
before shipping.
::

## Download the models

`createEngine()` downloads the pack **by itself** when `det_10g.onnx` and `w600k_r50.onnx` are missing
from the model directory — once per directory, ~280 MB, then the files stay on disk:

```typescript
const engine = await createEngine(); // downloads ./models/buffalo_l if needed
```

- `autoDownload: false` turns it off; a missing file then fails with `RECO_MODEL_NOT_FOUND`.
- `modelUrl` points at another archive, `downloadTimeoutMs` (default 10 minutes) aborts the transfer.
- Only the default file names are fetched: with a custom `detModel` / `recModel`, nothing is downloaded.
- Extraction uses `unzip`, or `tar` when `unzip` is absent (`bsdtar` reads zip on macOS and Windows).
- Two concurrent `createEngine()` calls for the same directory share a single download.

From a checkout of this repository, the same download is available as a script (progress on stderr):

```bash
bun run packages/reco/scripts/download-models.ts   # writes ./models/buffalo_l
RECO_MODEL_DIR=./models/buffalo_l bun run packages/reco/scripts/download-models.ts
```

The same step is exported for a custom bootstrap: `downloadModels({ modelDir, onProgress })` always
fetches, `ensureModels({ modelDir })` only when the two files are missing, and `modelsPresent(modelDir)`
answers the question.

Or by hand, as InsightFace documents it:

```bash
curl -L -O https://github.com/deepinsight/insightface/releases/download/v0.7/buffalo_l.zip
unzip buffalo_l.zip -d models/buffalo_l
```

The pack is ~340 MB on disk (five models); this package only loads the two above. Point
`createEngine({ modelDir })` at the directory, or set `RECO_MODEL_DIR`. A missing file after the attempt is
`RECO_MODEL_NOT_FOUND`, a failed transfer `RECO_MODEL_DOWNLOAD_FAILED`, a failed extraction
`RECO_MODEL_EXTRACT_FAILED`. Nothing is fetched at import time.

## Quick start

```typescript
import { cosineSimilarity, createEngine } from "@anteros/reco";

const engine = await createEngine({ modelDir: "./models/buffalo_l" });

// Every face, best score first — box, landmarks and a unit embedding.
const faces = await engine.recognize("./team.jpg");
for (const face of faces) {
  console.log(face.score.toFixed(3), face.box, face.embedding.length); // 512
}

// 1:1 — the best face of each image.
const score = await engine.compare("./alice-1.jpg", "./alice-2.jpg");
console.log(score); // 1 = same face, around 0 = unrelated

// 1:N — your own index, no dependency.
const best = faces
  .map((face, index) => ({ index, score: cosineSimilarity(face.embedding, storedEmbedding) }))
  .sort((left, right) => right.score - left.score)[0];

await engine.close();
```

An engine owns both ONNX sessions: **create it once** and reuse it. `close()` is idempotent, and every
method refuses to run afterwards with `RECO_ENGINE_CLOSED`.

## Detecting and embedding separately

`detect()` runs the detector only; `embed()` runs the recognizer for one face — the detection you pass,
or the best face of the image. This is what a UI needs: show the boxes, then embed the one the user picks.

```typescript
import { loadImage } from "@anteros/reco";

const image = await loadImage("./group.jpg"); // decode once, EXIF applied
const faces = await engine.detect(image, { threshold: 0.6, maxFaces: 5 });
const embedding = await engine.embed(image, faces[0]);
```

`loadImage()` returns `{ data, width, height }` in 8-bit RGB, and every method accepts that object, a
path, encoded bytes, a `Blob` (`Bun.file()` included), a base64 string or a `data:` URL — so a decoded
image is never decoded twice.

If you already hold an **aligned square crop** (a stored 112x112 face, an enrolment photo), skip the
detector: `embedAligned(crop)` feeds it straight to the recognizer. A non-square crop is refused rather
than silently stretched.

## Descriptors

`getDescriptors()` is the shortest path from an image to embeddings: it detects every face and returns
the 512-dimension unit vectors, best score first. `getDescriptor()` returns only the best one, or `null`.

```typescript
const descriptors = await engine.getDescriptors("./team.jpg");
for (const descriptor of descriptors) console.log(descriptor.length); // 512

const best = await engine.getDescriptor("./alice.jpg");
if (best) await users.insertOne({ user: "alice", descriptor: Array.from(best) });
```

### Base64 and data URLs

The same inputs work everywhere — `detect`, `recognize`, `getDescriptors`, `getDescriptor`, `embed`,
`embedAligned` and `compare`:

```typescript
// An explicit object — no ambiguity with a file path.
const fromPayload = await engine.getDescriptor({ base64: payload, mimeType: "image/jpeg" });

// A data URL, as a browser sends it.
const fromDataUrl = await engine.getDescriptors(`data:image/jpeg;base64,${payload}`);

// A bare base64 string is recognised too (long, multiple of 4, no dot or backslash).
const fromBare = await engine.getDescriptors(payload);
```

A string is a **path** when that file exists; otherwise a long base64-only string is decoded as base64.
When it could be either, pass `{ base64 }` and the question disappears.

## Options

| Option           | Type                        | Default              | Description                                                          |
| ---------------- | --------------------------- | -------------------- | -------------------------------------------------------------------- |
| `modelDir`       | `string`                    | `RECO_MODEL_DIR`, else `./models/buffalo_l` | Where the two `.onnx` files live.            |
| `detModel`       | `string`                    | `'det_10g.onnx'`     | Detector file name, relative to `modelDir`.                          |
| `recModel`       | `string`                    | `'w600k_r50.onnx'`   | Recognizer file name, relative to `modelDir`.                        |
| `providers`      | `ExecutionProvider[]`       | `['cpu']`            | ONNX Runtime execution providers (`'cuda'`, `'coreml'`, `'dml'`…).   |
| `detSize`        | `number`                    | `640`                | Detector input edge, square. Smaller is faster, worse on small faces. |
| `detThreshold`   | `number`                    | `0.5`                | Detector confidence below which a box is dropped.                    |
| `nmsThreshold`   | `number`                    | `0.4`                | IoU above which overlapping boxes are merged.                        |
| `maxFaces`       | `number`                    | `0` (all)            | Keep at most this many faces, best first.                            |
| `faceSize`       | `number`                    | `112`                | Aligned crop edge fed to the recognizer (`w600k_r50` wants 112).     |
| `maxPixels`      | `number`                    | Bun's ~268 MP        | Refuse a larger image before decoding — lower it for untrusted input. |
| `autoDownload`   | `boolean`                   | `true`               | Download buffalo_l when the two default models are missing.          |
| `modelUrl`       | `string`                    | buffalo_l release    | Archive used by `autoDownload`.                                      |
| `downloadTimeoutMs` | `number`                 | `600000`             | Abort the download after this many milliseconds.                     |
| `sessionOptions` | `InferenceSession.SessionOptions` | —              | Merged into both sessions (`intraOpNumThreads`, `'profiling'`…).     |

`detect()`, `recognize()`, `getDescriptors()`, `getDescriptor()` and `embed()` take the same detection
knobs per call: `detSize`, `threshold`, `nmsThreshold`, `maxFaces`; `recognize()`, `getDescriptors()`,
`getDescriptor()` and `embed()` also take `faceSize`. `embedAligned()` takes only `faceSize`.

## What you get back

```typescript
interface FaceDetection {
  score: number;                              // detector confidence, 0..1
  box: { x: number; y: number; width: number; height: number }; // source pixels, clamped
  keypoints: [RecoPoint, RecoPoint, RecoPoint, RecoPoint, RecoPoint]; // eyes, nose, mouth corners
}

interface FaceResult extends FaceDetection {
  embedding: Float32Array;                    // 512 dimensions, unit norm
}
```

Because every embedding has norm 1, `cosineSimilarity(a, b)` is a plain dot product and lands in
`[-1, 1]`. There is **no universal threshold**: calibrate on your own pairs. `1` means identical input;
for same-person candidates the useful cut-off depends on the operating point you accept, so measure
false accepts on your own data instead of copying a number from a tutorial.

## Images

`loadImage()` decodes through **`sharp`**, which hands back raw pixels — the detector tensor and the
aligned crop are built from those directly. It is deliberately strict about what the rest of the pipeline
sees:

- **EXIF orientation is applied** — a phone photo taken sideways is not fed sideways.
- **Three RGB channels, always** — grayscale, CMYK, RGBA, palette and 16-bit inputs are converted, so the
  RGB indexing cannot silently drift.
- **8 bits per channel** — 16-bit samples are downscaled; anything else is `RECO_IMAGE_UNSUPPORTED`.
- **Undecodable bytes are refused** with `RECO_IMAGE_INVALID`, never fed to the detector as noise.

::prose-callout{variant="warning" title="A string is a filesystem path"}
`loadImage()` hands any string to `sharp`, which reads it as a path. Never pass an untrusted string
(a query parameter, an uploaded filename) to `loadImage()` or to an engine method — read the bytes
yourself and pass a `Uint8Array`, a `Blob` or base64. For untrusted images, also lower `maxPixels`: a
32 KiB PNG can otherwise decode to hundreds of megabytes.
::

Because `sharp` returns the pixels, the RGB buffer is built in one step: EXIF applied, colourspace converted
to sRGB, alpha dropped, 16-bit samples downscaled. A Display P3 photo is therefore converted to sRGB, as
the InsightFace reference pipeline expects.

## How it works

1. **Fit and pad** — the image is resized to fit a `detSize` square, keeping its aspect ratio, and placed
   at the top-left over black. The tensor is `CHW`, RGB, normalized `(x - 127.5) / 128`.
2. **Decode** — the detector returns nine tensors, three per stride (8, 16, 32). They are grouped **by
   shape**, not by name or order: `1` channel is a score map, `4` a box regression, `10` five landmarks.
   Anchors are decoded to source pixels, then non-maximum suppression and clipping keep the real faces.
3. **Align** — a least-squares similarity transform maps the five landmarks onto the ArcFace reference
   points, and bilinear sampling produces the `faceSize` crop.
4. **Embed** — the crop is normalized `(x - 127.5) / 127.5`, run through `w600k_r50`, and the 512 outputs
   are scaled to unit length.

Detection and embedding are sequential on the CPU: a 1280x886 photo with six faces took roughly 420 ms on
an Apple Silicon laptop (decode included). Raising `maxFaces`, lowering `detSize` or passing
`sessionOptions: { intraOpNumThreads: n }` are the levers. Keep one engine per process rather than one per
request: the recognizer alone is 174 MB on disk, and loading it is the slow part.

::prose-callout{variant="warning" title="Face data is personal data"}
An embedding is biometric information: in the EU it is special-category data under the GDPR, and
comparable rules apply elsewhere. Collect it with a lawful basis and consent where required, keep it
only as long as needed, encrypt it at rest, and do not treat a cosine score as an identity proof.
::

## Errors

Every failure is a `RecoError` with a stable `code` (`isRecoError(error)` narrows it).

| Code                        | When                                                                    |
| --------------------------- | ----------------------------------------------------------------------- |
| `RECO_MODEL_NOT_FOUND`      | A `.onnx` file is missing from `modelDir`.                              |
| `RECO_MODEL_INVALID`        | The file cannot be loaded, or its outputs are not a RetinaFace layout.  |
| `RECO_MODEL_DOWNLOAD_FAILED` | Network error, HTTP failure or timeout during the automatic download. |
| `RECO_MODEL_EXTRACT_FAILED` | `unzip`/`tar` failed, or the archive lacks the two model files.         |
| `RECO_INFERENCE_FAILED`     | ONNX Runtime failed during a run (shape, device, memory).               |
| `RECO_IMAGE_INVALID`        | The bytes or path do not decode as an image.                            |
| `RECO_IMAGE_UNSUPPORTED`    | A pixel depth or channel layout the pipeline cannot normalize.          |
| `RECO_NO_FACE`              | `embed()` or `compare()` found no face above the threshold.             |
| `RECO_ALIGNMENT_INVALID`    | Degenerate landmarks, wrong landmark count, or a non-square crop.        |
| `RECO_EMBEDDING_INVALID`    | Empty, zero, non-finite or mismatched-length embeddings.                 |
| `RECO_ENGINE_CLOSED`        | A method was called after `close()`.                                     |

## Lower-level helpers

The pipeline is exported piece by piece for tests and custom paths:

- **images** — `loadImage`, `resizeImage`, `isRecoImage`, `isBase64Image`;
- **detection** — `detectorResize`, `toDetectorTensor`, `groupDetectorOutputs`, `decodeDetections`, `nms`,
  `clipDetections`;
- **alignment** — `alignFace`, `similarityTransform`, `toRecognitionTensor`, `ARC_DST`;
- **similarity** — `normalizeEmbedding`, `cosineSimilarity`, `findBestMatch`;
- **models** — `downloadModels`, `ensureModels`, `modelsPresent`, `DEFAULT_MODEL_URL`.

Plus the `Reco*` types. `engine.sessions` hands back the raw ONNX Runtime sessions when you need a tensor
this API does not expose.

## Requirements

`sharp` (libvips) and `onnxruntime-node` are native dependencies; both ship prebuilt binaries for macOS,
Linux and Windows (x64/arm64). Bun is the tested runtime — nothing in the library is Bun-specific, so
Node.js 20+ should work as well. `onnxruntime-node` is imported with the package, so the first `import`
loads the native binding; `createEngine()` downloads the weights if needed, then loads the two models.
