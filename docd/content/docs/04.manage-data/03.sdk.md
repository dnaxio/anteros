A lightweight, typed HTTP client for consuming the anteros REST API from any JavaScript or TypeScript environment (browser, Node.js, Bun, etc.). The package exports **two clients** that share the same transport — pick one, or use both side by side.

## Which client?

| Class     | Surface                                                       | When to use                            |
| --------- | ------------------------------------------------------------- | -------------------------------------- |
| `Anteros` | Namespaced — one namespace per family                         | **Recommended** for new code           |
| `Rest`    | Flat — `find(collection, …)`, `upload(…)`, `runService(…)`, … | Existing code — **nothing to migrate** |

`Anteros` groups every call **by family**, mirroring the server's URLs: `api.collection(slug)`, `api.service(name)`, `api.agent(id)`, `api.files`, `api.vars`. `Rest` is the **original** client — it keeps the flat methods it always had (`api.find(collection, params)`, `api.upload(…)`, `api.runService(…)`, …), **unchanged**. **Neither replaces the other**: a codebase already on the flat surface has nothing to migrate.

Both expose the same shared members — `vars`, `agent(id)`, `getConfig()`, `setHeader` / `setServer` / `setTenant` / `getTenant` / `getToken` / `clearToken` — and take the same constructor options. **All URLs are the server's** (`/api/:tenant/<family>/…`), including the flat methods of `Rest`: the paths are built by the SDK, so a client written against the original surface keeps working against the current server **without changing a line**.

```typescript
import { Anteros, Rest } from "@anteros/sdk"; // Anteros = new, Rest = the original

const api = new Anteros({ server, tenant });
const orders = api.collection<Order>("orders");
await orders.find({ $match: { status: "paid" } });

const legacy = new Rest({ server, tenant }); // the same server, the same thing another way
await legacy.find("orders", { $match: { status: "paid" } });
```

The sections below document `Anteros`. **Variables** and **Agents** are shared by both clients (they live on the instance), as are **Request Options**, **Error Handling** and the configuration/token methods; the **`Rest`** section lists the flat signatures.

## One namespace per family

`Anteros` **mirrors the server's URL families** (`/api/:tenant/<family>/…`) instead of exposing a flat list of verbs. Two shapes, one rule:

- a **singular** name is a client **bound to one resource** — `api.collection(slug)`, `api.service(name)`, `api.agent(id)`. The identifier (and the row type) is stated once and never repeated per call;
- a **plural** name is **that family's operations** — `api.files`, `api.vars`.

What the instance keeps for itself is the transport: the URL, the headers, the token and the error shape. `api.getConfig()` is therefore a method rather than a namespace — the public config is instance-wide, not a tenant family.

```typescript
import { Anteros } from "@anteros/sdk";

const api = new Anteros({ server: "http://localhost:4000", tenant: "v1" });

// Singular — bound to one resource: the identifier lives on the client
const orders = api.collection<Order>("orders");
const paid = await orders.find({ $match: { status: "paid" } });
await orders.updateOne(paid[0]._id, { $set: { status: "shipped" } });

const analytics = api.service("analytics");
const report = await analytics.run("monthly", { month: "2026-09" });

// Plural — the family's operations
const file = await api.files.upload("photos", cover, { alt: "Cover" });
await api.vars.set("config", "licence", "RDX00");
```

| Client                 | Server route(s)                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| `api.collection(slug)` | `POST /api/:tenant/collections/:collection/:action`                                        |
| `api.service(name)`    | `POST /api/:tenant/services/:service/:action`                                              |
| `api.files`            | `POST /api/:tenant/upload/:collection`, `GET\|DELETE /api/:tenant/files/:collection/:file` |
| `api.vars`             | `POST /api/:tenant/vars/:action`                                                           |
| `api.agent(id)`        | `POST /api/:tenant/agents/:agent/:action`                                                  |
| `api.getConfig()`      | `GET /_dnax/config/:tenant`                                                                |

::prose-callout{variant="info"}

The flat client reaches the **same** server calls, with the signatures it always had — `api.find("users", …)`, `api.upload(…)`, `api.getFileUrl(…)`, `api.runService(…)`. They live in the **`Rest`** section below; nothing is deprecated.

::

The same split exists **in process**: the server context exposes an `api` member next to `rest` and `agents`, built on the same rule — a singular client bound to one resource, plural namespaces for the families — and delegating every call to `rest`. See [Internal API → The `api` facade](/docs/manage-data/internal-api#the-api-facade).

## Installation

```bash
bun add @anteros/sdk@latest
```

The SDK calls the framework over HTTP, so its paths are the server's: everything under `/api/<tenant>/…` with one family segment per surface (`collections`, `services`, `vars`, `upload`, `files`, `agents`, `mcp`) — the [REST API](/docs/manage-data/rest-api) page lists them, and the server builds them with the exported `endpoints` helpers. Nothing to configure here: pass the server URL and the tenant.

## Quick Start

```typescript
import { Anteros } from "@anteros/sdk";

const api = new Anteros({
  server: "http://localhost:5000",
  tenant: "v1",
});

const users = api.collection("users");
const page = await users.find();
```

## Constructor

Both classes take the same options:

```typescript
const api = new Anteros(options: RestClientOptions); // namespaced (recommended)
const legacy = new Rest(options: RestClientOptions); // flat, original
```

| Option             | Type                                         | Default           | Description                                      |
| ------------------ | -------------------------------------------- | ----------------- | ------------------------------------------------ |
| `server`           | `string`                                     | —                 | Base URL of the anteros server (required)        |
| `tenant`           | `string`                                     | —                 | Tenant ID (required)                             |
| `headers`          | `Record<string, string>`                     | `{}`              | Custom headers sent with every request           |
| `token`            | `{ persist?: boolean; storageKey?: string }` | —                 | JWT persistence in `localStorage`                |
| `token.persist`    | `boolean`                                    | `true`            | Save the JWT token in `localStorage` after login |
| `token.storageKey` | `string`                                     | `"anteros_token"` | Key used in `localStorage` for the token         |

```typescript
const api = new Anteros({
  server: "https://api.example.com",
  tenant: "v1",
  headers: {
    "X-Custom-Header": "value",
  },
  token: {
    persist: true,
    storageKey: "my_app_token",
  },
});
```

::prose-callout{variant="info"}

When `token.persist` is `true` (default) and a token is found in `localStorage` at construction, it is automatically loaded into the `Authorization` header.

::

## Authentication

`login` and `logout` are **collection methods**: call them on the client bound to a collection that has auth enabled (a `login` action in its `api` block). A successful `login` stores the token on the SDK instance, so every later call — on any namespace — carries it. With `Rest`, the same actions are `api.login("users", payload)` and `api.logout("users")` (see the **`Rest`** section).

### login

Authenticate a user and store the JWT token.

```typescript
const users = api.collection("users");

const { token, data } = await users.login({
  email: "john@example.com",
  password: "secret",
});
```

| Parameter  | Type                      | Description       |
| ---------- | ------------------------- | ----------------- |
| `payload`  | `Record<string, unknown>` | Login credentials |
| `options?` | `RestRequestOptions`      | Request options   |

**Returns:** `{ token: string, data: any }`

### logout

```typescript
await api.collection("users").logout();
```

| Parameter  | Type                      | Description      |
| ---------- | ------------------------- | ---------------- |
| `payload?` | `Record<string, unknown>` | Optional payload |
| `options?` | `RestRequestOptions`      | Request options  |

### getToken

Retrieve the current JWT token:

```typescript
const token = api.getToken(); // string | undefined
```

### clearToken

Remove the token from memory and `localStorage`:

```typescript
api.clearToken();
```

### setHeader

Set or remove a custom header:

```typescript
api.setHeader("X-Custom", "value");
api.setHeader("X-Custom", undefined); // removes it
```

## CRUD Methods

Every CRUD method is called on a **collection client** — `const users = api.collection("users")`. The slug is no longer an argument: it is stated once when the client is created, and each call sends a `POST` to the same unified route, `POST /api/:tenant/collections/:collection/:action`.

### getSlug

The collection slug the client is bound to:

```typescript
users.getSlug(); // "users"
```

### find

Retrieve multiple documents.

```typescript
const page = await api.collection("users").find({
  $match: { activated: true },
  $sort: { createdAt: -1 },
  $limit: 20,
});
```

| Parameter  | Type                      | Description                                                               |
| ---------- | ------------------------- | ------------------------------------------------------------------------- |
| `params`   | `Record<string, unknown>` | Query parameters (`$match`, `$sort`, `$limit`, `$skip`, `$include`, etc.) |
| `options?` | `RestRequestOptions`      | Request options                                                           |

**Returns:** `T[]`

### findOne

Retrieve a single document by ID.

```typescript
const user = await api.collection("users").findOne("64f1a2b3c4d5e6f7a8b9c0d1");
```

| Parameter  | Type                      | Description      |
| ---------- | ------------------------- | ---------------- |
| `id`       | `string`                  | Document ID      |
| `params`   | `Record<string, unknown>` | Query parameters |
| `options?` | `RestRequestOptions`      | Request options  |

**Returns:** `T | null`

### insertOne

Create a single document.

```typescript
const newUser = await api.collection("users").insertOne({
  name: "Jane Doe",
  email: "jane@example.com",
});
// newUser._id is available
```

| Parameter  | Type                 | Description     |
| ---------- | -------------------- | --------------- |
| `data`     | `TBody`              | Document data   |
| `options?` | `RestRequestOptions` | Request options |

**Returns:** `T & { _id: string }`

### insertMany

Create multiple documents at once.

```typescript
const products = await api.collection("products").insertMany([
  { name: "Widget A", price: 9.99 },
  { name: "Widget B", price: 14.99 },
]);
```

| Parameter  | Type                 | Description        |
| ---------- | -------------------- | ------------------ |
| `data`     | `TBody[]`            | Array of documents |
| `options?` | `RestRequestOptions` | Request options    |

**Returns:** `(T & { _id: string })[]`

### updateOne

Update a single document by ID.

```typescript
await api.collection("users").updateOne("64f1a2b3c4d5e6f7a8b9c0d1", {
  $set: { name: "Jane Smith" },

```

| Parameter  | Type                 | Description     |
| ---------- | -------------------- | --------------- |
| `id`       | `string`             | Document ID     |
| `update`   | `TUpdate`            | Update payload  |
| `options?` | `RestRequestOptions` | Request options |

### updateMany

Update multiple documents by IDs.


| ---------- | -------------------- | --------------- |
| `ids`      | `string[]`           | Document IDs    |
| `update`   | `TUpdate`            | Update payload  |
| `options?` | `RestRequestOptions` | Request options |

### deleteOne

Delete a single document by ID.

```typescript

```

| Parameter  | Type                 | Description     |
| ---------- | -------------------- | --------------- |
| `id`       | `string`             | Document ID     |

### deleteMany

Delete multiple documents by IDs.


## Advanced Methods

### aggregate

Run a MongoDB aggregation pipeline on the bound collection.

```typescript
const stats = await api
  .collection("orders")
  .aggregate([
    { $match: { status: "completed" } },
    { $group: { _id: "$customerId", total: { $sum: "$amount" } } },
    { $sort: { total: -1 } },
  ]);
```

| Parameter  | Type                 | Description                 |
| ---------- | -------------------- | --------------------------- |
| `pipeline` | `unknown[]`          | Aggregation pipeline stages |
| `options?` | `RestRequestOptions` | Request options             |

**Returns:** `T[]`

### runAction

Call a custom action defined on the bound collection.

```typescript
const result = await api.collection("orders").runAction("processOrder", {
  orderId: "64f1a2b3c4d5e6f7a8b9c0d1",
});
```

| Parameter  | Type                 | Description                  |
| ---------- | -------------------- | ---------------------------- |
| `action`   | `string`             | Custom action name           |
| `data?`    | `unknown`            | Payload passed to the action |
| `options?` | `RestRequestOptions` | Request options              |

## Services

`api.service(name)` returns a client bound to **one** service — the name is stated once, exactly like `api.collection(slug)`. It talks to `POST /api/:tenant/services/:service/:action`.

### getName

The service name the client is bound to:

```typescript
api.service("analytics").getName(); // "analytics"
```

### run

Runs one action of the bound service.

```typescript
const analytics = api.service("analytics");

const report = await analytics.run("generateReport", {
  from: "2025-01-01",
  to: "2025-12-31",
});
```

| Parameter  | Type                 | Description                                                 |
| ---------- | -------------------- | ----------------------------------------------------------- |
| `action`   | `string`             | Action exposed in `service.actions`                         |
| `data?`    | `unknown`            | Sent as `{ data: … }` (readable server-side as `body.data`) |
| `options?` | `RestRequestOptions` | Headers, `signal`, `query`, `cleanDeep`…                    |

**Tenant** — the one passed to `new Anteros({ server, tenant, … })`; it is the first segment of the path (`/api/<tenant>/…`).

## Variables

`api.vars` mirrors the server's `rest.vars` (`POST /api/:tenant/vars/:action` — the namespace travels in the body). It is **shared by both clients**, on the instance.

```typescript
await api.vars.set("config", "licence", "RDX00");
const licence = await api.vars.get("config", "licence"); // 'RDX00'
await api.vars.del("config", "licence");

// Per-company store (the `scope` declared in `define.Vars`)
const acme = api.vars.scope(companyId);
await acme.set("config", "licence", "ACME-001", {
  meta: { note: "Contract" },
  ttl: "30d",
});
await acme.all("config");
```

| Method                        | Returns                                            |
| ----------------------------- | -------------------------------------------------- |
| `set(ns, key, value, opts?)`  | —                                                  |
| `setMany(ns, entries, opts?)` | —                                                  |
| `get<T>(ns, key, opts?)`      | `T \| undefined`                                   |
| `entry<T>(ns, key, opts?)`    | `VarEntry<T> \| undefined` (value + meta + expiry) |
| `entries(ns, opts?)`          | `VarEntry[]`                                       |
| `all(ns, opts?)`              | `Record<string, any>`                              |
| `del(ns, key, opts?)`         | `boolean`                                          |
| `has(ns, key, opts?)`         | `boolean`                                          |
| `incr(ns, key, by?, opts?)`   | `number`                                           |
| `expire(ns, key, ttl, opts?)` | `boolean`                                          |
| `clear(ns, opts?)`            | `number`                                           |
| `scope(value)`                | bound `Vars`                                       |

Options: `{ scope? }` on every method, plus `where?` for reads and `meta?` / `ttl?` for writes. The namespace must be exposed server-side with `define.Vars({ api: { access } })`.

## Agents

`api.agent(id)` returns a client bound to one [agent](/docs/ai/agents) of the tenant — it calls `POST /api/:tenant/agents/:agent/:action`. It is **shared by both clients**, on the instance.

```typescript
import { Anteros } from "@anteros/sdk";

const api = new Anteros({ server: "http://localhost:4000", tenant: "v1" });
const support = api.agent("support");
```

| Method                      | Returns          | Description                                                                                           |
| --------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------- |
| `info()`                    | `AgentInfo`      | Agent metadata (tools, model, options) — no token spent                                               |
| `generate(input, options?)` | `AgentResult`    | Runs to completion: `text`, `reasoning`, `toolCalls`, `toolResults`, `steps`, `usage`, `finishReason` |
| `stream(input, options?)`   | `AgentStream`    | Same run, token by token — same options                                                               |
| `object(input, options?)`   | `T`              | Typed object — the schema is declared server-side (`api.object`)                                      |
| `history(thread)`           | `AgentMessage[]` | The stored conversation (needs a memory on the agent)                                                 |
| `threads(options?)`         | `AgentThread[]`  | The caller's threads, most recent first (needs a store that lists them)                               |
| `clear(thread)`             | `boolean`        | Forget a thread                                                                                       |
| `getId()`                   | `string`         | The agent id used in the URL                                                                          |

`generate()`, `stream()` and `object()` share the same `AgentRunOptions`: `thread`, `resource`, `maxSteps`, `lastMessages`, `messages` (turns injected into the run) and `files`.

`input` is a string, one message, or an array of messages (`{ role, content }`) — the full shape (roles, content parts, tool turns) is documented on [Agents → Input](/docs/ai/agents#input).

```typescript
const { text, toolCalls, usage } = await support.generate(
  "Where is my order?",
  {
    thread: "user-42", // memory thread — replays the conversation
    resource: "acme", // opaque caller identity (server-side instructions)
    maxSteps: 3, // lower the ceiling; the server never lets it go higher
  },
);

const priority = await api
  .agent<{ priority: "low" | "high" }>("triage")
  .object("Triage this ticket");
```

### Streaming

`stream()` resolves once the response headers are in — access errors (`401`) and unknown agents throw **there**, not mid-stream.

```typescript
const stream = await support.stream("And in Lyon?", { thread: "user-42" });

for await (const token of stream.textStream) {
  process.stdout.write(token);
}

// Text is not the only channel: tool calls, results, steps and finish are there too
for await (const chunk of stream.fullStream) {
  if (chunk.type === "tool_call") console.log("→", chunk.toolCall.name);
}

console.log(await stream.text); // resolves when the whole run is over
console.log((await stream.usage).requests);
console.log(await stream.finishReason);
stream.abort(); // stop — the server aborts its model call too
```

| Member                                                    | Type                              | Description                                                                                      |
| --------------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------ |
| `textStream`                                              | `AsyncIterable<string>`           | Text tokens only                                                                                 |
| `fullStream`                                              | `AsyncIterable<AgentStreamChunk>` | `text`, `tool_call`, `tool_result`, `step`, `finish`                                             |
| `text` / `object` / `toolCalls` / `toolResults` / `steps` | `Promise<…>`                      | The final result — resolved at the end of the run                                                |
| `usage` / `finishReason`                                  | `Promise<…>`                      | Token usage and how the run ended                                                                |
| `abort(reason?)`                                          | `void`                            | Stop the run; the streams end, the promises reject with an `AbortError` (`AGENT_STREAM_ABORTED`) |

Streaming in a chat UI:

```typescript
const stream = await api
  .agent("support")
  .stream(userMessage, { thread: userId });

for await (const token of stream.textStream) {
  ui.append(token);
}

const final = await stream; // { text, usage, finishReason } when the run is done
```

::prose-callout{variant="info"}

A client only chooses the input, the memory thread and a _lower_ `maxSteps`. The model, the endpoint, the API key, the options and the structured-output schema stay on the server — see the [agents reference](/docs/ai/agents#what-a-client-may-choose-and-what-it-may-not).

::

## Files

`api.files` groups the file-collection operations: `upload`, `url` (synchronous — it only builds a URL) and `delete`.

### upload

Upload one or multiple files to a file collection — `POST /api/:tenant/upload/:collection`. Pass custom fields via the `data` parameter.

```typescript
// Simple upload
const file = await api.files.upload("photos", fileInput.files[0]);
// { _id, _file: { filename, name, mimetype, size, url } }

// With custom fields
const photo = await api.files.upload("photos", fileInput.files[0], {
  description: "Profile picture",
  alt: "My avatar",
});
// { _id, _file: {...}, description: 'Profile picture', alt: 'My avatar' }

// Multiple files — ONE request, one document per file
const files = await api.files.upload("photos", [file1, file2, file3]);
// [{ _id, _file: {...} }, ...]
```

| Parameter         | Type                               | Description                               |
| ----------------- | ---------------------------------- | ----------------------------------------- |
| `file`            | `Blob \| File \| (Blob \| File)[]` | One or multiple files                     |
| `data?`           | `Record<string, any>`              | Custom fields to store alongside the file |
| `opts?.fieldName` | `string`                           | Form field name (default: `'file'`)       |
| `opts?.signal`    | `AbortSignal`                      | Cancel the upload                         |

**Returns:** `FileResult` (single file) or `FileResult[]` (multiple files)

```json
{
  "_id": "507f1f77bcf86cd799439011",
  "_file": {
    "filename": "507f1f77bcf86cd799439011.jpg",
    "name": "photo.jpg",
    "mimetype": "image/jpeg",
    "size": 2048576,
    "url": "/api/v1/files/photos/507f1f77bcf86cd799439011.jpg"
  },
  "description": "Profile picture",
  "alt": "My avatar"
}
```

### url

Build the URL serving a file, with optional image transformations. **Synchronous** — it returns the string, it does not fetch.

```typescript
const url = api.files.url("photos", result._file.filename);
// /api/v1/files/photos/507f1f77bcf86cd799439011.jpg

const thumb = api.files.url("photos", result._file.filename, {
  width: 200,
  format: "webp",
  quality: 80,
});
// /api/v1/files/photos/507f1f77bcf86cd799439011.jpg?w=200&format=webp&q=80
```

| Parameter            | Type     | Description                                        |
| -------------------- | -------- | -------------------------------------------------- |
| `filename`           | `string` | Filename returned by upload                        |
| `transform?.width`   | `number` | Max width in pixels                                |
| `transform?.height`  | `number` | Max height in pixels                               |
| `transform?.format`  | `string` | Output format: `webp` \| `jpeg` \| `png` \| `avif` |
| `transform?.quality` | `number` | Quality 1–100                                      |

**Returns:** `string` — the full URL

### delete

Delete a file from a file collection by its document `_id` — `DELETE /api/:tenant/files/:collection/:file`.

```typescript
const upload = await api.files.upload("photos", file);
await api.files.delete("photos", upload._id);
// { message: 'File deleted', ok: true }
```

| Parameter | Type          | Description                             |
| --------- | ------------- | --------------------------------------- |
| `fileId`  | `string`      | Document `_id` (returned by `upload()`) |
| `signal?` | `AbortSignal` | Cancel the request                      |

**Returns:** `{ message: string, ok: boolean }`

## `Rest` — the original client

`Rest` is the client the package started with. **Its signatures are unchanged** — the collection is the first argument, exactly as before — and the **URLs are the current ones**: the paths are built by the client under `/api/:tenant/…`, so an existing `Rest` client talks to the current server without a single edit.

```typescript
import { Rest } from "@anteros/sdk";

const legacy = new Rest({ server: "http://localhost:4000", tenant: "v1" });

const paid = await legacy.find("orders", { $match: { status: "paid" } });
await legacy.updateOne("orders", paid[0]._id, { $set: { status: "shipped" } });

const { token } = await legacy.login("users", { email, password });
const report = await legacy.runService("analytics", "monthly", {
  month: "2026-09",
});
const photo = await legacy.upload("photos", cover, { alt: "Cover" });
legacy.getFileUrl("photos", photo._file.filename, { width: 400 });
await legacy.deleteFile("photos", photo._id);
await legacy.logout("users");
```

| Method                                           | Server route                                           |
| ------------------------------------------------ | ------------------------------------------------------ |
| `login(collection, payload, options?)`           | `POST /api/:tenant/collections/:collection/login`      |
| `logout(collection, payload?, options?)`         | `POST /api/:tenant/collections/:collection/logout`     |
| `find(collection, params, options?)`             | `POST /api/:tenant/collections/:collection/find`       |
| `findOne(collection, id, params?, options?)`     | `POST /api/:tenant/collections/:collection/findOne`    |
| `aggregate(collection, pipeline, options?)`      | `POST /api/:tenant/collections/:collection/aggregate`  |
| `insertOne(collection, data, options?)`          | `POST /api/:tenant/collections/:collection/insertOne`  |
| `insertMany(collection, data, options?)`         | `POST /api/:tenant/collections/:collection/insertMany` |
| `updateOne(collection, id, update, options?)`    | `POST /api/:tenant/collections/:collection/updateOne`  |
| `updateMany(collection, ids, update, options?)`  | `POST /api/:tenant/collections/:collection/updateMany` |
| `deleteOne(collection, id, options?)`            | `POST /api/:tenant/collections/:collection/deleteOne`  |
| `deleteMany(collection, ids, options?)`          | `POST /api/:tenant/collections/:collection/deleteMany` |
| `runAction(collection, action, data?, options?)` | `POST /api/:tenant/collections/:collection/:action`    |
| `runService(service, action, data?, options?)`   | `POST /api/:tenant/services/:service/:action`          |
| `upload(collection, file, data?, opts?)`         | `POST /api/:tenant/upload/:collection`                 |
| `getFileUrl(collection, filename, transform?)`   | `GET /api/:tenant/files/:collection/:file`             |
| `deleteFile(collection, fileId, signal?)`        | `DELETE /api/:tenant/files/:collection/:file`          |

`vars`, `agent(id)`, `getConfig()` and the configuration/token methods are the **same** on both clients.

## Request Options

Every method accepts an optional `RestRequestOptions` object as its last parameter — identically on `Anteros` and on `Rest` (where it comes after the flat arguments).

```typescript
type RestRequestOptions = {
  headers?: Record<string, string>;
  signal?: AbortSignal;
  query?: RestQueryOptions;
  cleanDeep?: boolean;
  useCache?: boolean; // find only — server-side DB query cache (TTL is managed server-side)
};
```

| Option      | Type                     | Description                                                                                                                                                                                                                                   |
| ----------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `headers`   | `Record<string, string>` | Extra headers for this request only                                                                                                                                                                                                           |
| `signal`    | `AbortSignal`            | Abort signal to cancel the request                                                                                                                                                                                                            |
| `query`     | `RestQueryOptions`       | URL query parameters                                                                                                                                                                                                                          |
| `cleanDeep` | `boolean`                | Strip `null`, `undefined`, empty arrays, and empty objects from the body before sending                                                                                                                                                       |
| `useCache`  | `boolean`                | **`find` only** — serve from the server-side DB query cache (populated on miss, invalidated on any write). Requires `cache.enabled: true` on the server. **TTL is managed server-side** (collection/server config). `findOne` is never cached |

```typescript
// Server-side query caching — TTL comes from the collection/server config
const orders = await api
  .collection("orders")
  .find({ $match: { status: "paid" } }, { useCache: true });

// On the flat client it is the same option, in the same position
// legacy = new Rest({ server, tenant })
const same = await legacy.find(
  "orders",
  { $match: { status: "paid" } },
  { useCache: true },
);
```

### AbortSignal

Cancel a long-running request:

```typescript
const controller = new AbortController();

api.collection("users").find({}, { signal: controller.signal });

setTimeout(() => controller.abort(), 5000);
```

### cleanDeep

Automatically remove empty values from the request body:

```typescript
await api.collection("users").insertOne(
  {
    name: "Jane",
    nickname: null,
    tags: [],
    meta: {},
  },
  { cleanDeep: true },
);
// Body sent: { name: 'Jane' }
```

## Error Handling

When the server returns a non-2xx response, the SDK throws an `Error` with extra properties — the same shape on both clients, since the transport is shared:

```typescript
try {
  await api.collection("users").findOne("invalid-id");
} catch (err) {
  console.log(err.message); // "Document not found"
  console.log(err.status); // 404
  console.log(err.code); // "DOCUMENT_NOT_FOUND"
  console.log(err.meta); // additional info from server
}
```

| Property  | Type     | Description                   |
| --------- | -------- | ----------------------------- |
| `message` | `string` | Error message from the server |
| `status`  | `number` | HTTP status code              |
| `code`    | `string` | Application error code        |
| `meta`    | `any`    | Optional metadata             |
