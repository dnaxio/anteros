Everything the framework serves lives under **one namespace**, `/api/:tenant_id`, and a **family** segment says what it is:

| Surface                                     | Route                                                  | Where it is documented                   |
| ------------------------------------------- | ------------------------------------------------------ | ---------------------------------------- |
| Collections (CRUD, custom actions, `login`) | `POST /api/:tenant_id/collections/:collection/:action` | **this page**                            |
| Services                                    | `POST /api/:tenant_id/services/:service/:action`       | [Services](/docs/reference/services)     |
| Variables                                   | `POST /api/:tenant_id/vars/:action`                    | [Variables](/docs/reference/vars)        |
| Upload                                      | `POST /api/:tenant_id/upload/:collection`              | [Files & uploads](/docs/reference/files) |
| Files                                       | `GET\|DELETE /api/:tenant_id/files/:collection/:file`  | [Files & uploads](/docs/reference/files) |
| Agents                                      | `POST /api/:tenant_id/agents/:agent/:action`           | [Agents](/docs/ai/agents#http-api)       |
| MCP                                         | `GET\|POST /api/:tenant_id/mcp`                        | [MCP](/docs/ai/mcp)                      |

```typescript
// `endpoints` is exported by the framework — the same builders the server maps
import { endpoints } from "@anteros/core";

endpoints.collection("v1", "orders", "find"); // /api/v1/collections/orders/find
endpoints.file("v1", "photos", "507f1f77.jpg"); // /api/v1/files/photos/507f1f77.jpg
```

The rest of this page details the **collection** family — one endpoint per action:

```
POST /api/:tenant_id/collections/:collection/:action
```

| Parameter    | Description       |
| ------------ | ----------------- |
| `tenant_id`  | Tenant identifier |
| `collection` | Collection name   |
| `action`     | Action to perform |

## Content Types

| Type                                | Description  |
| ----------------------------------- | ------------ |
| `application/json`                  | JSON body    |
| `multipart/form-data`               | File uploads |
| `application/x-www-form-urlencoded` | Form data    |

## Authentication (JWT)

For routes that require a logged-in user, send the token from login in the **`Authorization`** header:

```http
Authorization: Bearer <jwt_token>
```

The framework verifies the JWT before the request reaches collection handlers. If the header is present and the token is invalid or expired, the response is **401**. If you omit the header, no token is attached; use collection **`api.access`** rules to allow or deny actions and inspect claims via **`token.decoded`** (see [Access control](/docs/reference/access-control)).

After login, the JSON body includes `"token"` — use that value as the Bearer token for subsequent `POST /api/...` calls.

## Actions

### find

Retrieve multiple documents.

```http
POST /api/:tenant_id/collections/:collection/find
Content-Type: application/json

{
  "params": {
    "$match": { "status": "active" },
    "$limit": 20,
    "$skip": 0,
    "$sort": { "createdAt": -1 }
  }
}
```

**Response:**

```json
[{ "_id": "...", "name": "John", ... }, ...]
```

**Body parameters:**

| Parameter | Type          | Required | Description               |
| --------- | ------------- | -------- | ------------------------- |
| `params`  | `FindOptions` | No       | Query options (see below) |

**`params` options:**

| Parameter      | Type                             | Description                                                                                                      |
| -------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `$match`       | `object`                         | Filter conditions                                                                                                |
| `$limit`       | `number`                         | Limit results. `0` = **no limit** (the `$limit` stage is omitted); any non-negative integer is accepted (no cap) |
| `$skip`        | `number`                         | Skip results                                                                                                     |
| `$sort`        | `object`                         | Sort order                                                                                                       |
| `$project`     | `object`                         | Select fields                                                                                                    |
| `$include`     | `Array<string \| LookupOptions>` | Populate relationship fields via `$lookup`                                                                       |
| `$lookup`      | `Array<object>`                  | **Internal API only** — raw `$lookup` stages, no validation                                                      |
| `$graphLookup` | `Array<object>`                  | **Internal API only** — recursive graph traversal, no validation                                                 |

**`options`** (third parameter): `{ useCache?: boolean }` — `useCache: true` serves the result from the DB query cache (populated on miss, invalidated on any write, cross-collection on `$include`). **TTL is managed server-side** (collection/server config) — clients cannot override it.

### findOne

Retrieve a single document by ID.

```http
POST /api/:tenant_id/collections/:collection/findOne
Content-Type: application/json

{
  "id": "64f1a2b3c4d5e6f7a8b9c0d1",
  "params": {}
}
```

**Body parameters:**

| Parameter | Type             | Required | Description                |
| --------- | ---------------- | -------- | -------------------------- |
| `id`      | `string`         | Yes      | Document `_id`             |
| `params`  | `findOneOptions` | No       | Query options (`$include`) |

### insertOne

Insert a single document.

```http
POST /api/:tenant_id/collections/:collection/insertOne
Content-Type: application/json

{
  "data": {
    "name": "John Doe",
    "email": "john@example.com"
  }
}
```

**Body parameters:**

| Parameter | Type     | Required | Description        |
| --------- | -------- | -------- | ------------------ |
| `data`    | `object` | Yes      | Document to insert |

### insertMany

Insert multiple documents.

```http
POST /api/:tenant_id/collections/:collection/insertMany
Content-Type: application/json

{
  "data": [
    { "name": "Alice" },
    { "name": "Bob" }
  ]
}
```

**Body parameters:**

| Parameter | Type       | Required | Description                  |
| --------- | ---------- | -------- | ---------------------------- |
| `data`    | `object[]` | Yes      | Array of documents to insert |

### updateOne

Update a single document.

```http
POST /api/:tenant_id/collections/:collection/updateOne
Content-Type: application/json

{
  "id": "64f1a2b3c4d5e6f7a8b9c0d1",
  "update": {
    "$set": { "name": "Jane Doe" }
  }
}
```

**Body parameters:**

| Parameter | Type     | Required | Description                                            |
| --------- | -------- | -------- | ------------------------------------------------------ |
| `id`      | `string` | Yes      | Document `_id` (alias: `_id`)                          |
| `update`  | `object` | Yes      | Update document with operators (`$set`, `$unset`, ...) |

### updateMany

Update multiple documents.

```http
POST /api/:tenant_id/collections/:collection/updateMany
Content-Type: application/json

{
  "ids": ["64f1...", "64f2..."],
  "update": {
    "$set": { "status": "archived" }
  }
}
```

**Body parameters:**

| Parameter | Type       | Required | Description                                            |
| --------- | ---------- | -------- | ------------------------------------------------------ |
| `ids`     | `string[]` | Yes      | Document `_id`s (alias: `_ids`)                        |
| `update`  | `object`   | Yes      | Update document with operators (`$set`, `$unset`, ...) |


### aggregate

Run an aggregation pipeline.

```http
POST /api/:tenant_id/collections/:collection/aggregate
Content-Type: application/json

{
  "pipeline": [
    { "$match": { "status": "active" } },
    { "$group": { "_id": "$category", "total": { "$sum": 1 } } }
  ]
}
```

**Body parameters:**

| Parameter  | Type       | Required | Description                         |
| ---------- | ---------- | -------- | ----------------------------------- |
| `pipeline` | `object[]` | Yes      | MongoDB aggregation pipeline stages |

## Vars API

Variables are served on their own endpoint — `POST /api/:tenant_id/vars/:action` — rather than as a collection action.

The target **namespace** is passed in the body (`ns`) and must be declared with [`define.Vars`](/docs/reference/vars). Access is gated by the namespace's `api.access` (**no rules → 401**).

```http
POST /api/v1/vars/get
Content-Type: application/json

{ "ns": "config", "key": "licence" }
```

| Action    | Body                                      | Response                            |
| --------- | ----------------------------------------- | ----------------------------------- |
| `set`     | `{ ns, key, value, meta?, ttl?, scope? }` | `{ ok: true }`                      |
| `setMany` | `{ ns, entries, meta?, ttl?, scope? }`    | `{ ok: true }`                      |
| `get`     | `{ ns, key, scope? }`                     | `{ value }`                         |
| `entry`   | `{ ns, key, scope? }`                     | `{ entry }` (value + meta + expiry) |
| `entries` | `{ ns, scope?, where? }`                  | `{ entries }`                       |
| `all`     | `{ ns, scope?, where? }`                  | `{ vars }`                          |
| `del`     | `{ ns, key, scope? }`                     | `{ ok }`                            |
| `has`     | `{ ns, key, scope? }`                     | `{ exists }`                        |
| `incr`    | `{ ns, key, by?, scope?, ttl? }`          | `{ value }`                         |
| `expire`  | `{ ns, key, ttl, scope? }`                | `{ ok }`                            |
| `clear`   | `{ ns, scope? }`                          | `{ deleted }`                       |

Error codes: `NAMESPACE_REQUIRED` (400), `NAMESPACE_NOT_FOUND` (400), `ACTION_NOT_FOUND` (400), `ACCESS_DENIED` (401), `VALIDATION_ERROR` (400).

See [Variables](/docs/reference/vars) for `define.Vars`, scopes, meta and TTL.

## Update Operators

| Operator    | Description         |
| ----------- | ------------------- |
| `$set`      | Set field values    |
| `$unset`    | Remove fields       |
| `$inc`      | Increment value     |
| `$mul`      | Multiply value      |
| `$push`     | Add to array        |
| `$pull`     | Remove from array   |
| `$addToSet` | Add to set (unique) |
